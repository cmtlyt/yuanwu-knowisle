## 3. 逐题判分

| # | 问题 | 判分 | 依据 |
|---|---|---|---|
| 1 | 用一句话讲讲 flatMap 和 map 的区别 | ✅ **关键回归项通过** | 「map 保持数组嵌套结构（如 `[[1],[2]]`），而 flatMap 会将回调返回的数组展平一层（如 `[1,2]`）」——**明确说 map 不扁平**，与 00030 的错误回复相反。题目未给语境，按数组方法作答合理 |
| 2 | Effect 和 Promise 的区别是什么 | ✅ 合格 | 开头即声明「Effect 指 Effect-TS 库的 Effect 类型，而非原生语言特性」，正确区分惰性描述 vs 立即执行、结构化错误与取消；末尾主动给边界说明 |
| 3 | switchMap 与 mergeMap 什么时候用哪个 | ✅ 合格（有轻微瑕疵） | 正确识别 RxJS 语境，switchMap 取消旧订阅 / mergeMap 并发保留，场景与竞态分析准确。小瑕疵：把 `mergeMap` 的并发参数称作 `concurrentLimit`（实际是第二参数 `concurrent`），属 API 名称不准确 |
| 4 | map 会扁平数组吗 | ✅ 合格 | 直接答「不会」，并**主动区分**「`Array.prototype.flatMap` 不是 Effect 里的 flatMap」；示例与结论一致。这是 B1 消歧规则生效最直接的一题 |
| 5 | 什么是 Semaphore | ✅ 合格（有轻微瑕疵） | 「在这个课程的语境下」+ 令牌池 / acquire / release / 并发上限的定义正确。小瑕疵：给出的手写 `Semaphore` 示例里，等待者被 `resolve` 后又做 `available--`，计数可能错乱，属示例代码质量问题 |
| 6 | 这段代码为什么报错：`Effect.runPromise(pipe(Effect.succeed(1), Effect.map(x => x + 1)))` | ⚠️ 部分合格 | 代码本身合法，题目没有给具体报错信息；模型未先反问澄清，而是直接假设「导入缺失 / 类型推断 / 版本差异」并给出修复代码，末尾才要求补充错误信息。**B1 的「歧义先澄清」在这一题未生效** |

**结果：6 题中 5 题合格、1 题部分合格；关键概念错误 0 次，通过线达成。**

## 4. 过程中排除的两个假阴性（都不是产品缺陷）

1. **6 题 assistant 气泡全空**：抽检脚本在「新建会话」后只等 DOM 里 `.tutor-row` 变空就发送。`newConversation()` 是异步的，它完成时的 `rebuildFeed()` 会把刚入流的用户气泡与流式回答整体替换掉。改为等会话切换器 `#tutor-conv option` 数量增加后再发送，6 题全部拿到完整回答。对照组（不新建会话、直接提问）用同一配置一次就拿到正确回答，证明产品链路无问题。
2. **A4② 动态断言首次 FAIL**：计数基线取在 `send()` 之前，而 `send()` 本身会追加一条用户气泡，导致「点击不重复追加」的期望差 1。改为在 `send()` 之后、点击之前取基线，并把「卡片被移除」改成 `after < withCard` 的真断言，63/63 通过。

两条已按 `pitfall-resolver` 闭环回写到 `references/browser-viewport.md`。

## 5. 结论与边界

- **B1 的语境优先 / 跨语境消歧原则在真实模型上可见效果**：Q2、Q4、Q5 主动点明术语所属语境，Q1 与 Q4 都不再犯 00030 的概念错误。提示词只增加了 3 行，没有动 `SnapshotInput` 类型、没有注入站点课程列表（D3 未采纳）。
- **「歧义先澄清」尚未稳定生效**：Q6 在缺少关键输入（具体报错）时仍直接猜测原因。按方案约定，这属于「抽检显示规则仍被忽略」的情形，可考虑把该规则在 `BASE_PERSONA` 中提前，或重新评估 D3——但**属新一轮任务，本次不实施**。
- **不能外推**：单端点、单模型、单次采样，模型输出有随机性；本记录只证明「这一轮不再出现那个具体错误」，不证明普遍正确率提升，也不构成 CI 门禁。
- **未覆盖**：课时页 / 概念页的真实模型输出（本次刻意选首页做基线对照）、HTTPS 线上的 Mixed Content、更长输出的 60s 超时。
