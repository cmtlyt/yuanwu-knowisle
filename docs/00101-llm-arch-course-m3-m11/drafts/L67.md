### 把 671B 装进 2048 张卡

L66 把模型与训练目标讲完，接下来是一个工程问题：671B 参数、14.8T token，单卡根本装不下、也算不动。DeepSeek-V3 用 2048 张 H800 训练，靠的是一套分层的并行策略，论文称为 3D 并行加专家并行。核心思想是把「切什么、在哪切」分成几路：张量并行切矩阵、流水线并行切层、数据并行切样本，MoE 层再按专家切。本课的来源按 spec 标 A 级（S-DSV3），具体卡数分配以官方发布为准，这里用一组能乘出 2048 的配置讲清机制。

### 第一维 TP：节点内切矩阵

张量并行（TP）把一个大矩阵乘切开，多张卡各算一部分再合并，通信是频繁的 all-reduce。因为通信量大、延迟敏感，TP 一般限制在**节点内部**，走 NVLink 这种高速互联。典型做法是把注意力与 FFN 的输出维度按列或按行切到 8 张卡上（TP = 8）。TP 的优点是单步计算被摊薄，缺点是通信随层反复发生，所以不跨节点。

### 第二维 PP 与第三维 DP

流水线并行（PP）把模型按层切成若干阶段，每个阶段放在不同节点上，token 像流水线一样依次流过各阶段。TP 切层内、PP 切层间，两者正交。数据并行（DP）把样本切给不同副本，每步同步梯度，V3 配合 ZeRO 类优化把优化器状态也切分以省显存。设 PP = 16、TP = 8、DP = 16，三者相乘正好 16 × 8 × 16 = 2048 张卡（示意配置，以官方为准）。MoE 层再加一层专家并行 EP：把 256 个路由专家分到不同卡上，token 要按路由结果发到对应专家——这就是跨节点 all-to-all 的来源。

:::deep

### 流水线气泡：PP 的固有代价

PP 有个绕不开的问题：阶段之间有依赖，后面的阶段要等前面的输出，前面算完又要等反向传回来，于是出现**气泡**——某些卡在某些时刻空转。即便用 1F1B（一个前向紧跟一个反向）把气泡压小，气泡占比仍近似是 (p − 1)/(m + p − 1)，其中 p 是阶段数、m 是微批次数。代入 p = 16、m = 32，气泡约 15/47 ≈ 32%——接近三分之一的算力被空转吃掉。阶段越多、微批越少，气泡越严重。DualPipe 就是冲着这块来的：它不按单一方向排前向反向，而是让两个方向的微批**对冲排布**，一侧算前向时另一侧算反向，把空转时段用另一方向的计算填满，同时把通信塞进这些重叠窗口。L70 专门拆解它的调度细节。

:::

### 跨节点 all-to-all 与错峰

MoE 的专家并行让每个 token 按路由结果被发往远端专家，做完再收回来，形成一次 all-to-all。它和 TP 的 all-reduce 不同：TP 在节点内、延迟低；all-to-all 跨节点、走 InfiniBand、延迟高、数据量大。如果让 all-to-all 暴露在关键路径上，GPU 就要空等网络。办法是**错峰**：DualPipe 把 all-to-all 拆成小块，与另一方向的反向计算重叠——一侧在做本地计算时，另一侧的网络传输同时进行，带宽被持续喂满、通信延迟被藏在计算阴影里。这也是为什么 V3 要把流水线调度、专家并行、网络拓扑一起设计：单独看每一层都合理，合起来才能把通信藏干净。

### FP8 混合精度训练

V3 另一项关键工程是 FP8 训练。FP8（E4M3）用 8 位表示浮点数，相比 BF16 把显存占用与搬运量减半，并借 Hopper 架构的 FP8 Tensor Core 把大矩阵乘吞吐翻倍。但直接全 FP8 会溢出、不稳，所以是**混合精度**：大 GEMM 用 FP8，配逐张量或逐块（如 128 × 128 分块）的缩放因子把数值拉回动态范围；主权重、优化器状态保留 BF16/FP32；对精度敏感的算子——layernorm、softmax、MoE 门控、embedding 与输出头——保持高精度。这样既拿到 FP8 的显存与吞吐红利，又保住训练稳定性。

### 维度选择的互相牵制

三维并行不是各选各的，而是互相牵制。TP 增大意味着单次矩阵乘被切得更碎、all-reduce 更频繁，所以 TP 受限于节点内 GPU 数（常见 8）与 NVLink 带宽；PP 增大能切更深的模型，但按 (p − 1)/(m + p − 1) 放大气泡，必须用更大的 m 或 DualPipe 抵消；DP 增大意味着更大的全局 batch，有利于吞吐但可能受显存与收敛稳定性限制。三者乘积被总卡数锁死，调其中一个必然挤占另一个。MoE 的专家并行又额外要求总卡数能被 EP 整除，进一步收窄可选组合。工程上的做法是先按节点拓扑定 TP（节点内几张卡就切几路），再按模型深度与显存定 PP，最后用剩余卡数填 DP，并验证 EP 能整除。

### 可跑代码：3D 并行卡数分解

把卡数分解写成代码，并加入专家并行的分组，验证三维相乘覆盖整 cluster。

```python
def decompose_cluster(total_gpus, tp, pp):
    """给定 TP、PP，求数据并行度并校验乘积覆盖总卡数。"""
    assert total_gpus % (tp * pp) == 0, "TP*PP 必须整除总卡数"
    dp = total_gpus // (tp * pp)
    return dp

total, tp, pp = 2048, 8, 16
dp = decompose_cluster(total, tp, pp)
ep = 64                                  # MoE 层专家并行路数
print(f"TP={tp} PP={pp} DP={dp} → {tp*pp*dp} 张卡")
assert tp * pp * dp == total
assert total % ep == 0, "专家并行路数也要整除总卡数"
print(f"MoE 层另分 {ep} 路专家并行，每路覆盖 {total//ep} 张卡")
```

### 可跑代码：气泡占比对比

算 1F1B 的气泡占比，并展示 DualPipe 用双向填平后的残余量级（示意模型，说明趋势而非论文精确值）。

```python
def bubble_1f1b(p, m):
    """1F1B 流水线气泡占比 ≈ (p-1)/(m+p-1)。"""
    return (p - 1) / (m + p - 1)

def bubble_dualpipe(p, m, overlap=0.9):
    """示意：双向填平把气泡大部分盖住，残余 = 原气泡*(1-overlap)。"""
    return bubble_1f1b(p, m) * (1 - overlap)

p, m = 16, 32
b1 = bubble_1f1b(p, m)
b2 = bubble_dualpipe(p, m)
print(f"PP 阶段 p={p}，微批 m={m}")
print(f"1F1B 气泡 ≈ {b1:.1%}；DualPipe 填平后残余 ≈ {b2:.1%}")
assert b2 < b1 / 5, "双向填平应把气泡压到很小"
print(f"回收算力 ≈ {b1-b2:.1%}（示意，具体值以论文实测为准）")
```

### 可跑代码：all-to-all 数据量与 FP8 显存

算一次专家并行的 all-to-all 搬运量，并对比 FP8 与 BF16 的权重显存。

```python
tokens, hidden, ep, bytes_bf16 = 4096, 5120, 64, 2
# all-to-all：每 token 发给多数远端专家，近似 (ep-1)/ep 的 token 跨节点
cross = tokens * hidden * bytes_bf16 * (ep - 1) / ep / 1e6
print(f"一次 all-to-all 跨节点搬运 ≈ {cross:.1f} MB（需与计算错峰隐藏）")
params_b = 671e9
mem_bf16 = params_b * 2 / 1e12
mem_fp8  = params_b * 1 / 1e12
print(f"671B 权重：BF16 ≈ {mem_bf16:.0f} TB，FP8 ≈ {mem_fp8:.0f} TB")
assert abs(mem_bf16 / mem_fp8 - 2.0) < 1e-9
print("FP8 把权重显存减半，是装下大模型与提速的关键")
```

### 把四件事叠起来看

四件事不是并列开关，而是一套组合拳：3D 并行决定「谁算哪块」，把 671B 摊到 2048 卡；DualPipe 决定「什么时候算」，把 PP 气泡与 all-to-all 通信藏进计算；专家并行决定「MoE 怎么跨卡」，带来跨节点 all-to-all；FP8 决定「用什么精度算」，把显存与带宽压力再砍一半。L70 会单独拆 DualPipe 的调度细节。下一课 L68 做一件不同的事：给一个流传但无来源的名词「mFformer」定论，练来源纪律。

:::tip

### 一句话记住这一课

**TP 切矩阵（节点内）、PP 切层（跨节点）、DP 切样本**，三维相乘覆盖整 cluster，MoE 再叠专家并行。**DualPipe** 用双向流水把气泡与 all-to-all 通信藏进计算。**FP8** 把大 GEMM 减半显存、翻倍吞吐，敏感算子与 master 权重留高精度。记住「切什么、何时算、MoE 怎么跨卡、用什么精度」四个问题，V3 的训练系统就搭起来了。

:::
