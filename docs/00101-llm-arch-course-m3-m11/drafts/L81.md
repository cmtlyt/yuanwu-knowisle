### 为什么 loss 曲线不够：要独立测能力

L78 用 loss 曲线与困惑度判断训练是否有效，L79 用困惑度验证领域适配。但这两者都是**语言建模拟合度**的指标——它们告诉你模型有多像训练分布，却不能直接告诉你模型「能不能做题」。GPT-3 论文（2005.14165，A 级来源）系统观察到一个现象：下游任务能力随模型规模增长时，会在某些点出现**非线性跃升**，而困惑度是平滑下降的。这意味着你不能看着 PPL 曲线就断言「能力到了」——必须拿具体任务去探。

本课把「能力探针」做成可跑的实操：写 zero-shot 与 few-shot 探针，分别测分类、检索、简单推理三类任务，在不同规模/不同训练步数的模型上跑，观察能力随规模或步数的变化（涌现点），并用结果论证「困惑度下降≠能力涌现」。探针不改模型权重——它就是拿提示去问模型、用规则或答案匹配算分。

### zero-shot 与 few-shot：两种提示范式

**zero-shot** 只给任务描述与输入，比如「判断下面评论的情感，只回答正面或负面：{评论}」。**few-shot** 在提示里先放 k 个「输入→输出」示例，再放真正要测的输入，靠**上下文学习（in-context learning, ICL）**让模型从示例里归纳任务模式——全程不更新权重。GPT-3 的核心发现之一就是：足够大的模型仅凭 few-shot 提示就能完成没专门为它训练的任务，且规模越大 ICL 越强。

把两种提示构造写成可跑代码。用一个假想的 `ask(model, prompt)` 接口（真实项目接 L78 训练的 `GPT2LMHeadModel.generate`），构造分类任务的 zero-shot 与 few-shot 提示。

```python
def build_prompt(task, example_pairs, query, k=0, few_shot=True):
    """构造分类提示：few_shot=True 时前插 k 个示例。"""
    head = task.strip() + "\n"
    if few_shot and k > 0:
        for ex, ans in example_pairs[:k]:
            head += f"输入：{ex}\n输出：{ans}\n"
    head += f"输入：{query}\n输出："
    return head

task = "判断评论情感，只回答 正面 或 负面"
pairs = [("质量很好，喜欢", "正面"), ("太差了，退货", "负面"),
         ("体验不错", "正面"), ("很失望", "负面")]
query = "物流很快，包装用心"
p0 = build_prompt(task, pairs, query, k=0, few_shot=False)
p3 = build_prompt(task, pairs, query, k=3, few_shot=True)
print("=== zero-shot ===\n" + p0)
print("=== 3-shot ===\n" + p3)
assert "正面" in p3 and p3.count("输出：") == 4   # 3 示例 + 1 查询
assert "正面" not in p0.split("输出：")[-2]      # zero-shot 无示例
```

断言检查提示结构正确：3-shot 提示里有 3 个示例答案加 1 个待答、共 4 个「输出：」；zero-shot 没有示例。few-shot 提示让模型在回答前先看到「输入→标签」的映射模式，这正是 ICL 的载体。

:::deep

### 为什么 few-shot 不更新权重却有效

few-shot 的示例没有进入训练 loss、没有梯度、没有改一个参数——它们只是作为上下文 token 被注意力机制读取。模型之所以能用，是因为预训练阶段见过海量「从上下文归纳模式」的任务，学会了**在上下文里做模式匹配**的元能力。注意力让查询 token 能看到示例 token，相当于在激活空间里临时「拟合」了一个任务映射，前向结束即消失，不留痕迹。这就是 in-context learning 与微调的本质区别：一个是 transient（临时、不改权重），一个是 persistent（持久改权重）。探针用 few-shot，正是要测这种「从上下文学任务」的元能力——它随规模增长明显，是涌现研究的核心对象。

:::

### 三类探针：分类、检索、简单推理

设计三类探针，覆盖不同能力维度。每类探针固定任务与打分规则，保证跨模型可比：

- **分类**：情感/主题分类，看输出是否等于金标签（精确匹配率）。
- **检索**：在一段上下文里埋入事实，问「X 是什么」，看能否取出（needle-in-a-haystack 的简化版）。
- **简单推理**：两三步算术或常识推理（如「若 A>B 且 B>C，则 A 和 C 谁大」），看答案是否正确。

下面实现一个统一的探针框架，用可接真实模型的 `ask` 接口跑这三类任务，并用规则算准确率。为可离线运行，`ask` 用一个基于关键词的模拟函数；真实项目替换为模型生成。

```python
import re

def ask(prompt, model=None):
    """探针调用接口。真实项目替换为 model.generate + decode。"""
    if model is not None:
        ids = tok.encode(prompt).ids
        out = model.generate(torch.tensor([ids]), max_new_tokens=8,
                             do_sample=False, pad_token_id=1)
        return tok.decode(out[0].tolist())
    # 离线模拟：按提示末尾关键词给一个「伪预测」，演示打分流程
    if "包装用心" in prompt or "喜欢" in prompt[-30:]:
        return "正面"
    if "巴黎" in prompt:
        return "法国"
    if "A>B" in prompt or "大于" in prompt:
        return "A"
    return "负面"

def probe_classification(ask_fn):
    cases = [("质量很好", "正面"), ("太差了", "负面"),
             ("物流很快，包装用心", "正面"), ("很失望", "负面")]
    prompts = [build_prompt("判断情感，只回答 正面 或 负面", pairs, q, k=2)
               for q, _ in cases]
    preds = [ask_fn(p).strip() for p in prompts]
    acc = sum(pr == gold for pr, (_, gold) in zip(preds, cases)) / len(cases)
    return acc, preds

acc, preds = probe_classification(ask)
print("分类探针准确率:", acc, "预测:", preds)
assert 0.0 <= acc <= 1.0
```

分类探针用精确匹配率打分：4 个样本里预测等于金标签的比例。真实模型下，few-shot 示例让模型学会「输出只能是正面/负面」的格式，准确率随规模上升。检索与推理探针结构相同，只换任务与金标签。

```python
def probe_retrieval(ask_fn):
    ctx = "张三的出生地是巴黎。李四喜欢登山。王五在东京工作。"
    q = "张三的出生地是哪个城市？只回答城市名"
    p = f"{ctx}\n{q}\n答案："
    ans = ask_fn(p).strip()
    return int("巴黎" in ans), ans

def probe_reasoning(ask_fn):
    # 简单传递推理：A>B 且 B>C => A>C
    p = ("已知 A大于B，B大于C。请问 A 和 C 谁更大？只回答 A 或 C\n答案：")
    ans = ask_fn(p).strip()
    return int("A" in ans and "C" not in ans[:2]), ans

r_ret, a_ret = probe_retrieval(ask)
r_rea, a_rea = probe_reasoning(ask)
print(f"检索探针: {r_ret} (答:{a_ret})   推理探针: {r_rea} (答:{a_rea})")
assert r_ret in (0,1) and r_rea in (0,1)
```

这三个探针合起来给出一张「能力画像」：分类看模式归纳、检索看信息提取、推理看多步推断。关键点——**一个探针的高分不能外推到另一个**。模型可能检索满分但推理不及格，这正是为什么不能用一个 PPL 概括能力。

### 观察涌现点：跨规模/跨步数扫描

涌现的核心是「非线性跃升」。用可跑代码模拟在多个模型规模上跑同一探针，对比 PPL（平滑下降）与准确率（某点跃升）。这里的数字是演示用的合成数据，用来讲清「怎么从数据里看出涌现点」；真实项目把规模换成你实际训的模型（如 L78 的 125M 到 L82 的 700M），准确率换成实测。

```python
# 合成演示：规模（M）vs PPL（平滑降）vs few-shot 准确率（某点跃升）
scales = [50, 125, 350, 700, 1500, 7000]      # 参数量 M
ppls   = [22.0, 18.5, 15.0, 13.2, 11.5, 9.0] # 平滑下降
accs   = [0.25, 0.27, 0.30, 0.62, 0.75, 0.88] # 700M 附近跃升

print(f"{'规模M':>7s} {'PPL':>6s} {'few-shot准确率':>14s} {'PPL降幅':>8s}")
prev_ppl = None
for s, p, a in zip(scales, ppls, accs):
    delta = "" if prev_ppl is None else f"{prev_ppl-p:+.1f}"
    print(f"{s:7d} {p:6.1f} {a:14.2f} {delta:>8s}")
    prev_ppl = p

# 涌现点检测：准确率相邻增幅最大的规模
jumps = [(scales[i], accs[i]-accs[i-1]) for i in range(1, len(scales))]
emergent_at = max(jumps, key=lambda x: x[1])
print(f"准确率跃升最大点: {emergent_at[0]}M (Δacc={emergent_at[1]:.2f})")
# PPL 在 350->700 只降 1.8，但 acc 跳 0.32 -> 能力跃升不被 PPL 平滑反映
assert emergent_at[0] == 700
print("涌现点观察完成：PPL 平滑下降，能力在 700M 附近非线性跃升")
```

读法：PPL 从 50M 到 7000M 一路平滑下降，每步降幅相近；但 few-shot 准确率在 350M 到 700M 之间从 0.30 跳到 0.62（Δ0.32），远大于其他区间——这就是涌现点。**若只看 PPL，你会以为能力在均匀增长；探针才揭示它在某点突变**。这正是「困惑度↓≠能力涌现」的实证：两者相关（规模大 PPL 低、能力强），但不是同一条曲线。

### 把困惑度与能力分开看：论证与判据

把这一课的结论收成可执行的判断。第一，**两个指标分开报**：训练报告里同时给 PPL 曲线与能力探针表，不能用 PPL 代替后者。第二，**探针要覆盖多维**：分类、检索、推理至少各一个，避免「一个任务强就以为全能」。第三，**same prompt、same 打分**：跨规模比较时提示模板与打分规则必须一致，否则差异来自测量方式而非能力。第四，**关注跃升而非绝对值**：涌现研究看的是准确率随规模的斜率变化，不是某个模型的单点分数。

一个常见误区是在小模型（如 125M）上测不到某能力就断言「该能力不存在」。涌现是尺度相关的：很多能力要在足够大的规模才出现，125M 测不到很正常，不代表规律错了。反过来，也不能因为大模型 PPL 低就说它「什么都会」——仍需具体任务验证。把 PPL 当「语言建模质量的代理」、把探针当「能力的直接证据」，两者分工明确、互相补充，才是对待预训练效果的正确态度。

:::tip

### 一句话收束能力探针与涌现

PPL=exp(交叉熵) 衡量语言建模拟合度、曲线平滑；能力是具体任务上的表现，可能在规模跨阈值时非线性跃升（涌现），二者相关但不等价，须分开看（GPT-3，2005.14165，A 级）。探针用 zero-shot（无示例）与 few-shot（提示里放 k 个示例，ICL 不改权重），覆盖分类/检索/推理多维，same prompt same 打分跨规模比。从数据里找涌现点看「准确率相邻增幅最大」的规模，而不是看 PPL 降幅。下一课 L82 capstone 把从零 700M + 多卡 ZeRO + loss/困惑度/token 参数核算串成完整交付。

:::
