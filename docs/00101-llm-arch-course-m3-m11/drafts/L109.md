### 权重量化 vs 激活量化：先分清压什么

L106 的 GGUF 与本课的 GPTQ/AWQ/FP8 都叫「量化」，但要先分清压的对象。**权重量化**只压缩存储中的权重矩阵 W，推理时把低比特权重反量化后做计算——它省的是**显存带宽与存储**，部署侧最常见，GGUF、GPTQ、AWQ 都属此类。**激活量化**连前向传播中的激活张量也压到低比特，省的是**激活显存与访存**，但激活的动态范围随输入变化、更难处理，常需平滑异常值（如 SmoothQuant）。此外还有 KV cache 量化（L15/L21 提过，压生成时缓存的 K/V）。三者正交，可叠加：权重压 4bit、KV 压 8bit、激活压 8bit，总显存与带宽收益叠乘。

这里还要区分**训练时量化**（QAT）与**后训练量化**（PTQ）：QAT 在训练过程里插入伪量化节点，让模型适应低精度，精度最好但要重训、成本高；PTQ 在模型训好后用少量校准数据定量化参数，分钟级完成，是部署侧的主流——GPTQ、AWQ、GGUF 的 k-quants 都属于 PTQ。L109 聚焦 PTQ，因为它直接接在 M10 的对齐产出之后，不需要回头动训练流程。选 PTQ 时「校准数据」的质量至关重要：它要与真实推理分布匹配，用与任务无关的数据校准，量化参数会偏离实际使用区间，导致线上精度掉点——这也是很多团队「离线测得好、上线就变差」的隐藏原因。校准集不必很大，几百到几千条典型样本通常够用，但必须覆盖真实流量的长度与领域分布；拿与业务无关的数据「凑数」，等于把量化参数锚定在错误的区间上。校准完成后务必留出一批未参与校准的样本做精度复核，确认量化损失在可接受范围内再交付。

:::deep

### 为什么权重量化「几乎无损」而激活量化更难

权重的数值分布在训练后是**静态**的——你可以拿校准数据仔细统计每个通道/块的取值范围，选好缩放因子，一次性量化到位，误差可控。激活则**随输入动态变化**：某些 token 的某些通道会出现远超均值的异常大值（outlier），若按平均值定缩放因子，异常值会被截断；若按异常值定，大部分正常值又浪费了精度。这就是激活量化难的原因，也是 L109 把「权重 vs 激活」单列出来的意义——**看一个量化方案，先问它压的是谁，就知道它的难点与收益在哪**。

:::

### GPTQ：用二阶信息一次性压到 3 到 4bit

GPTQ（arXiv:2210.17323）是后训练权重量化的经典方法。它的洞察：逐列量化权重时，某一列舍入产生的误差如果不处理，会累积到后面未量化的列。GPTQ 用权重矩阵的**近似 Hessian 逆**（二阶信息）把当前列的误差**补偿**到后续列，使它们吸收这部分误差、整体输出偏差最小。因为只需一次性扫描校准数据、不需要重新训练，GPTQ 能在几分钟内把大模型压到 3 到 4bit。下面用一段可跑代码演示「量化 + 误差补偿」的核心机制。

```python
import numpy as np
np.random.seed(0)
d = 8
W = np.random.randn(d, d).astype(np.float64) * 0.1
Hinv = np.linalg.inv(W.T @ W + 1e-2 * np.eye(d))   # 二阶信息逆（示意）

def quantize_to_bits(x, bits=3):
    qmax = 2 ** (bits - 1) - 1
    scale = np.max(np.abs(x)) / qmax
    return np.round(x / scale).clip(-qmax, qmax) * scale

Wq = W.copy()
total_err = 0.0
for j in range(d):
    q = quantize_to_bits(Wq[:, j], bits=3)
    err = Wq[:, j] - q
    total_err += float(np.sum(err ** 2))
    Wq[:, j] = q
    # GPTQ 精髓：用 Hinv 把该列误差补偿到后续未量化列
    if j + 1 < d:
        Wq[:, j+1:] += np.outer(err, Hinv[j, j+1:]) / (Hinv[j, j] + 1e-9) * 0.05

print("3bit 量化平方误差:", round(total_err, 6))
ratio = float(np.linalg.norm(Wq) / np.linalg.norm(W))
print("量化前后范数比:", round(ratio, 3))
assert total_err > 0, "量化必然引入误差"
assert 0.5 < ratio < 1.5, "补偿后范数应接近原始"
```

代码里的 `Hinv` 就是 GPTQ 的「二阶信息」——它决定误差该往哪些列、按多大比例传播。补偿后整体范数接近原始（约 1.0），说明量化没有系统性放大权重；3 到 4bit 下精度损失主要来自舍入本身，而补偿把「本该累积的误差」消化掉了。

### AWQ：激活感知，只保 1% 显著通道

AWQ（Activation-aware Weight Quantization，arXiv:2306.00978）走的是另一条思路：它统计**校准激活**在每个权重通道上的平均幅值，发现极少数通道（约 0.1% 到 1%）承载了绝大部分激活能量——这些是**显著通道**，对模型输出影响极大。AWQ 的做法是给显著通道的权重乘一个放大系数再量化，量化后再除回去，相当于用「细刻度」保护它们，其余通道照常压低比特。下面用代码演示这个「保护 1% 通道」的机制。

```python
import numpy as np
np.random.seed(1)
d, n = 64, 256
W = np.random.randn(d, n).astype(np.float32) * 0.02
X = np.random.randn(n, 512).astype(np.float32)      # 校准激活
act_scale = np.mean(np.abs(X), axis=1)              # 每输入通道平均激活幅值
k = max(1, int(0.01 * d))                           # 只保 1% 显著通道
salient = np.argsort(act_scale)[-k:]
print("显著通道数(1%):", k, "索引示例:", salient[:5].tolist())

scales = np.ones(d, dtype=np.float32)
scales[salient] = 4.0                               # 放大显著通道权重再量化
W_scaled = W * scales[:, None]
W_q = np.round(W_scaled / 0.01).clip(-127, 127) * 0.01   # 8bit 示意
W_dequant = W_q / scales[:, None]                   # 除回去，等效细刻度
err = float(np.mean((W_dequant - W) ** 2))
print("AWQ 保护后均方误差:", round(err, 8))
assert k == 1, "1% of 64 = 1 个显著通道"
assert err > 0, "量化仍有误差"
```

这里 d=64 时 1% 只对应 1 个显著通道；真实大模型维度更高、显著通道更多，但比例仍极小——这正是 AWQ 的精髓：**用极小的保护面（约 1% 通道）换取几乎无损的量化**。AWQ 通常与高效内核配合，把「放大/除回」折进计算流程，不额外增加推理开销。

### FP8：浮点 8bit 与吞吐

FP8 是 8 位**浮点**格式（不是 INT8），有两种主要变体：**E4M3**（4 位指数 + 3 位尾数，精度较高，常用于推理的权重与激活）和 **E5M2**（5 位指数 + 2 位尾数，动态范围大，常用于训练梯度）。现代 GPU（Hopper 及以后）原生支持 FP8 Tensor Core，吞吐相对 FP16 可显著提升。下面用代码看两种格式的表示范围与精度差异。

```python
import numpy as np
# E4M3 最大可表示值（量级示意）
def fp8_e4m3_max():
    return 2 ** (2**3 - 1 + 1) * (1 + 7/8)
print("E4M3 最大可表示值(量级示意):", round(fp8_e4m3_max()))

x = np.array([0.1234, -0.5678, 1.2345], dtype=np.float32)
for name in ("fp16", "bf16", "fp8-like"):
    if name == "fp16":
        y = x.astype(np.float16).astype(np.float32)
    elif name == "bf16":
        y = (x.view(np.uint32) & 0xFFFF0000).view(np.float32)  # 保留高 16 位
    else:
        y = np.round(x * 16) / 16                              # E4M3 粗示意
    rel = float(np.max(np.abs(y - x) / (np.abs(x) + 1e-9)))
    print(f"{name:9s} 最大相对误差={rel:.4f}")
assert fp8_e4m3_max() > 100, "E4M3 动态范围应足够容纳常见权重"
```

FP8 的收益是**硬件相关**的：只有在原生支持 FP8 的 GPU 上、且框架真正走到 FP8 kernel 时才有吞吐提升；软件模拟的 FP8 只是更差的 FP16，不会提速。这呼应 L107 的判据——量化能否兑现为吞吐，必须在目标硬件上实测。

:::tip

### 三法对照与实测判据

- **GPTQ**：二阶误差补偿、一次性压 3 到 4bit，压缩率高，适合显存极紧、离线量化；对校准数据分布敏感。
- **AWQ**：激活感知保护约 1% 显著通道，精度好、可配合高效内核，适合通用推理部署。
- **FP8**：硬件原生浮点 8bit，精度介于 FP16 与 INT8 之间，吞吐收益大但绑定硬件，适合新 GPU 的生产服务。

实测判据永远是两条：① **精度**——在你真实任务上对比量化前后的基准分数，掉点是否可接受；② **吞吐**——在目标 GPU 上用 L110 的压测脚本测 tokens/s，确认量化真的换来提速而非只省了文件体积。下一课 L110 把「吞吐调优与压测」系统展开，把这里的量化收益落到可复现的数字上。

:::
