### 场景：局部编辑为什么是自回归的痛点

真实工作流里，生成很少是「从空白写到底」——更多是「把这段改得更好」「在中间补一句」「按指定格式填字段」。自回归模型在这些场景下很别扭：它只能左到右逐 token 生成，要改句中某段，往往得把该段之前的 token 重新喂进去、再顺着续写，而该段之后的后缀因为因果依赖被「锁死」——你想保留后缀不变，模型却无法在「不改后缀」的约束下只重算中间。工程上常见的变通是「重新生成整句再挑着用」，既浪费又不保证非编辑区一致。扩散 LLM 把这件事变简单了：因为去噪是双向、且掩码位置可任意指定，**固定已知位置、只把要改的段设为 [MASK] 再去噪**，后缀根本不用重算。这一课把三种典型操作跑成冒烟：inpainting（填充被掩区）、FIM（填中间）、约束生成（按位置/格式约束生成），并用可执行断言验证「局部编辑的可用性」。实验不依赖真模型权重也能先把判据逻辑跑通，再接 LLaDA 或 SEDD 的真实推理。

### 三种操作：inpainting、FIM、约束生成

三种操作本质是同一件事的不同掩码摆法，理解这点就不会把它们当三种功能。

**inpainting（填充）**：把待生成区域设为 [MASK]，其余位置作为已知上下文，去噪填回。图像领域的 inpainting 是抠掉一块补画面，文本里就是把一段词抠掉补句子。

**FIM（fill-in-the-middle）**：这是 inpainting 的一个高频特例——已知前缀 A 和后缀 B，要把中间段 C 填上。在扩散框架里，A 与 B 都作为可见上下文（去因果双向注意力的天然能力），只把 C 的位置掩码，去噪填 C。自回归做 FIM 需要专门训练「前缀 后缀 中间」的特殊格式，扩散则天生支持。

**约束生成**：在指定位置必须是某词、某格式、某长度等约束下生成。实现方式还是控制掩码——把「必须固定的位置」保持已知（不掩码），把「自由生成的位置」掩码，去噪时已知的约束位作为上下文引导其余位置。SEDD 的 score（L52）在这里尤其有用，它给出每个被掩位的恢复倾向，便于把约束当条件注入。

:::deep

### 任意顺序 vs 自回归单向不可编辑：一张对照

把两种范式的编辑能力钉成对照，选型时一目了然：

- **可改的位置**：自回归天然只能续写尾部，改中间要靠重生成；扩散任意位置都可设为掩码再填。
- **后缀处理**：自回归改中间会连带后缀失效（因果依赖），扩散后缀作为已知上下文保持不变。
- **上下文可见性**：自回归只能看左侧（因果掩码），扩散左右都看（去因果双向），FIM 的后缀信息能用上。
- **计算范围**：自回归局部改动常退化为整句重生成；扩散只对被掩段迭代去噪，局部改动的步数可压低（L53 的步数旋钮）。

要客观：扩散的「局部编辑更省」是指**编辑场景**，整句从头生成时它仍要付出多步去噪的代价，未必比自回归快。优势场景与代价要分开讲——这正是 M6 选型的核心纪律。

:::

### 可跑代码：三种编辑的冒烟对比

下面的脚本用纯 Python 模拟「掩码占位与填回」的过程（不依赖真权重），把三种操作的输入输出与可编辑断言跑通；接真模型时只要把 `denoise()` 换成 LLaDA/SEDD 的推理调用即可。

```python
MASK = "[M]"

def apply_mask(tokens, span):
    """把 tokens 在 span=(start, end) 的位置设为 MASK，返回新序列。"""
    out = list(tokens)
    for i in range(span[0], span[1]):
        out[i] = MASK
    return out

def denoise(masked, filled):
    """模拟去噪填回：把 MASK 位置按顺序填入给定 token（真模型按 score 采样）。"""
    out, k = [], 0
    for t in masked:
        if t == MASK:
            out.append(filled[k]); k += 1
        else:
            out.append(t)
    assert k == len(filled), "填回数量须与 MASK 数一致"
    return out

def unchanged_outside(orig, edited, span):
    """局部编辑判据：非编辑区必须逐 token 不变。"""
    return all(orig[i] == edited[i] for i in range(len(orig))
               if not (span[0] <= i < span[1]))

sent = ["我", "今", "天", "吃", "了", "苹", "果"]
# inpainting：把「苹果」两字抠掉重填
m = apply_mask(sent, (5, 7))
e = denoise(m, ["香", "蕉"])
print("inpainting:", "".join(e))
assert unchanged_outside(sent, e, (5, 7)), "非编辑区不得改变"
# FIM：已知前缀「我今天吃了」+后缀「真好吃」，填中间
base = ["我", "今", "天", "吃", "了", MASK, MASK, "真", "好", "吃"]
e2 = denoise(base, ["一", "碗", "面"][:2])
print("FIM:", "".join(e2))
assert e2[:5] == base[:5] and e2[-3:] == base[-3:], "FIM 前后缀须保持"
```

```python
def constraint_fill(slots, fixed):
    """约束生成：fixed 字典固定某些位置，其余按候选填。"""
    out = []
    for i, cand in enumerate(slots):
        out.append(fixed.get(i, cand[0]))   # 约束位取固定值，自由位取首候选
    return out

fixed = {2: "必须"}                       # 第 2 位必须是「必须」
slots = [["我们"], ["要"], ["必须"], ["完成"]]
res = constraint_fill(slots, fixed)
print("约束生成:", "".join(res))
assert res[2] == "必须", "约束位必须取指定值"
assert len(res) == len(slots), "长度须匹配"
print("三种编辑操作的可用性断言全部通过")
```

第一段把 inpainting 与 FIM 跑通：`apply_mask` 摆掩码、`denoise` 填回、`unchanged_outside` 验证局部性——最后一条断言是「局部编辑」的灵魂：非编辑区逐 token 不变。FIM 还验证前后缀保持，这正是自回归难做而扩散天然会的点。第二段验证约束生成：固定位取指定值、自由位自动生成。三段合起来构成一组可复用的编辑冒烟测试，把真模型接进来就能升级成实际评测。

### 编辑开销的数值自检：局部到底省多少

局部编辑的「省」要能算成数字，否则只是直觉。算一笔账：设整句长 L 个 token，编辑段长 m 个 token（m 远小于 L），去噪步数 s。整句重生成要处理 L 个 token 乘以 s 步（每步对所有位置算注意力），而局部编辑虽然去噪仍走双向注意力（要看全句上下文），但可以把已确定位置的反复去噪降为零——只在被掩的 m 个位置上迭代 s 步，其余位置作为固定上下文只算一次。更关键的是自回归的对比基线：改中间一段，自回归要么重算整句后缀（该段之后所有位置的 KV 全部作废重来），要么放弃一致性。扩散则复用全部已知位置，只花 m 个位置的去噪算力。用下面的脚本把两笔账算清楚。

```python
def edit_cost(length, edit_span, steps):
    """处理量（token×步）：整句重生成 vs 局部去噪。已知位只算 1 次上下文。"""
    full_regen = length * steps
    local = edit_span * steps + (length - edit_span)
    return full_regen, local

L, m, s = 128, 12, 16
full, local = edit_cost(L, m, s)
print(f"整句长 {L}、编辑 {m} 字、{s} 步：重生成 {full} vs 局部 {local} 单元")
print(f"局部处理量约为整句的 {local/full:.1%}")
assert local < full * 0.3, "编辑段远小于整句时，局部处理量应显著更小"

full2, local2 = edit_cost(128, 120, 16)
assert local2 > full2 * 0.9, "编辑占比接近 1 时，局部退化为整句生成"
print("编辑占比决定收益：占比小则省，占比大则退化")
```

这段把「局部编辑省多少」钉成可核对的量：编辑段只占整句约十分之一时，局部处理量约为整句重生成的几成——这就是「局部」二字的量化含义。要诚实说明，这里是教学用的简化模型（真实双向注意力每步仍扫描全句，省的是「对已确定位置的反复去噪」而非注意力扫描本身），但方向正确：编辑段越小、句子越长，相对收益越大。反过来，若要改整句的大部分（m 接近 L），局部编辑就退化成整句生成，多步代价照付不误——这正是选型时容易被忽略的隐藏变量「编辑占比」。

### 可用性判据与常见翻车点

把「局部编辑可用」落成可勾选的三条判据：① **编辑区正确且通顺**——填回内容语义/语法合格；② **非编辑区不变**——上面 `unchanged_outside` 的断言，这是「局部」的硬指标；③ **不重算后缀**——编辑范围之外的 token 全部复用，步数只花在被掩段。三条同时成立才叫真·局部编辑，缺任何一条都退化成「重生成碰巧相似」。三个常见翻车点：一是**FIM 时把后缀也掩码了**，丢掉后缀这个关键上下文，填出的中间与后缀接不上——后缀必须是可见的；二是**掩码范围与实际改动不一致**，多掩了邻近词导致「非编辑区」被改，断言会挂；三是**步数给太多导致过生成**，扩散在已确定的位置反复去噪可能把好词改坏，局部编辑时步数应比整句生成更保守。接真模型时，把这三判据写成自动断言，每次改动都跑一遍，比肉眼看靠谱得多。

:::tip

### 收束：编辑的本质是「控制掩码位置」

inpainting、FIM、约束生成看似三种功能，本质是同一件事——**控制哪些位置被掩、哪些位置固定**，然后让双向去噪填回被掩位。自回归因因果顺序做不到「固定后缀只改中间」，扩散因去因果双向 + 掩码可调而天生擅长。记住三条可用性判据（编辑区正确、非编辑区不变、不重算后缀），它们把「局部」从口号变成可断言的工程指标。到这里 M5 讲完扩散范式的原理、实测、谱系、理论与编辑；从 L55 起进入 M6，把扩散与自回归、MoE、SSM 放进同一张五维矩阵做横向选型。

:::
