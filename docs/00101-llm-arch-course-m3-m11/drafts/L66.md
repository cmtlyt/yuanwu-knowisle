### 单 token 预测的局限

标准语言模型在每个位置只做一件事：预测下一个 token，用一个交叉熵监督。训练信号是「一位一位」给的，每个位置只贡献一个未来 token 的监督。MTP（Multi-Token Prediction，DeepSeek-V3，arXiv:2412.19437）的想法是：既然一个位置的隐藏态已经包含了上下文信息，为什么只让它预测一个未来 token？如果让它同时预测接下来 k 个 token，训练信号密度提高，模型被迫学更长的依赖；更妙的是，这套多 token 预测头在推理时能直接当草稿模型用，做推测解码加速。

### k 个未来 token 需要 k−1 个模块

MTP 的结构是**串行**的，不是并排的。主模型的输出头先预测第 1 个未来 token（位置 i 预测 t_{i+1}）。第 1 个 MTP 模块拿主模型在该位置的隐藏态，以及已预测出的 t_{i+1} 的嵌入，拼在一起算出自己的隐藏态，再预测 t_{i+2}。第 2 个模块再拿第 1 个模块的隐藏态与 t_{i+2} 的嵌入，预测 t_{i+3}。依此类推。于是要预测 k 个未来 token，除主模型头负责的第 1 个外，还需要 k−1 个 MTP 模块，每个模块依赖前一个的输出——这就是「k−1 个模块」的来由，也是它不能完全并行、而要在推理时当串行草稿链的原因。V3 训练时实际取 k = 2（即 1 个 MTP 模块，论文记 D = 1），但机制可推广到任意 k。

### 训练目标：把信号变密

每个 MTP 模块对自己负责的那个未来 token 做一个交叉熵。总损失写成：主模型标准损失，加上 λ 倍的各 MTP 模块损失的均值。λ 是权衡系数，控制多 token 目标对主任务的影响。这样做有两层收益：一是**信号更密**——同一个位置的隐藏态现在要解释多个未来 token，学到的表示更扎实；二是**天然对齐推理**——训练时模块就是在「给定已预测 token 预测下一个」，推理时把它当草稿头，行为分布一致，草稿质量比外挂一个独立小模型更高，接受率更好。

:::deep

### 推理时怎么用：推测解码全流程

训练完的 MTP 模块在推理时变成一条**草稿链**。给定当前隐藏态，主模型头预测候选 t₁，第 1 个 MTP 模块接着预测 t₂，第 2 个预测 t₃……一口气吐出 γ 个草稿 token。然后主模型用**一次前向**并行验证这 γ 个草稿：如果从第 1 个到第 j 个都对上了，就接受这段前缀，再顺手取主模型给出的第 j+1 个 token，于是这一步总共产出 j+1 个 token；遇到第一个不对的草稿就截断，从那里重新来。因为草稿来自与主模型联合训练的 MTP，分布接近主模型，接受率 α 显著高于「随便找个小模型当草稿」的方案。单次验证是并行的（γ 个位置一次前向），所以「每步多出好几个 token」直接变成吞吐提升。

:::

### 接受率与加速的定量账

把推测解码的收益写成期望：设每步生成 γ 个草稿 token，每个被独立接受的概率是 α。这一步能产出的 token 数是「接受前缀长度 + 1 个额外 token」，其期望是对 1, α, α² 一直到 α^γ 求和，即 (1 − α^(γ+1))/(1 − α)。α 越高，这个期望越大：α = 0.8、γ = 4 时约 3.36 个 token 每步，相对单 token 解码就是约 3.36 倍的步数节省（忽略草稿本身的开销）。这解释了为什么 MTP 强调「草稿质量」——α 从 0.5 提到 0.8，收益是数量级的差别。

### 可跑代码：MTP 模块的串行前传

用一个极简 numpy 版 MTP 模块展示「上一模块隐藏态 + 已预测 token 嵌入 → 下一个 token 分布」，并断言 k−1 个模块产出 k 个 token。

```python
import numpy as np

rng = np.random.default_rng(0)
d_model, vocab, k = 16, 100, 4          # 预测 k=4 个未来 token

# 共享的嵌入表与输出头（简化：一个线性层当分类器）
E = rng.normal(size=(vocab, d_model)) * 0.1
W_head = rng.normal(size=(d_model, vocab)) * 0.1

def predict_next(h, token_id):
    """一个 MTP 模块：拼接隐藏态与该 token 嵌入，预测下一个 token。"""
    x = h + E[token_id]                 # 简化融合；真实实现用 concat + 投影
    logits = x @ W_head
    return int(np.argmax(logits)), x    # 返回预测 token 与新隐藏态

h = rng.normal(size=d_model)            # 主模型在当前位置的隐藏态
tok = int(rng.integers(vocab))          # 主模型头预测的第 1 个未来 token
drafts = [tok]
for module in range(k - 1):             # k−1 个 MTP 模块
    tok, h = predict_next(h, tok)
    drafts.append(tok)
print(f"k={k} 个未来 token：{drafts}")
print(f"MTP 模块数 = {len(drafts) - 1} = k-1")
assert len(drafts) == k and len(drafts) - 1 == k - 1
```

### 可跑代码：接受率决定加速

把期望产出 token 数写成公式，扫不同 α 与草稿长度 γ，断言加速随 α 单调上升。

```python
def expected_tokens(alpha, gamma):
    """每步期望产出的 token 数 = 1 + α + ... + α^γ。"""
    if abs(alpha - 1.0) < 1e-9:
        return gamma + 1
    return (1 - alpha ** (gamma + 1)) / (1 - alpha)

gamma = 4
print(f"草稿长度 γ={gamma} 时，不同接受率 α 的每步期望 token 数：")
prev = 0.0
for a in (0.3, 0.5, 0.7, 0.8, 0.9):
    e = expected_tokens(a, gamma)
    print(f"  α={a:.1f} → 期望 {e:.2f} token/步（约 {e:.2f}× 步数节省）")
    assert e > prev, "期望产出应随接受率单调上升"
    prev = e
assert expected_tokens(0.8, 4) > 3.0
print("结论：MTP 草稿质量越高（α 越大），推测解码加速越明显")
```

### 与单 token 预测对照

把两者钉在一起看差异。单 token 预测：每位置一个交叉熵、一个输出头、推理每步只出一个 token。MTP：每位置 k 个交叉熵（主头 1 + k−1 个模块）、训练信号更密、推理时那 k−1 个模块当草稿链、靠主模型一次并行验证把「每步一个 token」变成「每步多个 token」。代价是多了 k−1 个小模块与它们的训练损失，以及推测解码的验证调度复杂度；收益是表示更扎实与解码加速。V3 选 k = 2 是在「加速够用」与「额外开销可控」之间取的点。下一课 L67 转向训练系统，看 3D 并行、DualPipe 与 FP8 怎么把 671B 模型真正训起来。

:::tip

### 一句话记住 MTP

训练上，主头加 k−1 个串行模块，每位置监督 k 个未来 token，信号更密；推理上，这些模块当草稿链吐出 γ 个候选，主模型一次前向并行验证，按接受前缀推进。加速由接受率 α 决定，期望产出约 (1 − α^(γ+1))/(1 − α)。记住「k 个 token = k−1 个模块」「串行草稿 + 并行验证」「α 越高越快」三点，MTP 就讲透了。

:::
