### 场景与目标：为什么要亲手跑一遍 LLaDA-8B

上一课从原理上讲了离散扩散的前向掩码与反向去噪，但纸面机制不能回答工程问题：一个 2.3T token 训练的 8B 扩散模型，实际能不能当自回归一样用？ reversal curse（反转事实问答）真的缓解了吗？few-shot 的上下文学习能力会不会因为去掉因果掩码而退化？任意顺序生成快不快？这一课把这些问题做成一组可复现的冒烟测试。选 LLaDA-8B 是因为它是开源的、规模够大（2.3T token）、代表性强；对照组选 LLaMA3 8B，二者参数量同档，唯一系统性差异就是「扩散 vs 自回归」这条架构主线。整个实验只验证四件事：推理链路能跑通、reversal curse 对照、ICL 对比、任意顺序生成的可用性与速度。先说清楚一件事——这里的目标是**建立可执行的验收判据**，不是刷榜，所有断言都围绕「能不能、差多少」展开。

### 推理冒烟：从全 MASK 到完整句

LLaDA 的推理入口和自回归完全不同。自回归给一个前缀，模型一次吐一个 token；LLaDA 给的是一条带 [MASK] 的序列（生成任务里就是全 [MASK]，长度预先给定），模型用双向注意力反复预测被掩位置，每步填回一部分，迭代若干步后得到完整句。核心接口通常是 `generate` 加一个 `steps` 参数（去噪步数）和一个采样策略（每步填多少、填哪些）。冒烟的第一目标是跑通这条链：加载 8B 模型（BF16 约 16GB 显存，单张 24GB 卡可装下）、喂一条测试句、设 steps 等于 32、吐出通顺文本。若显存不足，用 4bit 量化（约 5GB）也能验证链路，只是速度变慢。

:::deep

### reversal curse 为什么会缓解

reversal curse 指自回归模型学会「A 叫 B」之后，反过来问「B 叫谁」却答不出。根因是训练顺序：AR 只在「A 在前、B 在后」的方向上建立条件概率 p(B 给定 A)，反向 p(A 给定 B) 从未被直接优化，模型也看不到反向的共现。LLaDA 的双向去噪从机制上拆掉了这个枷锁：训练时任意位置被掩，模型要利用**左右两侧**上下文预测它，于是「A」和「B」互为上下文、双向关联都被优化。问「B 叫谁」时，把「B」放在已知位置、把答案位置设为 [MASK]，模型能直接看到「B」并预测「A」。这不是说 LLaDA 永远不犯错，而是说它**不再系统性地受训练方向支配**。实测要设计成对称问答对：正向「张三的父亲是李四，张三的父亲是谁」与反向「张三的父亲是李四，李四的孩子是谁」，比较两模型在正反方向的准确率差。

:::

```python
# 第二段：纯 Python 可跑判据（验证测试设计，不依赖模型权重）
def reversal_gap(forward_ok, backward_ok):
    """反转差距：正向对 vs 反向对的准确率落差，越小说明 curse 越轻。"""
    return sum(forward_ok) / len(forward_ok) - sum(backward_ok) / len(backward_ok)

# 8 组人造反转问答对（1=答对）。AR 常见形态：正向满、反向掉；扩散应更均衡。
ar_fwd = [1, 1, 1, 1, 1, 1, 1, 1]
ar_bwd = [1, 0, 1, 0, 1, 1, 0, 1]
llada_fwd = [1, 1, 1, 1, 1, 1, 1, 0]
llada_bwd = [1, 1, 1, 0, 1, 1, 1, 0]
gap_ar = reversal_gap(ar_fwd, ar_bwd)
gap_llada = reversal_gap(llada_fwd, llada_bwd)
print(f"AR 反转差距={gap_ar:.2f}  LLaDA 反转差距={gap_llada:.2f}")
assert gap_ar > 0.25 and gap_llada < 0.15, "LLaDA 的反转差距应明显小于 AR"

def infill_check(pos, filled):
    """任意顺序：检查指定位置能否被填回且非空。"""
    return all(t not in ("<unk>", "") for t in filled) and pos in ("head", "mid", "tail")

for pos in ("head", "mid", "tail"):
    assert infill_check(pos, ["张", "三"]), f"{pos} 位置填回失败"
print("任意位置（head/mid/tail）填回断言通过")
```

第二段先把「反转差距」这个可量化判据跑通：AR 的正反向准确率落差应明显大于 LLaDA（在这里的示意数据里是 0.38 对 0.13），这就是 reversal curse 缓解的可操作定义。真实测试把 `ar_fwd/ar_bwd` 换成两模型的实际答题对错即可。第三段对 head/mid/tail 三个位置都做填回断言，验证「任意顺序」不是只在默认左到右成立。

### 与 LLaMA3 8B 的 ICL 对比：控制变量

few-shot 对比的难点在于变量太多，稍不留神就把「提示差异」误当成「架构差异」。正确的做法是固定四样东西：同一 few-shot 样例集（例子内容与顺序都一致）、同一提示模板、同一解码温度与 top-p、同一任务与评分口径；唯一变量是模型（LLaDA-8B 对 LLaMA3 8B）。在此基础上比较两类结果：一是 few-shot 相对 zero-shot 的**增益**（ICL 是否在扩散上同样生效），二是两模型在相同 few-shot 下的绝对准确率。要注意 LLaDA 的去噪步数是个额外旋钮，步数太少会欠生成、太多会拖慢速度，对比时应固定一个合理步数（如 32）并单独报告步数敏感性。若 LLaDA 的 ICL 增益明显低于 LLaMA3，别急着下「扩散不会 ICL」的结论——先检查 few-shot 样例是否被双向注意力「看得太透」而需调整模板，这本身是双向模型 ICL 的调参特点。

### 任意顺序生成的可用性与速度判据

「任意顺序」必须主动测，不能默认。设计三组提示：只在句首留 [MASK]（head）、只在句中留 [MASK]（mid）、只在句尾留 [MASK]（tail），各跑若干样本，记录填回通顺率与正确率。可用性判据是三组都显著高于随机基线、且彼此差距在可接受范围；若 mid 明显差于 head/tail，说明双向上下文利用不充分，要回查去噪步数与填回策略。速度判据要诚实：扩散生成整句要跑数十步双向前向，而 LLaMA3 8B 每步只算一个 token，单句延迟上扩散常处劣势；但扩散能**一次性并行填多个位置**，在「只改中间一小段」的编辑场景反而更快（不用重算后缀，L54 展开）。所以速度结论要分场景：整句从头生成看 AR 延迟优势，局部填充/编辑看扩散的并行优势。把这两种场景分开报，才不会得出「扩散一定慢」的粗糙结论。

```python
def forward_calls(mode, steps, gen_len):
    """网络前向调用次数：AR 逐 token；扩散每步整句一次（可并行填多位）。"""
    return gen_len if mode == "ar" else steps

calls_ar = forward_calls("ar", steps=0, gen_len=128)
calls_full = forward_calls("diff", steps=32, gen_len=128)
calls_edit = forward_calls("diff", steps=8, gen_len=128)
print(f"整句 128 token：AR 前向 {calls_ar} 次，扩散 32 步 {calls_full} 次")
print(f"局部编辑（8 步）：扩散仅 {calls_edit} 次前向")
assert calls_edit < calls_full < calls_ar, "扩散用更少的大步前向替代 AR 的逐 token 前向；编辑时步数更少"
# 判读：整句生成 AR 延迟占优；只改一小段时扩散步数可压到个位数，反而更快
```

### 一组可量化的验收清单

把这一课的四件事变成可勾选的验收项，跑完实验对着打勾：

- [ ] 冒烟：LLaDA-8B 能加载并吐出通顺文本，steps=32 时无 OOM（4bit 量化兜底）。
- [ ] Reversal：正向对的准确率不低于反向对太多，`gap_llada` 明显小于 `gap_ar`（示意阈值 0.15 对 0.25）。
- [ ] ICL：few-shot 相对 zero-shot 有正向增益，且与 LLaMA3 8B 在固定变量下可比。
- [ ] 任意顺序：head/mid/tail 三组填回都通过通顺率与正确率判据。
- [ ] 速度：分别报告「整句生成延迟」与「局部填充延迟」，不混为一谈。

五条全过才算「跑通 LLaDA-8B」，缺 reversal 对照或速度分场景，实验就不完整。

### 收束：这一课验的是「可用性」不是「刷榜」

LLaDA-8B 的价值不在于单项分数压过 LLaMA3，而在于它证明了扩散 LLM 在 8B 规模、2.3T token 上能**可用**：reversal curse 缓解、ICL 生效、任意顺序生成成立。测的时候牢牢抓住「控制变量」和「分场景报速度」两条纪律——前者保证差异归因到架构，后者避免用整句生成的尺子去量局部编辑的优势。带着这些判据，L51 看 LLaDA 谱系怎么把这套能力做成产品矩阵，L54 把局部编辑做成可直接用的工具。

:::
