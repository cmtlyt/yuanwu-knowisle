### 低秩假设：全参更新真的需要满秩吗

L83 指出全参微调要更新 d_out×d_in 个权重，7B 模型要动上百亿参数。LoRA 的出发点是一个经验观察：**下游微调所需的权重改变量 ΔW，其「内在秩」很低**。也就是说，虽然 ΔW 是一个满尺寸矩阵，但它真正有意义的变化集中在一个很低的维数子空间里。既然如此，就不必用满秩矩阵去表示它，用一个秩为 r（r 远小于 d）的分解就够。这就是低秩适应（Low-Rank Adaptation）的名字来源，也是它能省约 10⁴ 倍参数的根本原因。

L84 把 LoRA 放在 PEFT 谱系的终点：它既像 Adapters 那样只训少量参数，又能像全参那样 merge 回权重、零推理延迟。这一课把它的机制推到底——从 W=W₀+(α/r)BA 的推导，到 r 与 α 各自的角色，再到与全参更新的逐项对照。

### 机制推导：W = W₀ + (α/r)·B·A

对一个线性层 W₀ ∈ R^{d_out×d_in}，前向是 h = W₀x。全参微调直接改 W₀；LoRA 冻结 W₀，改为：

**h = W₀x + (α/r)·B·A·x**

其中 A ∈ R^{r×d_in}（把输入降到 r 维）、B ∈ R^{d_out×r}（升回 d_out 维），于是 BA ∈ R^{d_out×d_in} 与 W₀ 同形状，可以直接相加。训练时只更新 A、B，W₀ 全程冻结。初始化有个不对称的细节：**B 初始化为全零、A 用随机高斯**，这样初始 ΔW = BA = 0，模型一开始就等价于原基座，训练从「无损起点」开始，不会一上来就扰动预训练能力。

关键在参数量：全参要训 d_out×d_in 个；LoRA 只训 B 的 d_out×r 加 A 的 r×d_in，即 r·(d_out+d_in)。以 d_in=d_out=4096、r=8 为例，前者约 16.8M，后者约 65K，单层的可训参数少了约 256 倍。跨几十层、再算上优化器状态（L83 的 16 字节/参数也只对可训参数收），整体可训参数量级达到全参的约 10⁴ 分之一。

```python
d_in = d_out = 4096
for r in (4, 8, 16, 64):
    full = d_out * d_in
    lora = r * (d_out + d_in)
    print(f"r={r:2d}: 全参 {full/1e6:6.2f}M vs LoRA {lora/1e3:6.1f}K，省 {full/lora:5.0f}×")
# r=8: 全参 16.78M vs LoRA 65.5K，省 256×
assert d_out * d_in / (8 * (d_out + d_in)) > 200
print("单层省 256×；叠加 '基座不存优化器状态' 后，整体训练显存可降约 10⁴ 量级")
```

### 秩 r 与缩放 α：两个旋钮各自的活

**秩 r** 决定低秩子空间的大小，是表达力与代价的主旋钮。r 越大，BA 能表示的变化越丰富，更接近全参，但可训参数与显存随 r 线性增长，且过拟合风险上升。经验取值：简单分类/风格任务 r=4 到 8 够用，复杂指令或对领域迁移要求高时上到 16 到 64。L84 的量级表里已经看到，挂全线性层 + r=8 的可训参数就比只挂 Wq/Wv 多好几倍——r 与目标模块是乘性叠加的。

**缩放 α/r** 是个归一化系数。若没有它，增大 r 会让 BA 的尺度跟着涨，训练动态随 r 漂移；除以 r 后，增量尺度与秩大致解耦，改 r 时不必从头重调学习率。实践中两种用法：一是固定比例 α = 2r（于是 α/r = 2 为常数），二是把 α 直接当超参搜。要记住 α/r 与学习率会耦合——调大 α/r 等价于放大LoRA 分支的有效学习率，这两者不要同时乱动。

:::deep

### 为什么 B 零初始化、A 高斯初始化

这是 LoRA 最容易被忽略、却最关键的实现细节。若把 A、B 都随机初始化，初始 ΔW = BA 是一个随机满秩矩阵，会在训练第一步就给冻结的基座叠加一个随机扰动，破坏预训练表征，训练可能从一开始就偏掉。正确做法是 **B=0、A~N(0,σ²)**：由于 B 全零，初始 BA=0，ΔW 严格为零，模型与基座完全等价；反向传播时 B 的梯度不为零（因为它乘的 A 有值），于是 B 从 0 开始被「解锁」，ΔW 逐步长出来。这个「零起点」保证了 LoRA 不损伤基座，是它能稳定训练的前提。L89 的 LoraConfig 实现里会看到与之对应的初始化参数。

:::

### 对照全参更新：逐项拆解

把 LoRA 与全参更新放在一起，差异落在四个维度：

- **可训参数**：全参 N 个；LoRA 约 0.01% 到 0.5% N（取决于 r 与目标模块）。这是 10⁴ 量级差距的来源。
- **优化器状态**：全参要给 N 个参数准备 16 字节/参数（L83）；LoRA 只给可训的 BA 准备，优化器显存同样塌缩几个数量级。
- **灾难性遗忘**：全参直接改 W₀；LoRA 冻结 W₀，增量可视为旁路，对通用能力的扰动小得多（L83 的遗忘问题被结构性缓解）。
- **推理开销**：全参本来就是新权重，无额外开销；LoRA 训练时并行算 W₀x + BAx 有额外计算，但**部署前可 merge**——把 (α/r)BA 加回 W₀ 得 W' = W₀ + (α/r)BA，之后就是单个 W'x，零额外延迟。这是 LoRA 胜过 Adapters（串行）与 Prefix（占上下文）的决定性优势（L84）。

```python
import numpy as np
rng = np.random.default_rng(0)
d_in, d_out, r, alpha = 8, 8, 2, 4
W0 = rng.normal(size=(d_out, d_in))
A  = rng.normal(size=(r, d_in)) * 0.1
B  = np.zeros((d_out, r))                            # B 零初始化：初始 ΔW = 0
x  = rng.normal(size=d_in)

def forward_parallel(W0, B, A, x, alpha, r):
    return W0 @ x + (alpha / r) * (B @ A) @ x

assert np.allclose(forward_parallel(W0, B, A, x, alpha, r), W0 @ x), "B=0 时增量必须为零"
B[:] = rng.normal(size=(d_out, r)) * 0.1             # 训练后 B 被解锁
W_merged = W0 + (alpha / r) * (B @ A)               # merge：单矩阵
assert np.allclose(forward_parallel(W0, B, A, x, alpha, r), W_merged @ x), "merge 前后输出必须一致"
print("并行前向 == merge 后单矩阵前向；增量 0 -> 训练 -> merge，全程可验证")
```

### 表达力的边界：LoRA 不是万能

低秩假设在多数下游任务上成立，但有边界。若任务要求权重改变量真的接近满秩（例如领域与预训练差异极大、需要重排底层特征），r 必须开得很大，此时省参数的优势被削弱，逼近全参成本——这正是 L83「何时才该全参」判据里「领域差异极大」那一条的量化版本。另一个边界是**多层累积**：单层低秩没问题，但几十层低秩增量叠加的表达力弱于每层满秩，复杂推理任务上可能露出差距。缓解手段包括增大 r、挂更多目标模块、或叠加 DoRA（L87 把方向/幅度拆开进一步增强）。理解边界，才能既用 LoRA 又不迷信 LoRA。

:::tip

### 把 LoRA 记成「可合并的低秩旁路」

一句话锁定机制：LoRA 冻结 W₀，在旁边挂一条低秩旁路 BA，前向为 W₀x + (α/r)BAx；只训 A、B 省约 10⁴ 倍参数；B 零初始化保证零起点；部署前把增量 merge 回 W₀，推理零延迟。r 管表达力与代价，α/r 管尺度与解耦。带着这个模型读 L86 的 QLoRA（把 W₀ 换成 4bit）、L87 的 DoRA（把 BA 只用在方向）、L89 的端到端实现，都是在同一个旁路上做文章。

:::
