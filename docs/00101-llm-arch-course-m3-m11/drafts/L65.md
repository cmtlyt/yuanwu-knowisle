### 通用 MoE 的两个老问题

L30 讲过，MoE 把 FFN 换成一组专家，每个 token 只激活 top-k 个，从而把「总参数」与「每 token 计算量」解耦。但经典 MoE 有两个长期毛病。一是**知识混杂**：专家数量有限（如 8 或 16 个），每个专家都被迫学会非常杂的知识，难以专注。二是**知识冗余**：像语法、常用搭配这类公共知识，会在多个专家里各存一份，浪费参数容量。结果就是「专家不小、但每个都不精，还互相重复」。DeepSeekMoE（arXiv:2401.04088）针对这两点各给了一招，V3 又把负载均衡一并改造。

### 第一招：细粒度专家细分

细粒度细分的做法是把原来的 N 个专家，每个切成 m 个更小的子专家，于是专家总数从 N 变成 m·N；同时把每 token 激活的专家数按比例提高（从 top-k 变成 top-m·k）。单个子专家更小、更专，而 token 可以从更多子专家里挑选组合，表达自由度大幅上升。用组合数看最直观：原来从 16 个专家里选 top-2，只有 C(16, 2) = 120 种组合；切成 m = 4 后从 64 个子专家里选 top-8，组合数是 C(64, 8)，量级到数十亿。组合空间的爆炸意味着不同 token 能走截然不同的精细路径，知识被切得更碎、更可组合。关键是：虽然激活的专家个数变多，但每个更小，**激活的总容量可以保持不变**，所以计算量不因细分而暴涨。

:::deep

### 第二招：共享专家隔离

细粒度解决了「专家不够专」，但公共知识往哪放？如果让所有路由专家都学一遍常识，冗余又在细分后 replicated 得更厉害。DeepSeekMoE 的答案是**隔离出一个（或少数几个）共享专家**：它对每个 token 都常驻激活，专门承载公共知识；其余路由专家则被「解放」出来，只专注各自的差异化知识。这样公共知识只存一份，路由专家不必重复携带，参数容量被用在真正有区分度的模式上。共享专家与路由专家是正交的两条通道：前者稳定、常开、管共性；后者动态、按 token 选、管个性。V3 沿用这套结构，采用 1 个共享专家加 256 个路由专家、每 token 激活 8 个路由专家，总参数 671B、每 token 激活 37B（A 级，论文口径）——细粒度与共享隔离一起，让 37B 的激活参数撑起 671B 总容量的表达力。

:::

### 第三招：无辅助损失的负载均衡

经典 MoE 用辅助损失（auxiliary loss）惩罚负载不均，但辅助损失会往主任务梯度里掺噪声，可能伤模型质量。V3 的 aux-loss-free 做法更巧：给每个专家一个可学习的偏置 b_i。路由时，把 b_i 加到亲和度上做 top-k 决策；但真正计算输出门控权重时，**只用原始亲和度、不加偏置**。于是 b_i 只影响「选谁」，不影响「选了之后权重多大」。每步按专家负载更新偏置：负载高于目标就减小 b_i（少被选中），低于目标就增大 b_i（多被选中），更新量是一个小步长 γ。这样负载被稳稳拉平，而主任务的梯度不被辅助损失污染，质量与兼得。

### 可跑代码：细分带来的组合爆炸

用组合数量化「细分让表达自由度暴涨」，并断言细分后组合数远大于原来。

```python
import math

def combos(n_experts, top_k):
    return math.comb(n_experts, top_k)

# 经典：16 专家 top-2；细分 m=4：64 子专家 top-8
base = combos(16, 2)
fine = combos(64, 8)
print(f"经典 16 选 2：{base} 种组合")
print(f"细分 64 选 8：{fine} 种组合")
print(f"组合自由度提升约 {fine/base:.0f} 倍")
assert fine > base * 1000, "细粒度细分应带来组合数数量级提升"
# 注意：激活子专家数变多，但每个更小，总激活容量可保持不变
```

### 可跑代码：共享专家承载公共知识

用一个 toy 矩阵演示「公共知识只存一份」：有共享专家时，公共模式只占一个专家；无共享时，多个路由专家各自复制一份，冗余容量被浪费。

```python
import numpy as np

rng = np.random.default_rng(1)
common = rng.normal(size=8)                 # 公共知识模式
specific = [rng.normal(size=8) for _ in range(4)]  # 各路由专家的差异知识

def capacity_without_shared(n_route):
    # 每个路由专家都得夹带一份公共知识 → 公共知识被复制 n_route 份
    return n_route, [common + 0.3 * s for s in specific[:n_route]]

def capacity_with_shared(n_route):
    # 公共知识只放共享专家一份；路由专家只放差异知识
    return n_route + 1, [common] + specific[:n_route]

n_route = 4
n_no, experts_no = capacity_without_shared(n_route)
n_yes, experts_yes = capacity_with_shared(n_route)
print(f"无共享：{n_no} 个专家都在学公共+差异，公共知识复制 {n_route} 份")
print(f"有共享：{n_yes} 个专家，公共知识只存 1 份")
assert len(experts_yes) == n_route + 1
print("共享专家隔离把公共知识的存储从多份降到一份")
```

### 可跑代码：aux-loss-free 偏置更新

模拟 8 个专家的负载，按「过载降偏置、欠载升偏置」迭代，看负载方差随步数下降，验证均衡有效且不碰主任务梯度。

```python
import numpy as np

rng = np.random.default_rng(2)
n_expert = 8
bias = np.zeros(n_expert)          # b_i，只进路由决策
gamma = 0.05
target = 1.0 / n_expert
loads_log = []
for step in range(200):
    # 模拟 token 亲和度：人为让部分专家天然更热
    affinity = rng.normal(size=(256, n_expert)) + np.linspace(0, 0.5, n_expert)
    gate = affinity + bias                      # 路由决策：加偏置
    chosen = np.argmax(gate, axis=1)
    load = np.bincount(chosen, minlength=n_expert) / 256
    loads_log.append(load)
    bias += -gamma * np.sign(load - target)     # 过载降、欠载升
first_var = np.var(loads_log[0])
last_var = np.var(loads_log[-1])
print(f"负载方差：初始 {first_var:.5f} → 200 步后 {last_var:.5f}")
print(f"最终各专家负载：{np.round(loads_log[-1], 3)}")
assert last_var < first_var, "偏置更新应降低负载不均"
print("aux-loss-free 均衡生效，且不向主梯度注入辅助损失")
```

### 路由与专家容量的数值走查

把 V3 的专家配置算成一张容量账，理解「细粒度加共享」为什么不会让单步计算爆炸。取论文配置：1 个共享专家加 256 个路由专家，每 token 激活 8 个路由专家与 1 个共享专家，共 9 份专家计算。若把 256 个专家视为把原 FFN 切成 256 份细粒度单元，每份宽度约为原 FFN 的 1/256；激活 8 份加 1 份共享，合计容量约为「1 份原宽的共享通道 + 8 份很窄的路由份」。这正是细粒度设计的精髓：共享专家兜住公共计算，路由部分只花很小容量做差异化选择。用激活参数看总量，V3 的 37B 对 671B 约 5.5%（A 级），其中相当一部分花在常驻共享专家与注意力上。再对照 aux-loss-free 的偏置更新：步长 γ 若取 0.001 量级，200 步内累计调整约 0.2，足以把负载从明显倾斜拉平；γ 取太大会在专家之间来回震荡，取太小则收敛慢——这个旋钮与学习率一样，是需要实测的超参。另一条判据是看偏置是否只进路由：若把 b_i 乘进了输出门控，等于改变了专家输出的相对权重，模型质量会被偏置污染，这正是 aux-loss-free 最容易被写错的地方。

### 与通用 MoE 的差异对照

把差异钉成一张对照表，便于复述。通用 MoE：专家少而宽、top-k 固定、公共知识在各专家重复、靠辅助损失压负载。DeepSeekMoE：专家多而细（细粒度细分）、有常驻共享专家隔离公共知识、路由只按动态亲和度选差异专家、靠专家偏置做 aux-loss-free 均衡。四处的共同目标都是「让有限的激活参数表达更多样的知识，同时不让负载塌缩」。这套结构从 V2 引入、V3 沿用并放大到 256 路由专家，是 DeepSeek 在 MoE 侧最鲜明的标志。下一课 L66 转回训练目标，看 MTP 如何用多 token 预测把训练信号变密。

:::tip

### 三招各治一个病

**细粒度细分**治「专家不够专」——切小专家、放大组合空间。**共享专家隔离**治「公共知识重复」——常驻一份、路由专家只管差异。**aux-loss-free** 治「辅助损失伤质量」——偏置只调路由、不进门控，负载照样平。V3 把它们开到 1 共享 + 256 路由 + top-8，撑起 671B 总参、37B 激活（A 级）。记住「细分、隔离、偏置」六个字，就把 DeepSeekMoE 与通用 MoE 的区别讲清了。

:::
