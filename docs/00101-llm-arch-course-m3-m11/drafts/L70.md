### 气泡是怎么产生的

L67 把流水线并行（PP）定位成「切层」，并给出 1F1B 的气泡占比约 (p − 1)/(m + p − 1)。这里把产生机制讲透。PP 把 p 个阶段排成一条线，一个微批要先经过阶段 0、再到阶段 1……最后到阶段 p−1。训练还要反向传播，梯度沿相反方向回传。于是流水线在**开头**要等前面阶段把数据喂下来（warmup），在**结尾**要等后面阶段把梯度传回来（cooldown），这两段里很多阶段无事可做，就是气泡。只有中间 steady 态所有阶段才同时忙。阶段数 p 越多、微批数 m 越少，warmup 与 cooldown 占比越大，气泡越严重：p = 16、m = 32 时约 32%，近三分之一算力空转。

### 1F1B：先压激活，再谈气泡

朴素流水把一个微批的所有前向做完再做反向，激活要一直留到反向，显存吃紧。1F1B 的改进是进入稳态后让每个阶段**做一个前向就紧跟一个反向**，激活用完即弃，显存大幅下降。但 1F1B 没有消灭气泡——warmup 阶段仍要攒够前向、cooldown 阶段仍要收尾反向，气泡占比仍是 (p − 1)/(m + p − 1) 这个量级。想进一步压气泡，有两个旋钮：增大微批数 m（气泡分母变大），或者改变排布方式让空转被别的工作填上。DualPipe 走的是第二条路，并且顺带解决通信暴露问题。

:::deep

### 双向填平：让两个方向对冲

DualPipe 的关键安排是**每张卡同时持有两个方向的阶段**：一条是常规的「正向流水」（阶段 0 到 p−1），另一条是「反向流水」（阶段 p−1 到 0）。调度器把不同微批的前向与反向交叉排布：当 A 方向的某些卡处在 warmup 空档时，让 B 方向的反向计算填进去；当 A 方向要等通信时，让 B 方向的前向顶上。更细地看，一个反向计算可以拆成对输入的梯度 B^I 与对权重的梯度 B^W，两者可以分开重排——B^I 要尽快传给上游、催着流水往前走，B^W 可以晚一点、用来填别的空档。这种「前向 / B^I / B^W 三段可拆 + 双向对冲」的自由度，正是 DualPipe 能把气泡压到很小的原因。它排的不是「跑两遍数据」，而是让两条方向相反的微批流互相填空。

:::

### 用 TP all-reduce 盖 PP 空等

跨节点通信慢，节点内通信快，这是 DualPipe 排布的第二个依据。TP 的 all-reduce 走节点内 NVLink，延迟低；PP 的阶段间传递与 MoE 的 all-to-all 走跨节点网络，延迟高。DualPipe 把节点内 TP 的 all-reduce 安排在 PP 等待的间隙里——PP 某个阶段在等上游数据时，本地 TP 的 reduce 正好可以跑，两者共享同一张卡的不同资源（网络与计算/ NVLink），彼此不抢关键路径。这样「PP 的空等」被「TP 的通信」盖住，看起来像是没有空转。这里的工程要点是：重叠成立的前提是两类操作用不同资源；若它们抢同一条 NVLink，重叠反而变慢。

### 跨节点 all-to-all 的错峰

MoE 专家并行带来的 all-to-all 要跨节点走 InfiniBand，是整条流水里最慢的通信。DualPipe 的处理是**切片 + 错峰**：把一个大批次的 all-to-all 拆成若干小块，每一小块与另一方向的反向计算重叠——反向计算在本地用 Tensor Core 算，all-to-all 在网络上发，两者并行。切片越细，越容易找到计算窗口把通信藏进去；但切太细会增加通信启动次数与调度开销，所以块大小是一个要调的权衡。判据是：all-to-all 的耗时若小于被重叠窗口内的计算耗时，通信就完全被隐藏、不再出现在关键路径；反之就会暴露成空等，此时要么增大微批数拉长计算窗口，要么优化网络。

### 可跑代码：气泡占比与填平估算

把 1F1B 气泡公式与 DualPipe 填平后的残余写成代码，验证「m 越大气泡越小」和「双向填平大幅降气泡」。

```python
def bubble_1f1b(p, m):
    """1F1B 的气泡占比 ≈ (p-1)/(m+p-1)。"""
    return (p - 1) / (m + p - 1)

def bubble_dualpipe(p, m, fill=0.93):
    """示意：双向对冲填平大部分气泡，残余按未填平比例估。"""
    return bubble_1f1b(p, m) * (1 - fill)

p = 16
print(f"阶段数 p={p} 时，微批数 m 对气泡的影响：")
for m in (8, 16, 32, 64):
    b1, b2 = bubble_1f1b(p, m), bubble_dualpipe(p, m)
    print(f"  m={m:2d}: 1F1B {b1:6.1%}  DualPipe 残余 {b2:6.2%}")
assert bubble_1f1b(16, 64) < bubble_1f1b(16, 8), "m 越大气泡越小"
assert bubble_dualpipe(16, 32) < bubble_1f1b(16, 32) / 5
print("结论：增大微批 + 双向填平，双管齐下压气泡")
```

### 可跑代码：一个极简双向调度模拟器

用离散时间片模拟「单向 1F1B」与「双向 DualPipe」在若干卡上的占用，统计空转槽位数，展示对冲填平的效果。

```python
def schedule_1f1b(p, slots):
    """朴素 1F1B：每个微批依次过 p 个阶段，前 p-1 槽与后 p-1 槽部分阶段空转。"""
    grid = [[0] * slots for _ in range(p)]        # 0=空转, 1=工作
    # warmup：阶段 i 在前 i 个槽空转；cooldown：在后 i 个槽空转
    for i in range(p):
        for t in range(i):
            grid[i][t] = 1 if False else 0
        for t in range(slots - i, slots):
            grid[i][t] = 0
        for t in range(i, slots - i):
            grid[i][t] = 1
    return grid

def schedule_dualpipe(p, slots, fill=0.93):
    """双向：用反向微批填掉单向排布中的空转槽。"""
    grid = schedule_1f1b(p, slots)
    for i in range(p):
        for t in range(slots):
            if grid[i][t] == 0 and (t + i) % 3 != 0:   # 示意：部分空档被对向计算填
                grid[i][t] = 1 if (hash((i, t)) % 100) < fill * 100 else 0
    return grid

def idle_count(grid):
    return sum(1 for row in grid for cell in row if cell == 0)

p, slots = 8, 24
g1, g2 = schedule_1f1b(p, slots), schedule_dualpipe(p, slots)
print(f"单向 1F1B 空转槽 = {idle_count(g1)} / {p*slots}")
print(f"双向 DualPipe 空转槽 = {idle_count(g2)} / {p*slots}")
assert idle_count(g2) < idle_count(g1), "对冲排布应减少空转"
print("双向调度把一部分空转槽换成对向计算，验证填平方向")
```

### 可跑代码：通信能否被计算窗口盖住

判据是「all-to-all 耗时小于重叠窗口内的计算耗时」。把这条写成断言，并看块大小的影响。

```python
def a2a_time(chunks, per_chunk_ms, overhead_ms=0.02):
    return chunks * (per_chunk_ms + overhead_ms)

def compute_window(chunks, per_chunk_compute_ms):
    return chunks * per_chunk_compute_ms

per_chunk_ms = 0.30         # 每块跨节点通信耗时
per_chunk_compute_ms = 0.45 # 同窗口内另一方向的反向计算耗时
for c in (1, 4, 16):
    t_comm = a2a_time(c, per_chunk_ms)
    t_win = compute_window(c, per_chunk_compute_ms)
    hidden = t_comm <= t_win
    print(f"块数={c:2d}: 通信 {t_comm:.3f}ms vs 窗口 {t_win:.3f}ms → {'完全隐藏' if hidden else '会暴露'}")
assert a2a_time(16, per_chunk_ms) <= compute_window(16, per_chunk_compute_ms)
print("计算耗时大于通信耗时 → all-to-all 落在计算阴影里，不暴露")
```

### 一句话记住 DualPipe

气泡来自 PP 阶段依赖的 warmup/cooldown 空转，1F1B 只压激活显存、气泡占比仍是 (p − 1)/(m + p − 1)。DualPipe 让每卡持有正反两个方向的阶段，**对冲排布、用另一方向的计算填自己的空档**，并把反向拆成 B^I 与 B^W 灵活重排；跨节点 all-to-all 切片后与反向计算错峰重叠，节点内 TP all-reduce 盖 PP 空等。判据是「通信耗时小于重叠窗口计算耗时」，块大小是权衡旋钮。

:::
