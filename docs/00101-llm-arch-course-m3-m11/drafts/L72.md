### 从 M1 的 next-token 损失走进 M8

M1 讲 transformer 结构时，我们第一次写出过 next-token 的损失：把一段文本切成 token 序列，让模型看前面的 token 猜下一个。那时重点是「这个损失长什么样、怎么回传」。M8 是整个预训练模块的起点，要把这件看似简单的事拆到数学根上：为什么一个「猜下一个词」的目标，能撑起上千亿参数、上万亿 token 的训练，并且训练完之后模型恰好就会「续写文本」。答案在于自回归分解把语言建模变成一个**纯粹的概率估计问题**，而 decoder-only 架构让训练目标与推理行为完全同构。这一课先把目标函数讲透，后面 L73 的数据配比、L75 的 scaling law、L78 的从零训练，全都挂在这个目标之上。

### 自回归联合概率分解

设一段 token 序列为 x_1 到 x_T。语言模型要学的是它的联合概率 P(x_1, ..., x_T)。直接对整段序列建模是不可能穷举的——词表动辄十几万，长度上千，组合爆炸。自回归模型用链式法则把它拆成条件概率的连乘：

P(x) = ∏_{i=1..T} P(x_i | x_1, ..., x_{i-1})

每一项 P(x_i | 前缀) 都只预测一个 token，词表规模虽大但可 softmax 归一化。这就是「next-token 目标」的数学本体：**把对整段文本的建模，化为在每一个位置上做一个词表大小的多分类**。链式法则是恒等式，不引入近似；所以自回归分解在表达力上没有损失，唯一的信息限制来自「第 i 位只能看到前缀」这个因果约束——但语言本来就是从左到右生成的，这个约束恰恰符合生成过程。

训练时我们用负对数似然（NLL）把连乘变成连加，数值上更稳定：

L = - (1/T) · Σ_{i=1..T} log P(x_i | x_<i)

模型对每个位置输出一个词表上的 logits，经 softmax 得到分布，取真实下一个 token 的对数概率。这个 L 就是**平均 next-token 交叉熵**：每个位置都是一次以真实 token 为标签的交叉熵分类，整段取平均。把 P 写成 exp(logits) 的归一化形式，log P(x_i) 等于「该 token 的 logit 减去所有 logit 的 log-sum-exp」，这正是 F.cross_entropy 在内部做的事。

### decoder-only 为何统一

早期语言模型并不只有一种骨架：encoder-only（BERT 式，双向看全句）、encoder-decoder（T5/BART 式，先编码再解码）、decoder-only（GPT 式，只看前缀）三者并存。为什么今天主流大模型几乎全是 decoder-only？根因是**目标与行为同构**。

encoder-only 用掩码语言建模：随机遮住一些位置，让模型利用左右双向上下文猜被遮的词。它训练时看得到「未来」，但生成时未来还不存在，于是训练和生成天然错位——它擅长理解类任务（分类、检索），不擅长开放续写。encoder-decoder 把输入编码成表示再自回归解码，虽能生成，但目标是「给定输入序列生成输出序列」的条件生成，训练与推理要维护两段结构，参数与计算都分散在两块。

decoder-only 只做一件事：因果掩码下的 next-token 预测。第 i 个位置通过下三角掩码只能看到 x_1 到 x_i，因此它的输出恰好就是 P(x_{i+1} | x_1..x_i) 所需要的分布。训练时如此，推理时逐 token 采样也如此：**你优化的那个函数，就是你要执行的那个过程**。这种同构带来三个工程红利：一是结构单一，从 1 层堆到 100 层不用改范式；二是训练能一次前向并行算完所有位置的损失（下面 teacher forcing 会讲），算力利用率高；三是下游所有任务——分类、问答、推理、续写——都能改写成「给一段提示续写 token」，统一成同一个接口。

:::deep

### 因果掩码如何「免费」实现条件分解

decoder-only 的精髓在于：我们不需要为每个位置单独跑一次前向，只要一个下三角掩码，就能在一次矩阵乘里同时算出所有位置的 P(x_i | x_<i)。注意力分数矩阵 A 中，第 i 行第 j 列代表第 i 个查询对第 j 个键的关注；当 j > i 时把它置为负无穷，softmax 后权重为零，第 i 位就无法「偷看」未来。于是同一份输入序列前向前，每个位置的 hidden state 都只编码了它的前缀信息，接一个线性层映射到词表就得到该位的条件分布。

这意味着一次长度为 T 的前向，等价于 T 次「看前缀猜下一个」的操作叠加，训练并行度极高。相比之下，若严格按自回归一步步算，要跑 T 次前向、每次只算一个新 token，训练和生成一样慢——teacher forcing 的作用正是打破这个串行。

:::

### 训练目标与「预测下一 token」的数学：teacher forcing 与 shift

要把「猜下一个」写成可并行的张量运算，关键是 **teacher forcing**：训练时第 i 位的条件不是模型上一步自己采样的 token，而是数据里真实的 x_i。这样每个位置的条件都是「干净的真实前缀」，不累积采样误差，而且整段能并行。

落实到代码，就是一次错位对齐：模型对位置 i 的输出 logit 用来预测位置 i+1 的真实 token。写成切片形式：logits 取 `[:, :-1, :]`（去掉最后一个位置，因为它没有「下一个」可预测），labels 取 `[:, 1:]`（去掉第一个位置，因为它没有前缀用于自回归预测起点）。两者形状相同，逐位置做交叉熵：

loss = cross_entropy(logits[:, :-1, :], labels[:, 1:])

下面用一段可跑代码把这个对齐和损失算清楚，并打印出具体数字。

```python
import torch
import torch.nn.functional as F

# 一个极小的「模型」：直接把可学习 logits 当作输出，演示 shift 对齐
torch.manual_seed(0)
T, V = 6, 11                       # 序列长 6，词表 11
labels = torch.randint(0, V, (1, T))   # 真实 token id
logits = torch.randn(1, T, V, requires_grad=True)  # 模型在每位的词表输出

# 关键：第 i 位预测第 i+1 位 —— shift 一位
shift_logits = logits[:, :-1, :].contiguous()  # [1,5,11] 位置 0..4 的输出
shift_labels = labels[:, 1:].contiguous()      # [1,5]   位置 1..5 的真实 token
loss = F.cross_entropy(shift_logits.view(-1, V), shift_labels.view(-1))
print("labels:", labels.tolist())
print("逐位置预测目标(应为 labels[1:]):", shift_labels.tolist())
print("next-token 平均交叉熵 loss =", round(loss.item(), 4))

# 手算校验：交叉熵 = -log softmax(logit)[correct]
probs = F.softmax(shift_logits, dim=-1)
p_correct = probs.gather(-1, shift_labels.unsqueeze(-1)).squeeze(-1)
manual = -torch.log(p_correct).mean()
print("手算交叉熵 =", round(manual.item(), 4))
assert abs(loss.item() - manual.item()) < 1e-5, "框架交叉熵与手算应一致"
```

这段把三件事钉死：一是 `[:, :-1]` 与 `[:, 1:]` 的错位关系，二是交叉熵就是「真实 token 对数概率的负值」，三是框架实现与手算一致。若把 shift 写反（比如用 logits[:, 1:] 对齐 labels[:, :-1]），模型会学成「根据后文猜前文」甚至「复制上一个 token」，loss 看起来也可能下降，但生成时完全错乱——这是实现 next-token 目标最常见的翻车点。

### 困惑度：把交叉熵翻译成「等效候选数」

平均交叉熵 L 是个对数尺度上的数，不够直观。工程上常报告困惑度（perplexity, PPL）：

PPL = exp(L)

它表示「模型在这段文本上，平均相当于在多少个等可能候选里做选择」。PPL 越低越好：理想情况下若模型对下一个 token 完全确定，PPL 接近 1；若在词表 V 里完全随机猜，PPL 接近 V。因为 exp 单调，L 降必然 PPL 降，两者可以互相换算，但**不能混为一谈**——L 是损失（自然对数单位的每 token 代价），PPL 是它的指数（等效分支数）。L75 讲 scaling law、L78 画 loss 曲线时，会交替用这两个量，务必清楚它们的换算关系。

```python
import math
# 一批 loss 到困惑度的换算自检
for L in (0.0, 0.69, 1.61, 3.0, 5.0):
    print(f"平均交叉熵 L={L:4.2f}  ->  困惑度 PPL=exp(L)={math.exp(L):8.2f}")
# L=0.69≈ln2 -> PPL≈2（相当于二选一）；L=ln(V) 时 PPL=V（完全随机猜词表）
assert abs(math.exp(math.log(2)) - 2) < 1e-9
```

### 工程判据与常见误区

把这一课的认知收成可执行的判据。第一，**目标唯一**：预训练阶段只有 next-token 交叉熵这一个监督信号，所有「能力」都是把这个损失压低的过程中副带出来的，不需要为下游任务另设损失。第二，**对齐正确**：任何训练脚本上线前，先用一个小 batch 断言 loss 在头几百步明显下降，且 shift 对齐的切片形状相等——否则极可能错位。第三，**困惑度与生成分开看**：PPL 是语言建模质量的代理指标，但低 PPL 不等于下游能力强（L81 会用能力探针专门论证这一点），它只说明模型更像训练分布。

一个常被误解的点是「 teacher forcing 训练和自回归生成不一致会不会有 bias 」。确实存在 exposure bias：训练时条件永远是真实前缀，生成时条件是自己采样的、可能带错的历史，二者分布不同。缓解手段（如 scheduled sampling）存在，但主流大模型在超大规模数据下直接接受这个偏差——因为模型足够强时自采样很少偏离真实分布，收益不足以抵消复杂度。作为课程主线，记住「训练与生成同构、用 teacher forcing 并行」即可，这是 decoder-only 统一范式的核心。

:::tip

### 一句话收束 next-token 目标

自回归把整段文本的联合概率拆成逐位置条件概率连乘，取负对数就是 next-token 交叉熵；decoder-only 用因果掩码让第 i 位只能看前缀，使「训练时优化的函数」与「生成时执行的过程」完全同构，且能一次前向并行算完所有位置的损失。shift 对齐（`logits[:, :-1]` 对 `labels[:, 1:]`）是把目标落到代码的关键一步，困惑度 PPL=exp(平均交叉熵) 是它的直观刻度。M8 后面所有内容——数据、算力、并行、从零训练、能力探针——都是围绕把这一个交叉熵压得更低、更聪明地展开。

:::
