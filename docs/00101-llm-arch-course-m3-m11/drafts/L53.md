### Dream 7B 的定位：站在 AR 肩膀上的扩散

前面几课讲的扩散 LLM（LLaDA、SEDD）有一个共同的现实问题：从零训练一个高质量扩散语言模型代价高昂——要从头学遍语言知识，还得额外学「掩码恢复」这件新目标。Dream 7B（arXiv:2508.15487）给出一条更聪明的路线：**从强自回归模型初始化，再转成扩散训练**。直觉是，自回归 checkpoint 已经把语言知识、世界知识、句法语义学到位了，扩散要学的其实主要是「双向去噪」这件新技能；与其从零学语言加学去噪，不如把语言知识直接继承过来，只补去噪这一课。这让扩散模型的训练起点更高、收敛更快、质量天花板也更高。Dream 7B 用这套方法做到 7B 规模，在通用知识基准 MMLU 上与强自回归模型 Qwen2.5-7B 打平，在需要全局规划的 Countdown 任务上还实现了反超。这一课拆开它的两大机制（AR 初始化 + CART 噪声重调度），并讲清「为什么规划任务上扩散会占优」。

### AR 初始化：把语言知识迁移进扩散骨干

AR 初始化的操作并不复杂：拿一个训练好的自回归 LLM 权重，作为扩散模型的初始化，然后把训练目标从「预测下一个 token」换成「预测被掩 token」（L49 的掩码扩散目标），继续训练。但为什么可行？关键在于 Transformer 骨干的**权重语义是共享的**：自回归学出的注意力头、FFN、词嵌入，编码的是语言与知识，而不是「因果掩码」本身。因果掩码只是注意力矩阵上的一个开关，去掉它、换成双向注意力，权重里学的知识仍然有效。所以把 AR 权重搬过来、去掉因果掩码、换训练目标，模型只需适应「双向上下文下去噪」这个新玩法，不必重学语言。工程上这一步的价值是**训练效率**：从强 AR 起步的扩散，往往用更少 token 就能追上甚至超过从零训的扩散。当然，初始化不是免费的——AR 权重带的是「左到右」的归纳偏置，转成双向需要一段适应期，若数据量不足可能残留单向习惯；这也是 CART 等机制要帮着解决的问题之一。

### CART 噪声重调度：按上下文难度分配去噪

CART（上下文自适应噪声重调度）是 Dream 的另一半核心机制。要理解它，先想清楚掩码扩散的痛点：标准做法对所有位置用**同一条噪声调度**——每个位置在同样时刻有同样的掩码概率。但真实句子里，不同位置的「难度」差别巨大：虚词、固定搭配 easy，专有名词、推理关键位 hard。统一调度会浪费：简单的位置被反复去噪（早就能确定），难的位置却没得到足够关注。CART 的思路是**让噪声水平随上下文自适应**：模型根据每个位置的上下文信号，判断它当前该处于什么噪声水平，难的位置保持较高噪声（多去噪几轮）、易的位置快速降噪（早点定下来）。这相当于把「去噪算力」按需分配到最需要的位置，而不是平均撒。结果是同样的采样预算下，质量更高；或者达到同样质量，需要的步数更少。这也让 Dream 天然具备「质量-速度可调」：调步数就是在调去噪算力的总预算。

:::deep

### 为什么规划任务（Countdown）上扩散会反超

Dream 在 Countdown（给几个数字，用四则运算凑出目标数）上反超自回归基线，这个现象很能说明扩散的结构优势。Countdown 这类任务的本质是**全局规划**：你要同时盯着所有数字、尝试多种组合、回溯调整，而不是顺着一条线往下写。自回归模型受困于因果顺序——它必须从第一个 token 开始线性展开推理，前面的中间步骤一旦写错，后面的推导都被带偏，而且它无法「回看并修改」已经生成的步骤。扩散的双向去噪则不一样：每一步它都能看到整条序列（包括尚未定下的所有位置），可以先在心里「全局布局」，再逐步把各位置填实；关键中间结果若不合理，可以在后续去噪中被修正，而不必像 AR 那样被已生成的 token 锁死。这种「先全局、后局部，且可反复修正」的工作方式，恰好契合规划任务的需求。要强调：这不是说扩散在所有推理任务上都赢，而是说**当任务需要全局一致性与可回溯修正时，双向去噪的结构比单向生成更对味**。选型时若你的场景重规划、重约束满足，这是扩散的一个真实加分项。

:::

### 可跑代码：CART 调度与质量-速度旋钮

把 CART 的「按难度分配噪声」和「步数旋钮」写成可跑脚本，看得见它相对统一调度省了什么。

```python
import numpy as np

def uniform_schedule(steps, n_pos):
    """统一调度：所有位置每步同样降噪。"""
    return np.tile(np.linspace(1, 0, steps + 1), (n_pos, 1))

def cart_schedule(steps, n_pos, difficulty):
    """CART：难度高的位置噪声降得慢（多占去噪步）。"""
    t = np.linspace(1, 0, steps + 1)
    sched = np.zeros((n_pos, steps + 1))
    for i, d in enumerate(difficulty):
        # 难度 d∈[0,1]：越大，曲线越靠后降到 0
        sched[i] = np.clip(t + d * 0.3 * np.sin(np.pi * t), 0, 1)
    return sched

difficulty = np.array([0.1, 0.8, 0.3, 0.9, 0.2])   # 5 个位置的难度
u = uniform_schedule(8, 5)
c = cart_schedule(8, 5, difficulty)
print("统一调度末步噪声:", np.round(u[:, -1], 2))
print("CART 调度末步噪声:", np.round(c[:, -1], 2))
assert np.all(u[:, -1] == 0), "统一调度末步应全为 0"
assert np.all(c[:, -1] >= 0), "CART 噪声须非负（难度高处降得慢）"
print("CART 对难位置（难度 0.8/0.9）保留更高噪声→分配更多去噪关注")
```

```python
def quality_vs_speed(steps, max_steps=64):
    """质量-速度旋钮：步数越多质量越高（这里用饱和曲线示意），速度越慢。"""
    quality = 1 - np.exp(-steps / 12)     # 边际递减的质量曲线
    speed = max_steps / steps             # 步数少则相对速度快
    return quality, speed

for steps in (4, 16, 64):
    q, s = quality_vs_speed(steps)
    print(f"步数={steps:2d}  质量≈{q:.2f}  相对速度≈{s:.1f}x")
q4, _ = quality_vs_speed(4); q64, _ = quality_vs_speed(64)
assert q4 < q64, "多步应提升质量（边际递减）"
```

第一段用难度数组驱动 CART 曲线，难位置（0.8/0.9）被保留更高噪声，意味着它们会在更多步里持续被去噪——这就是「按上下文难度分配算力」。第二段把步数旋钮画成「质量饱和、速度反比」的曲线：4 步快但质量约 0.28，64 步慢但质量约 0.99，中间步数是甜点。两段合起来说明 Dream 为什么能「质量-速度可调」而不重训。

### 任意顺序生成、infilling 与工程判据

Dream 延续了扩散家族的通用能力：任意顺序生成（不按左到右）、infilling（固定已知位、填目标位）、以及上面的质量-速度可调。这三项是同一枚硬币的三面——都源于「掩码位置可任意指定、去噪步数可调」。工程上落地 Dream 7B 时要盯三件事：第一，**步数标定**，在自己的任务上画一条「步数-质量-延迟」曲线，找到甜点步数（通常 16 至 64 之间），别照搬默认；第二，**AR 初始化的适配检查**，确认模型没有残留单向偏置（可用 L50 的 reversal 对称问答测）；第三，**规划类任务的针对性评估**，若你的场景是约束满足/路径规划，Dream 的双向全局优势才兑现，纯知识问答上它只是打平 Qwen2.5-7B，别为「打平」付扩散的多步代价。

:::tip

### 收束：Dream 的两把钥匙

Dream 7B = **AR 初始化（借知识、提起点）+ CART 噪声重调度（按难度分配算力）**。它用这两把钥匙做到 MMLU 打平 Qwen2.5-7B、Countdown 规划反超，并把「质量-速度可调」做成推理时旋钮（改步数即可）。记住规划反超的结构原因：双向去噪能「先全局布局、再局部填实、且可回溯修正」，这正对规划任务的胃口。带着这个认知，L54 把 infilling/约束生成做成可跑工具，L55 起进入 M6 把扩散放进五维矩阵做横向选型。

:::
