### 一张谱系地图：四代各解决什么

基础 LLaDA（8B、2.3T token 训练）证明了离散扩散能在 LLM 规模上跑通，但「能跑」和「好用」之间隔着几道工程关。后续几个分支各自补一道：LLaDA 1.5 补**指令对齐与稳定性**，让任意顺序生成在真实指令下可控；LLaDA-V 补**模态**，把图像/图文接进同一套掩码去噪框架；LLaDA-MoE 补**容量效率**，把 M3/M4 讲过的稀疏专家接进扩散骨干，让「总参大、激活参小」的 MoE 红利也惠及扩散；LLaDA 2.0 则是**规模化与能力升级**的新一代。四者不是互相推翻，而是共享「离散扩散 + 去因果双向 Transformer + 掩码去噪」同一范式，在能力维度上叠加。把这条谱系记成「一个骨干、四个插件」就不会乱：骨干不变，插件分别是对齐、视觉、稀疏、规模化。

### LLaDA 1.5：从「能生成」到「听话地生成」

基础版的短板常体现在指令跟随：任意顺序生成虽然自由，但自由度太高反而让输出不稳定——同一指令多次采样可能风格漂移、格式不齐。1.5 代的主线是**指令对齐**：用更高质量的人类偏好数据做对齐训练，让模型在被掩位置填回时更贴近「用户想要的答案」而非仅仅是「统计上像的词」。这一步没有改变扩散机制本身，仍是掩码去噪，只是把 p_θ 的分布往有用方向推。工程上的收益是直接可感的：同样的 few-shot 提示（L50），1.5 代的格式合规率与指令遵循度通常更好。但要清醒：对齐解决的是「听不听话」，不是「快不快」——多步去噪的延迟代价仍在，1.5 代并没有把它变成单步模型。所以它属于同一范式内的**质量迭代**，不是架构革命。

### LLaDA-V：把视觉接进掩码去噪

LLaDA-V 是多模态分支。思路是把图像编码成 token 序列，与文本 token 拼在同一条序列里，继续用掩码去噪的目标训练：文本位用 [MASK]、图像位用对应的图像掩码，模型在双向注意力下同时看到图文两侧信息来预测被掩位。这和自回归多模态模型（把图像当前缀、文本在其后逐 token 生成）的根本差别仍在「顺序」——扩散版不要求图像一定在文本之前，任意位置都可被掩、可按任意顺序恢复。这对「图文交错」「给定图填文、给定文补图」这类任务更自然。代价是视觉 token 数量大（一张图常几百到上千 token），会让序列变长、双向注意力的计算与 KV 更贵——这是 L57 成本模型在多模态场景的延伸。LLaDA-V 的定位是**模态扩展**，证明扩散范式不局限于纯文本。

:::deep

### LLaDA-MoE：把「总参与激活参分离」搬进扩散

LLaDA-MoE 是谱系里最有架构含量的一支，因为它把 M3/M4 的稀疏门控 MoE 直接接进了扩散 FFN。回顾 M3：MoE 把 Transformer 的前馈层换成「专家库加门控」，每 token 只路由到 top-k 个专家（如 8 选 2），于是**总参数量随专家数增长、每 token 激活参数量却只有一小部分**——容量随内存（存专家）而非 FLOPs（算激活）增长。把这套机制接到扩散骨干上，收益是双重的：一方面总参涨到很大，模型容量与知识存储上限提高；另一方面每步去噪前向只对整条序列算少量激活参，抵消了一部分多步去噪的计算代价。但要注意 MoE 的老问题照样出现：路由不均衡会让部分专家饿死（M4 的 aux-loss 与无辅助均衡路由），专家并行带来通信开销（M3 的并行策略），这些在扩散的多步迭代里会被放大——每步都要路由一次，步数越多累计开销越大。所以 LLaDA-MoE 的工程设计重点和三件事有关：路由均衡、专家并行的通信隐藏、去噪步数与路由开销的平衡。它本质上是把「M3/M4 的 MoE 账」和「L49 的多步去噪账」叠在一起算。

:::

### LLaDA 2.0：规模化与新一代能力

2.0 代代表谱系的规模化升级：更大的训练规模、更新的数据配方、更强的通用能力。对这一代，最该关心的不是某个单独指标，而是**「扩散范式是否随规模继续兑现」**——自回归的 scaling law 已被充分验证，扩散 LLM 能否在更大参数、更多 token 下延续质量提升，是这个分支要回答的核心问题。若 2.0 在同规模通用基准上继续逼近甚至追平强 AR，说明扩散不只是「可控性特化」的小众路线，而是有资格成为主流范式之一。工程上，规模化会把前面所有成本问题放大：KV 随序列长增长（L57）、多步去噪的延迟、MoE 版的路由开销，都会随规模变成真金白银的账单。所以看 2.0，能力数字与成本曲线要一起看。

### 可跑代码：谱系配置对照与激活参账

把四代的关键属性做成可查询的配置表，并把 MoE 分支的「总参 vs 激活参」算成可跑数字，这是把谱系从名词变成判据的第一步。

```python
LINEAGE = {
    "LLaDA":     {"modality": "text", "ffn": "dense",  "align": "base",   "role": "范式验证"},
    "LLaDA-1.5": {"modality": "text", "ffn": "dense",  "align": "instruct","role": "对齐迭代"},
    "LLaDA-V":   {"modality": "vision", "ffn": "dense", "align": "instruct","role": "模态扩展"},
    "LLaDA-MoE": {"modality": "text", "ffn": "sparse", "align": "instruct","role": "容量效率"},
    "LLaDA-2.0": {"modality": "text+", "ffn": "mixed", "align": "instruct","role": "规模化升级"},
}
for name, c in LINEAGE.items():
    print(f"{name:11s} 模态={c['modality']:7s} FFN={c['ffn']:6s} 定位={c['role']}")
assert LINEAGE["LLaDA-MoE"]["ffn"] == "sparse"
assert LINEAGE["LLaDA-V"]["modality"] == "vision"
print("谱系断言通过：MoE 分支稀疏化、V 分支多模态")
```

```python
def moe_params(n_layers, d_model, n_experts, top_k, expert_mult=4, dense_ffn=None):
    """MoE 分支：总参 = 所有专家；每 token 激活参 = top_k 个专家 + 共享部分。"""
    expert_size = expert_mult * d_model * d_model
    total = n_layers * n_experts * expert_size
    active = n_layers * top_k * expert_size
    return total, active

total, active = moe_params(n_layers=32, d_model=4096, n_experts=64, top_k=2)
print(f"LLaDA-MoE 示意：总参≈{total/1e9:.1f}B，激活参≈{active/1e9:.1f}B，激活占比={active/total:.1%}")
assert active / total < 0.1, "8 选 2 级稀疏应让激活参占比远小于总参"
# 关键：去噪每步只算激活参 → 多步去噪的计算被稀疏化部分抵消
```

第二段把 LLaDA-MoE 的容量账钉成可跑数字：64 专家、top-2 时每 token 激活参只占总参的约 3%，这正是「用内存换 FLOPs」的 MoE 红利在扩散场景的量化体现——它部分对冲了 L49 里那笔「32 步放大计算」的账。

### 商用对照与展示型模块的定位

商用扩散 LLM（如 Mercury 等，C 级来源）值得知道，但必须摆正位置：**它们随时间变动、多为闭源，只作背景展示，不承载任何关键结论**。本课所有机制与数字都以 A 级开源谱系（LLaDA 系列）为准。这里更要讲清「展示型模块」的概念：LLaDA 谱系中不少组件的主要价值是**验证范式可行、展示能力边界**，而非作为性能最优的产品化实现。比如任意顺序生成展示了扩散区别于 AR 的本质能力，但它不等于「在所有任务上更好」；再比如 LLaDA-V 的多模态更多是「扩散也能做多模态」的证明，不是多模态榜首。理解这一定位，选型时才不会把「能力展示」误读成「全面领先」。真正决定用不用扩散的，是 L55 的五维矩阵与 L56 的选型判据——可控性、编辑需求是否真的值那笔多步去噪的延迟成本。

:::tip

### 收束：一个骨干，四个插件

LLaDA 谱系记成「**一个离散扩散骨干 + 四个能力插件**」：1.5 装对齐、V 装视觉、MoE 装稀疏容量、2.0 做规模化。四代共享同一掩码去噪范式，差异在补哪块能力。商用产品只作背景、不担关键结论；展示型模块的价值在验证范式，而非单项登顶。带着这张地图，L52 讲 SEDD 如何把去噪目标理论化、L53 讲 Dream 如何用 AR 初始化加速收敛——它们继续在这根骨干上做机制创新。

:::
