### 训练最优与推理最优：两个不同的目标函数

L75 讲清了 Chinchilla 的计算最优：固定训练算力 C≈6ND，参数量 N 与 token 数 D 应等比扩展，最优点约每参数 20 个 token。这是 **S-Chinchilla，A 级**的结论，目标函数是「让训练这一次花掉的算力最小」。但工程里还有另一个目标：**模型训好之后要被调用成千上万次**。此时真正贵的是推理，而推理成本近似与参数量成正比——模型越大，每次前向的算力、显存、延迟都越高。

这两个目标不总是一致。Chinchilla 最优点让「训练这一次」最便宜，但没有考虑「推理很多次」的账。如果某个模型要服务海量请求，多花一些一次性训练算力，把同样的能力压进一个更小的模型，长期省下的推理开销会远超训练增量。这就是**过训练（over-training）**：在 Chinchilla 最优点之后继续喂 token，用更多训练成本换更小模型的推理收益。一句话——**训练最优≠推理最优，取决于你把成本记在训练还是推理那一栏**。

:::warn

### 来源纪律：本课的 token/参数比是 B 级

这一课会引用两个具体比值：Llama2 7B 的训练 token/参数比约 290、Llama3 70B 约 215。必须明确标注：

- 这两个数字是**第三方（唐杰、Epoch AI 等）基于公开信息的复算/估算**，属 **B 级**，不是 Llama 论文原始数据，也不是 Chinchilla 论文结论。
- 它们的口径（训练 token 总数如何估计、是否含续训、去重前后）存在不确定性，且**随时间与版本变动**。
- 因此它们**只能作数量级参考，绝不能担关键结论**。本课任何推理都不依赖「290 精确正确」——即使实际是 250 或 350，结论（小模型被显著过训练）不变。

与之对照：L73 的 LLaMA 配比（2302.13971）和 L75 的 Chinchilla 20 token/参数是 **A 级**，可作关键结论。一个讲清「是什么」（A），一个说明「业界实际怎么做」（B），等级要分清。

:::

### 为什么小模型更值得过训练

过训练的价值来自一个简单的账：**推理总成本 ≈ 单次推理成本 × 调用次数**，而单次推理成本随参数量 N 近似线性增长。设有一个场景每天要处理上亿次请求，模型从 70B 压到 7B（参数 10 倍缩小），单次推理成本大约也降到十分之一。即便把 7B 训练 token 从 Chinchilla 最优的 140B（20×7B）增加到 2T（约 290×7B，B 级量级），多花的训练算力是一次性的，而省下的推理成本每天都在累积。用不了太久，训练增量就被推理节省覆盖。

反过来，**大模型、低调用量**的场景过训练就不划算：推理次数少，省不下多少，多花的训练 token 纯属浪费。所以过训练是**场景相关**的决策，判据是「推理量是否足够大、模型是否能压得更小且不掉点」。这也解释了为什么业界倾向对**小模型**过度训练：小模型单次推理便宜、部署广、调用量大，把能力压进去的收益最明显。Llama2 7B、Llama3 8B 这类被广泛部署的小尺寸，正是过训练的典型对象。

注意「压得更小且不掉点」这个前提。过训练之所以可行，是因为经验上在同样数据预算下，把一个小模型训得更久，能在很多基准上逼近甚至达到一个更大但欠训练模型的水平。这个经验现象有多篇工作支持，但具体比值（如 290、215）是 B 级估算，不要写死。

### 把「训练账 vs 推理账」算成可跑脚本

把上面的直觉落成可执行的总成本估算：给定模型参数 N、训练 token/参数比 r、调用次数 Q，比较「Chinchilla 最优小模型」与「过训练小模型」以及「欠训练大模型」的训练成本与推理成本。数字用 B 级量级作示意，**仅用于展示账的结构，不担关键结论**。

```python
# 成本结构演示（B 级量级，仅示意账的结构，不担关键结论）
def cost_breakdown(N_params, tokens_per_param, Q_calls):
    D = N_params * tokens_per_param
    train_flops = 6 * N_params * D            # C≈6ND
    infer_flops_per_call = 2 * N_params       # 推理约前向 2ND，单 token 简化为 2N
    infer_flops_total = infer_flops_per_call * Q_calls
    total = train_flops + infer_flops_total
    return D, train_flops, infer_flops_total, total

N_small = 7e9
Q = 1e12                                     # 海量调用：1 万亿次前向
configs = {
    "7B @20x (Chinchilla最优, A级比例)": 20,
    "7B @290x (过训练, B级复算)": 290,
    "70B @20x (大模型基线)": 20,
}
print(f"{'配置':32s} {'训练FLOPs':>12s} {'推理FLOPs':>12s} {'合计':>12s}")
for name, r in configs.items():
    N = 70e9 if "70B" in name else N_small
    D, tr, inf, tot = cost_breakdown(N, r, Q)
    print(f"{name:32s} {tr/1e18:11.1f}E {inf/1e18:11.1f}E {tot/1e18:11.1f}E")
# 读法：调用量 Q 极大时，推理项主导；把模型从 70B 降到 7B，推理项降 10 倍
_, tr7, inf7, _ = cost_breakdown(7e9, 290, Q)
_, tr70, inf70, _ = cost_breakdown(70e9, 20, Q)
print(f"7B 推理是 70B 推理的 {inf7/inf70:.2f} 倍（应≈0.1）")
assert abs(inf7/inf70 - 0.1) < 1e-6
```

这段代码把「为什么过训练划算」讲成结构：当 Q 极大时，推理项主导总成本，模型参数量是杠杆——70B 降到 7B，推理项降十倍。训练项哪怕因过训练涨十几倍，在总账里仍可能远小于推理节省。再次强调：这里 290 只是 B 级量级示意，结论对具体数值不敏感。

### 工程判据：什么时候该过训练

把决策落成判断顺序。第一，**先看推理量**：模型要被高频调用（API、端侧、嵌入服务）才值得过训练；一次性离线使用的模型按 Chinchilla 最优点训即可。第二，**确认能力不掉点**：过训练的前提是小模型训久后能达到目标能力，要在你的任务上抽测，不能假设「训久必追平」。第三，**记全成本**：把训练增量与推理节省放在同一张账上比（上面的脚本），用你自己的 Q 与硬件单价算，不要用别人的比值。第四，**标注来源等级**：引用 290、215 时必须写明「B 级第三方复算、随时间变动、不担关键结论」，不能当常量传播。

一个常见误区是把过训练理解成「训得越久越好」。它不是无止境的：token 增加带来的收益递减，到某个点后再加 token 提升极小、纯属浪费；而且高质量数据有限，过度重复可能过拟合。过训练是**有限度的主动偏离**，目标是在给定推理约束下找到总成本最低点，不是把训练拉到最长。

:::tip

### 一句话收束过训练

Chinchilla（A）的 20 token/参数是「训练成本最优」；过训练是「推理成本最优」——当模型被海量调用时，多花一次性训练 token 把能力压进更小模型，长期推理更省，故小模型更值得过训练。Llama2 7B≈290、Llama3 70B≈215 是**第三方复算的 B 级值，随时间变动、不担关键结论**，只作数量级参考；即使数值有出入，「小模型被显著过训练」的结论不变。训练最优与推理最优是不同目标函数，不矛盾。下一课 L77 用可跑脚本把 6ND、Chinchilla 边界与过训练系数合成给定预算的 N/D 规划。

:::
