### L17 补的实质内容

- **为什么「再试一次」没用**：把「偶发失败（采样方差）」与「系统性失败（输入没变）」分开，
  这是 Reflexion 的立论前提。
- **五步闭环里的第②步才是命门**：评估必须是外部信号，「让同一个可能出错的模型判卷」等于没判。
- **三种「让 Agent 变好」的边界表**：微调 / few-shot / 语言化记忆，按「作用域」区分——few-shot
  是通用示例，Reflexion 是针对本次失败的经验，所以记忆必须按任务类型检索。
- **反思质量的对照表**：三组写法（空话 / 归因错 / 具体动作）逐条拆「为什么无效」，给出三条判据
  （指向动作、可检验、不重复已有提示）。
- **有效三前提与失效三情形**：可判定、原因稳定、可归因；反之评估噪声大 / 失败随机 / 不可重试时
  要克制。
- **记忆腐化**（膨胀 / 矛盾 / 过期）与三条工程对策（分区、最近 K 条、置信度淘汰）。

### L18 补的实质内容

- **四个不变量**：只有失败才反思、必须落盘且分桶、注入是一次性 K 条、重试有上限且同反思不重复触发。
- **原子落盘**：临时文件 + `rename`，并解释「半截 JSON 导致整库丢失」这个真实故障。
- **`hits` 命中计数**：注入后任务成功加分，作为召回排序与淘汰的唯一学习信号（否则记忆只会增长）。
- **反思 prompt 三段式**：现象 / 根因 / 下次改动，禁止归因于「模型能力」「信息不足」。
- **两个确定性用例**：失败一次→反思落盘→第二次成功不再反思；同一反思重复出现→提前收手。
- **框架对照**（`:::deep`）：LangGraph 的 `checkpoint` 存「流程状态」、`MemoryStore` 存「经验」，
  对齐点只有隔离粒度（`thread_id` ↔ `taskKind`）。
- **记忆存储选型表**：JSON / SQLite / 向量库 / 托管 KV，判据是「召回靠什么」。
- **一笔成本账**：成功率 60%→85% 时净收益在 C 量级；60%→62% 时净成本 +0.1C 每次——先量成功率
  再决定要不要反思。
