### 一行实现体背后的架构宣言

L103/L104 解剖完旧世界的宪法与状态协议，本课翻到新大陆这一页。核心结论：**1.x 的 agent 不是「更聪明的 Chain」，而是「被编译成 LangGraph 图的程序」——createAgent 的一行实现体就是这句话的物证，ReactAgent 类里的 #graph 字段是它的心脏。**前四课你已经见过 LangGraph 的内核（L65-L82），现在看它如何成为新 agent 的运行底座。

先看工厂函数的真身。createAgent 拥有 14 个重载（index.ts:175-670），但翻到 implementation，核心只有一行：

```ts
export function createAgent<
  StructuredResponseFormat extends Record<string, any>,
  TStateSchema extends StateDefinitionInit,
  ContextSchema extends AnyAnnotationRoot | InteropZodObject,
  TMiddleware extends readonly AnyAgentMiddleware[],
  TTools extends readonly (ClientTool | ServerTool)[],
  TStreamTransformers extends ReadonlyArray<() => StreamTransformer<any>>,
>(
  params: CreateAgentParams<StructuredResponseFormat, TStateSchema, ContextSchema, any>
): ReactAgent<AgentTypeConfig<...>> {
  return new ReactAgent(params);
}
```

*— langchain/src/agents/index.ts:672-702（commit 7704471，泛型有裁剪）*

它不做任何执行逻辑——这是与旧世界最根本的区别。旧 AgentExecutor 自己是执行器（extends BaseChain，手写 while 循环）；新工厂把执行责任全部移交给 ReactAgent 类，而 ReactAgent 的全部职责是**在构造期把参数编译成图**。


*— langchain/src/agents/ReactAgent.ts:164-188（commit 7704471）*

三个字段值得逐个读。`#graph: CompiledStateGraph` 是核心：编译图不是构造完就丢掉的中间产物，而是 agent 实例的持久成员，invoke/stream/getState/getStateHistory 全部委托给它（L42-L44 走读过的路径）。`~agentTypes` 是品牌字段，纯粹为类型推导服务（L40/L101 讲过），与执行无关。`#agentNode` 持有 AgentNode 实例——模型调用与「要不要继续调工具」的决策节点，对应 L45 的 1107 行解剖。

「编译」这个词在这里是字面意义：构造器把 model、tools、prompt、responseFormat、stateSchema、middleware 六类参数组装成 StateGraph 的节点与边，再 compile 成可执行图。旧世界「构造一个带开关的执行器」，新世界「编译一张程序图」——constructor 即编译器，这就是新世界观的第一句话。

### 循环控制的三层代差

Agent 即编译图最实际的收益在循环控制上。旧 AgentExecutor 的循环是唯一闸门：

```ts
maxIterations?: number = 15;
earlyStoppingMethod: StoppingMethod = "force";
...
private shouldContinue(iterations: number): boolean {
  return this.maxIterations === undefined || iterations < this.maxIterations;
}
...
while (this.shouldContinue(iterations)) {
```

*— langchain-classic/src/agents/executor.ts:367-372,503（commit 7704471）*

一个计数器 + 一个布尔函数 + 一个 while，所有迭代上不去下不来。新架构把它拆成三层：**图级** recursionLimit 由 LangGraph 统一管（超步计数，interrupt/恢复时依然生效）；**工具级** toolCallLimitMiddleware 能按工具名、按次数精确限闸（middleware/index.ts:47-51 导出）；**模型级** modelCallLimitMiddleware 限模型调用次数。旧开关「一个数字管一切」到新架构「按切面分层限闸」，这个映射在 L112 的参数对照表里还会逐项过。

错误处理的代差同样来自图结构。旧执行的 handleParsingErrors 是一个布尔/字符串/函数三态开关（executor.ts:384-390 的 JSDoc 写明了三态语义），错误发生后塞回 LLM 当 observation。新架构里 toolErrorMiddleware/toolRetryMiddleware 是独立可组合的切面——错误处理从「执行器的一个属性」变成「工具调用环路上的可插拔节点」，而且 middleware 组合本身是声明式的（L55/L58 走读过实现）。

### 为什么「编译图」改变了可观测性与持久化

旧循环是黑盒：想知道中间发生了什么，要开 `returnIntermediateSteps = false` 这个开关手动收集 AgentStep。图执行天然自带观测面：每个节点写状态都走 `_applyWrites` 的确定性排序（L76），八种流模式能按 values/updates/messages/events 等粒度订阅（L78），checkpoint 在超步边界落快照（L79）。三者共用同一套「图状态」底座——**因为执行是图，所以断点恢复、时间旅行、human-in-the-loop 都是免费午餐**；旧循环想加这些，等于重写执行器。

这也解释了 L102 那条依赖证据的分量：langchain@1.6.6 依赖 @langchain/langgraph ^1.6.1。旧包是自足的（编排引擎内嵌在 AgentExecutor 里），新包把编排引擎外包给 LangGraph 并以此为心脏。**「Agent 即编译图」不是营销比喻，是 package.json 里的一行依赖声明加一个 #graph 私有字段。**

顺带钉死一个术语口径：TS 线的真实导出是 `createAgent`（camelCase），`create_agent` 是 Python 名；而 classic 里有一个同名陷阱——classic 的 `createReactAgent` 是从 LangGraph prebuilt 迁来的旧入口（agents/index.ts:96-99 导出），与新的 `createAgent` 毫无继承关系，这个坑在 L119 专门排雷。

### 本课小结

- createAgent 的实现体只有 `return new ReactAgent(params)`（index.ts:672-702）：工厂不执行，执行体是 ReactAgent 编译出的 #graph。
- AgentExecutor 的 while 循环 vs 图执行是两代分水岭：单一 maxIterations=15 → 图级 recursionLimit + 工具级/模型级 middleware 分层限闸。
- 错误处理从执行器三态开关变成可组合 middleware；中间步骤从手动开关收集变成八种流模式与 checkpoint 的天然产物。
- 可观测性、持久化、HITL 之所以在 1.x 是「免费午餐」，因为执行即图——代价是必须理解 LangGraph（模块六已垫底）。
