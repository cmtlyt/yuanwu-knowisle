### 开篇：一行 return 背后的 530 行

L40 说 ReactAgent 构造器是「真正的引擎」，本课把它拆开。从 ReactAgent.ts:189 到 722，构造器完成一件事：**把 createAgent 的声明式参数变成一张可执行的 LangGraph 图**。这段代码是全模块的枢纽——中间件怎么变成节点（L47）、entry/exit 怎么决策（L48）、模型与工具怎么循环（L45/L46），全部在这 530 行里定形。本课按八个阶段走主干，深水区留给后续课。先给一张阶段地图，再逐段取证。

### 阶段一：工具收集与状态 schema 合并

```ts
const toolClasses = [...(options.tools ?? []), ...middlewareTools];

const shouldReturnDirect = new Set(
  toolClasses

    .filter((tool) => "returnDirect" in tool && tool.returnDirect)
    .map((tool) => tool.name)

```

`createAgentState`（annotation.ts:24-169）把内置 messages 通道、jumpTo（UntrackedValue）、用户 stateSchema、每个中间件的 stateSchema 合成一个 StateSchema，且**输入/输出 schema 与内部状态 schema 分离**——下划线前缀字段只在内部状态存活，不进输入输出。然后 `new StateGraph(state, { input, output, context })` 建图。此处 `allNodeWorkflows` 断言（ReactAgent.ts:263-266）让 addNode/addEdge 能引用还没注册的节点名——纯类型层手术，运行时无任何变化。

### 阶段二：hook 节点注册——中间件变成图节点

构造器按 middleware 顺序遍历，**每个实现 hook 的中间件都会产生真实图节点**，命名规则 `{middleware名}.{hook名}`：

```ts
for (let i = 0; i < middleware.length; i++) {
  ...
  const m = middleware[i];
  if (middlewareNames.has(m.name)) {
    throw new Error(`Middleware ${m.name} is defined multiple times`);
  }
  middlewareNames.add(m.name);
  if (m.beforeAgent) {
    beforeAgentNode = new BeforeAgentNode(m);
    const name = `${m.name}.before_agent`;
    beforeAgentNodes.push({
      index: i,
      name,
      allowed: getHookConstraint(m.beforeAgent),
    });
    allNodeWorkflows.addNode(name, beforeAgentNode, beforeAgentNode.nodeOptions);
  }
  // beforeModel / afterModel / afterAgent 同构，略
}
```

*— libs/langchain/src/agents/ReactAgent.ts:306-372（commit 7704471）*

三个要点。其一，**重名中间件直接抛错**——节点名以中间件名为前缀，重名会让图节点冲突。其二，hook 有 `allowed` 约束（getHookConstraint 提取），它决定该节点是否升级为条件边（这是 L47/L48 的主题，此处只见数据收集）。其三，`wrapModelCall` 不产生节点——它不进图，而是被收集进 `wrapModelCallHookMiddleware` 数组交给 AgentNode 内部使用（ReactAgent.ts:374-376），这就是六个 hook 里 wrapModelCall/wrapToolCall 与四个 before/after hook 在图结构上的根本差异。

### 阶段三：主节点注册与 ToolNode 按需创建

主循环节点注册在前，工具节点按需注册在后：

```ts
allNodeWorkflows.addNode(AGENT_NODE_NAME, this.#agentNode);

if (clientTools.length > 0 || hasWrapToolCallMiddleware) {

    signal: this.options.signal,

  });

```

*— libs/langchain/src/agents/ReactAgent.ts:382-415（commit 7704471）*

两处防御值得圈点。其一，**v1 + hitl per_call 直接抛错**，错误信息把原因讲透：v1 把所有工具调用塞进一个任务，per-call interrupt 会共享 ID，无法逐调用暂停——所以必须 v2（默认）。其二，ToolNode 的创建条件是「有客户端工具 **或** 有 wrapToolCall 中间件」；构造 ToolNode 时还把 `workflow.channels` 的键（除 jumpTo）作为 stateKeys 传入，供动态工具读取状态。注意 server tools（filter isClientTool 之后被排除）不进 ToolNode——它们由 provider 端执行。

### 阶段四：三锚点接线——START、回环、出口

边接线由三个锚点驱动（ReactAgent.ts:420-441）：

```ts
let entryNode: string;
if (beforeAgentNodes.length > 0) {
  entryNode = beforeAgentNodes[0].name;
} else if (beforeModelNodes.length > 0) {
  entryNode = beforeModelNodes[0].name;
} else {
  entryNode = AGENT_NODE_NAME;
}

const loopEntryNode =
  beforeModelNodes.length > 0 ? beforeModelNodes[0].name : AGENT_NODE_NAME;

const exitNode =
  afterAgentNodes.length > 0
    ? afterAgentNodes[afterAgentNodes.length - 1].name
    : END;

allNodeWorkflows.addEdge(START, entryNode);
```

*— libs/langchain/src/agents/ReactAgent.ts:421-441（commit 7704471）*

**entryNode 由第一个 beforeAgent 节点决定**（无则退到 beforeModel，再无则 model_request）——L48 的标题就在这句话里。`loopEntryNode` 刻意不含 beforeAgent：工具执行后回到循环头（第一个 beforeModel 或 model_request），保证 beforeAgent 在一次 invoke 里只跑一次。`exitNode` 取**最后一个** afterAgent——注意方向：afterModel/afterAgent 的执行顺序是按中间件数组**倒序**（ReactAgent.ts:542-568 的 `for (let i = afterModelNodes.length - 1; i > 0; i--)`），后注册的先跑，与 before* 的正序形成镜像。随后是四段循环接线：beforeAgent 链（可含条件边）、beforeModel 链、模型节点→(最后 afterModel 或模型路由)、afterModel 倒序链、工具回环。所有条件边的 destinations 都做了一致处理：把 END 替换成 exitNode、把 tools 目标按 hasToolsAvailable 过滤——**条件边必须穷举合法目标**，这是 LangGraph 的编译期约束。

### 阶段五：compile 与烘焙收尾

最后收集三层流转换器并编译（ReactAgent.ts:690-721）：内置 createToolCallTransformer/createSubagentTransformer、中间件 streamTransformers、用户 streamTransformers，按此顺序传入 `allNodeWorkflows.compile({ checkpointer, store, name, description, transformers })`，产物赋给 #graph；若 toGraphDefaultConfig 筛出的静态默认配置非空，再用 `#graph.withConfig(...)` 替换一次（L40 已拆）。至此 createAgent 的调用返回——**参数变成了图，声明变成了拓扑**。后续所有执行课（invoke/stream/节点内部）都在这张静态图上发生。

### 本课小结

- **八阶段流水线**：工具收集与 returnDirect 盘点 → createAgentState 三 schema → hook 节点注册（重名抛错）→ AgentNode + 条件 ToolNode → 三锚点（entry/loopEntry/exit）+ 四段链接线 → transformers 收集 → compile → withConfig 烘焙。
- **两个按需条件**：ToolNode 需要 clientTools 非空或存在 wrapToolCall；条件边仅在 hook 声明 allowed 时出现。
- **三个锚点记法**：entry=第一个 beforeAgent（无则降级）、loopEntry=第一个 beforeModel（无则 model_request）、exit=最后一个 afterAgent（无则 END）；before* 正序、after* 倒序。
- **wrapModelCall 是例外**：不产生图节点，收集进数组交给 AgentNode 内部。
- 下一课走第一条执行路径：invoke 如何归一参数、初始化中间件状态，最终委托 #graph.invoke。
