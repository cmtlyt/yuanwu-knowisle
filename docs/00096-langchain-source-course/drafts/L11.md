### 最薄的两个类，最清楚的一课

模块二的消息族里，AIMessage 有 190 行构造函数、ToolMessage 有三字段协议，而本课的两位主角是全库最薄的消息类——薄到一屏读完。薄不是偷懒，是 L10 双泛型骨架的设计收益兑现：role 已被类型参数吃掉，content 归一已上移基类，子类真的只剩「报个名字」。本课的第二个主题是 concat：同样是合并消息，HumanMessageChunk 与 SystemMessage 走了两条不同的路，差异不大但语义耐人寻味。**核心结论：极简子类验证了基类承载全部逻辑的可行性，而 concat 的分叉暴露了两类消息不同的存在方式**。

### 最薄子类的形状

四个要点：用 `this.constructor` 取类而非硬编码类名（子类化安全）；content 交 mergeContent（空串让位、双串拼接）；additional_kwargs/response_metadata 交 _mergeDicts（L15 的主角，字符串累加、数字求和）；id 取 `this.id ?? chunk.id`（首个非空 id 获胜）。SystemMessageChunk 的 concat（system.ts:100-114）与这段几乎逐字相同——chunk 世界是统一的。

三处差异摆上桌。**参数类型**：`string | SystemMessage`，而 HumanMessageChunk.concat 只收同类型 chunk——系统消息可以直接拼一段提示词，这是「系统提示词常被程序分几段组装」的使用现实倒逼出的 API。**合并策略**：消息分支不用 _mergeDicts，而是 `{...a, ...b}` 浅展开。**白名单校验**：两种输入之外一律抛错，不做 coerce。

### 差异背后的语义

为什么同一个库允许两种合并哲学并存？把两类消息的存在方式摆出来就清楚了。HumanMessage 在对话里会经历流式（虽然 provider 很少流式输出用户消息，但 chunk 类仍在）、会有 usage 类元数据需要求和、会有多段内容需要拼接——它生活在「增量世界」，需要类型感知的合并器。SystemMessage 生活在「单条世界」：系统提示词通常一条定终身，最多被程序预拼接几段；它没有 delta 流、没有 token 累加、没有按 index 归并的数组。对这样的对象，_mergeDicts 的精细规则是过度工程，浅覆盖（后者同名字段赢）反而语义直白。**合并器的复杂度应当匹配对象的生命周期形态**——这是本课真正想留下的判断力，下一课 AIMessage 会展示增量世界的完整复杂度。

还有一处小对比：SystemMessage.concat 的字符串分支保留 name（this.name），消息分支用 `this.name ?? chunk.name` 兜底；id 恒用 `this.id ?? chunk.id`。这些「首值优先」的小规则与 chunk 世界的 id 规则一致，说明作者在浅合并里也保留了身份字段不覆盖的底线。

三条规则各有含义。**空串让位**：firstContent 为空串时直接返回 secondContent——这是「空 delta 不产生内容」语义的来源，L15 的 _mergeLists 对空 text 块的跳过规则与此一脉相承。**双串拼接**是流式文本累积的基本盘。最有意思的是第三条：**字符串遇上数据内容块时，字符串被升格为 `{type:"text", text}` 块再拼接**——v1 内容模型的混合现实（一段文本 + 一张图）就这样在合并层被无损处理，字符串永远不会「挤掉」块数组。对 HumanMessageChunk 与 SystemMessage 来说它们几乎用不到多模态分支，但共享这一个入口意味着消息内容合并在整个库只有一份规则表——L15 讲的 _mergeDicts/_mergeLists 是元数据与列表层，内容层永远先过 mergeContent。把这两层分开记，后面读 AIMessageChunk.concat 的完整合并链时就不会迷路。

### 本课小结

- HumanMessage 类体只有 lc_name/type/构造透传/判型四件事，薄子类是 L10 基类骨架投资回报的直接证据。
- chunk 家族的 concat 是统一套路：mergeContent + _mergeDicts + `this.id ?? chunk.id`，SystemMessageChunk 与 HumanMessageChunk 逐字同构。
- SystemMessage.concat 特立独行：接受字符串、消息间浅合并、白名单外抛错——因为系统消息是「单条世界」的公民。
- 合并策略应匹配对象生命周期：增量世界用 _mergeDicts，静态世界用浅覆盖。
