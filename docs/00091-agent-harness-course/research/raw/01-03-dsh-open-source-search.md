## 2. [DeepSeek不满足于模型,还要让AI自己干活](https://so.html5.qq.com/page/real/search_news?docid=70000021_0126ae9ad9997952)

(本文作者为财能圈,钛媒体经授权发布)文|财能圈10月31日晚,DeepSeekHarness团队在官方公众号发表技术文章《Super-agent设计探索:迈向更自主的Agent系统》,配套原型dsh-superagent-prototype同日在GitHub开源,MIT协议。文章开头有一句自我限定:这是一篇面向工程实践的架构思路探讨,并非对现有产品功能的介绍。但文中给出的判断很具体:随着模型能力提升,AI完成单个任务已越来越不需要人工干预,人管理多任务的注意力却没有同步增长,一个人依然只能同时跟进3到5个活跃会话。DeepSeek的原话是:单任务的上限取决于模型能力,多任务的上限取决于人的注意力。这句话是整篇文章的起点。文章还提到,模型能力的提升催生了一批新形态,个人助手开始集中涌现,它们直接接入消息、日程、邮件与工作平台,持续观察信息流。这种持续在线、事件驱动的工作方式不局限于个人场景,在软件开发等商业场景同样成立,但现有主流智能体的设计撑不住这个规模。新架构的所有设计,都在解决这个卡点。01 会话之间不通,上限就落在人身上据悉,现有智能体以单个会话为基本单位,会话之间彼此独立。这会导致一种现象,A会话里得出的结论,B会话里的它并不知道。当用户并行推进多项工作时,必须手动切换,自己记住每一条上下文。到最后,只有人知道所有任务的全貌。DeepSeek的解法是给AI分工。一层叫router,是持续运行的全局协调节点,统一接收群聊、GitHub、邮件等多渠道消息,维护共享上下文,把任务分派下去,自己不深入执行。另一层叫worker,各自维护独立上下文,并行做问题复现、代码审查、功能开发,必要时可调用Subagent(子智能体)。这个设计和常见的“主智能体带几个子智能体”不一样。主智能体需要理解任务细节、规划子任务、高频协调,推理负担很重;router只管这件事该推给谁,worker之间上下文隔离,冲突靠订阅同一个话题自行发现。worker接手任务后还能直接订阅后续消息,省掉经router转发的协调开销。DeepSeek自己说,这套设计没有提出全新理论,是把计算机系统里的经典工程思想搬到了智能体身上。事件驱动,让群聊消息、邮件、日程提醒、GitHub评论、CI测试结果都成为触发行动的事件。存算分离,执行循环放在云端,会话状态存入数据库,本地只留一个轻量daemon(守护进程),电脑离线任务也能继续跑。外部watchdog(看门狗)负责检查任务是否陷入无效循环并尝试修复。异步ReActLoop(推理—行动循环)让AI执行耗时任务时仍能响应新指令,这一项尚未默认开启。另外,还有一层投机执行,当结果是否会被采用尚不确定时,先在后台提前尝试,有价值再提交,没有就放弃。此外,“主动”是这套系统的关键词,也是最需要克制的地方。绝大多数群聊消息不需要AI介入,DeepSeek设了两级过滤:先用程序规则筛掉明显无关的消息,再由大模型判断剩下的是随口吐槽还是真有问题,两道都通过才派任务。文章给了一个内部实例:团队成员在群聊里说“这个项目有BUG”,没有人@它,Super-agent在后台静默复现,确认问题存在并找到简单修复方法后才提交PR(拉取请求),交给人验收。后续有人在GitHub评论里要求换一种修法,它又能从聊天软件的上下文切到GitHub继续做。这套策略在内部叫“静默复现并修复”。文章还给了一组实验数据,基于该思路的Super-agent,任务完成时间中位数12.4分钟,95分位15.7分钟,优于带子工具的普通会话。DeepSeek同时说明,这是基于合成负载与简化环境的初步实验,不是正式产品结论。产品边界也写在明处。GitHub上的原型是研究原型,不是正式产品。按仓库说明,公开发布的版本与DeepSeek内部运行的系统并不相同,文中部分功能仍在开发中。目前它主要面向一个GitHub仓库,也可以选择接入飞书。Super-agent只在被请求、或团队事先写好规则允许时行动,没有结果时不播报过程,没有权限时不擅自行动。值得注意的是做这件事的团队。发布者是Harness团队,不是模型团队。02 两轮融资之后,对外输出的东西变了把时间线拉出来,这条新闻的位置就清楚了。2026年4月,DeepSeek启动成立以来的首轮外部融资,6月底完成交割,规模约510亿元,投后估值接近4000亿元。出资方中,梁文锋个人出资约200亿元,腾讯约100亿元,宁德时代体系约50亿元,网易、京东、砺思资本、IDG资本各约30亿元,国家人工智能产业投资基金也在其列。10月22日起,新一轮融资的消息在市场间传开:拟筹约1000亿元,最初募资目标500亿元,此后至少两次上调。腾讯和宁德时代是本轮出资最多的投资方。多家媒体从不同信源交叉求证,截至发稿,DeepSeek及相关投资方 8 月 13 日,DeepSeek 在 GitHub 上公开了一个叫 deepseek-harness 的仓库(命令行名 dsh)。没有发布会,没有长篇技术报告,README 第一行只有四个词:Everything is a plugin(一切皆插件)。几天之内,星标冲过 15 万;到 10 月中旬,约 25 万星、2.9 万 fork,npm 周下载量 45 万次——对一个还处于“开发者预览”阶段的项目来说,这个速度在开源史上排得上号。很多读者对“Harness”这个词是陌生的:它既不是新模型,也不是聊天助手,凭什么让整个开发者社区这么兴奋?这篇文章讲清楚三件事:Harness 到底是什么、它用在哪里、以及 DeepSeek 这次开源的 Harness(dsh)有什么不一样。最后照例给三个冷静的折扣,免得大家把预览版当成成品。⏱ 信息截止:文中版本号、星标数、下载量等均截至 2026-10-31 前后的公开口径(来源:GitHub deepseek-ai/deepseek-harness、npm、DeepSeek 官网);dsh 处于快速迭代期,具体特性请以官方仓库为准。一、Harness 是什么:模型是大脑,Harness 是身体Harness 不是新词。它在软件工程里原本指“测试工具链”(test harness):把被测对象装进一个标准化框架里,自动喂输入、收输出、断言结果。飞机出厂前要上“测试台架”,软件发布前要过“测试 harness”——让一个核心部件能在真实环境里反复运转起来的那套装置,就是 harness。把这个概念搬到 AI 上:大模型是核心部件,Agent Harness 就是让它在真实工作环境里运转起来的整套装置。DeepSeek 官方给过一个极简公式:
Agent = Model + Harness
模型本身只会做一件事:根据上下文,预测下一个 token。它没有手、没有持久记忆、没有权限,也不能主动“停”——你不对话,它就是磁盘上的一堆权重。而 Agent 之所以能“自己干活”,靠的是模型外面那一圈东西:循环(Agent Loop):把目标交给模型 → 解析它输出的工具调用 → 真正执行 → 把结果塞回上下文 → 再问模型下一步 → 直到任务完成。一圈一圈转,直到“活干完了”;工具系统:读写文件、跑 shell、搜索网页、调用 API——模型“说话”,工具“动手”;上下文管理:历史太长要压缩,关键信息要注入,窗口装不下要取舍;权限与沙箱:哪些命令能跑、哪些文件能碰、失败了怎么办;会话与界面:你的终端窗口、网页、桌面应用,都是 harness 的一部分。所以更准确的理解是:模型负责“想”,harness 负责“落地”。同一个模型套上不同的 harness,日常体验可能天差地别——为什么有的编程助手失败后会自动换个思路重试、有的会记住你的项目偏好、有的敢直接改你的生产配置,这些差异九成不在模型,而在 harness。一个容易被忽略的事实:我们平时评价一个 AI 编程工具“好不好用”,很大程度上是在评价 harness 的工程水平——上下文怎么组织、工具怎么设计、错误怎么恢复。模型拿到的是头条,但体验是 harness 给的。二、应用场景:从写代码到自动化,harness 已经无处不在1. 编程——目前最成熟的主战场。 Claude Code、OpenAI Codex CLI,以及国产阵营的 Qwen Code、Kimi CLI、MiniMax Code、Z.ai ZCode,本质都是“模型 + harness”的编程 agent:理解仓库、定位 bug、写代码、跑测试、提交 PR。2026 年的一个明显趋势是:每家有模型的大厂,都开始自研自己的 harness。2. 日常办公自动化。 整理资料、分析表格、写文档、做汇报 PPT、生成周报——这些“描述清楚就能干”的任务,正是 harness 的舒适区。dsh 官网首页的演示场景就是这个方向:生成季度数据汇总 PPT、给报表补同比环比列、定时整理项目记录。3. 数据分析与研究查证。 让 agent 读数据、跑脚本、出图表,再联网交叉核对、标注来源。顺带说一句:本文的配图,就是 agent 在 harness 里写脚本、逐像素画出来的——这本身就是一个应用场景的现场演示。4. 后台与定时任务。 跑批处理、监控指标、定时执行长任务。dsh 专门提供了 headless 模式:一条命令跑完一个会话、打印结果、退出,天然适合塞进 cron 或流水线。5. 更深一层:评测与训练的基础设施。 SWE-bench 这类基准的分数,和 agent 使用的 harness 强相关——同一模型换个 harness,成绩能差出一截。做 RL 训练时,给模型提供工具环境的那套装置同样是 harness。谁掌握 harness,谁就同时掌握了“使用模型”和“训练模型”两个入口。这就是为什么 harness 突然成了兵家必争之地:模型开源了很多,但默认入口才是生态位。三、DeepSeek Harness(dsh):把整个 agent 拆成插件dsh 的定位要说准确:它不是模型,也不是聊天界面,而是一个开源的 Agent 运行时(harness)。上面那个公式里,它负责加号右边的全部。基本盘:MIT 许可证、TypeScript 编写、2026 年 8 月 13 日仓库公开,提供 Web UI 和桌面端(macOS / Windows)。装好 Node.js 后一行命令就能跑起来:npx @deepseek-ai/dsh web默认在本地 3080 端口起一个 Web UI,模型可以在设置里接入——不只 DeepSeek 自家,Kimi、OpenAI、谷歌等数十家厂商的模型都能接。这一点非常关键:dsh 是一个模型无关的运行时,它赌的不是“你必须用我的模型”,而是“你可以用任何模型,但用我的骨架”。架构:一切皆插件。 dsh 底层是 Cordis 插件内核(脱胎于老牌 Node.js 聊天机器人框架 Koishi)。Cordis 有个漂亮的特性叫“可逆副作用”:插件注册的每一项能力都被追踪,卸载时自动回收——所以插件可以真正热插拔,装卸不用重启。在 dsh 里,模型适配器、工具注册表、会话日志、沙箱、子 agent、调度器,甚至 agent loop 和 UI 本身,全都是插件,通过配置就能替换扩展,不需要改一行源码。官方架构文档的表述很直接:不存在“需要打补丁的特权内核”。四种运行模式,覆盖从日常到极客的场景:创造模式最出圈:官方演示里,agent 接到“写一个悬浮番茄钟”的需求后,自动加载插件开发技能、写出 638 行代码、通过插件管理器安装、再验证运行——全程 5 分 24 秒,不需要人碰一行代码。这不是演示动画,是“一切皆插件”架构的自然结果:既然所有能力都是插件,那“创造新能力”当然也可以是 agent 的一项能力。可观测性是另一个亮点。 每个会话对应一份只增不改的事件日志(append-only):系统提示词、模型推理、每一次工具调用与结果、子 agent 调度、每一次上下文注入,全部留痕。在“轨迹视图”里可以按来源逐条审查;继续会话、分叉、搜索、回放,操作的都是同一份事件流。对认真做生产级 agent 的人来说,这一条比任何花哨功能都重要——跑过长任务的人都知道,“它刚才到底看到了什么、为什么这么做”有多难查。记忆机制要单独说。 dsh 内置两层:会话日志 + 自动压缩(上下文超过窗口 80% 时自动摘要旧历史、保留最近原文)。但这两层都不跨会话——关掉会话,积累的上下文就没了。跨会话的长期记忆(记住你的偏好、项目约定),要靠装记忆插件(Mem0、Hindsight 等)或 MCP 记忆服务实现。这个设计很诚实:内置的保持简单,有分歧的交给生态。四、三个折扣:兴奋之前,先泼三盆冷水折扣一:这是开发者预览版,不是成品。 README
