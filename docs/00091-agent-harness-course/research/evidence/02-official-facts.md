## Pi（https://pi.dev/，官方产品页）

- **F-P1｜定位与口号**：`Pi is a minimal agent harness.` / `There are many agent harnesses but this one is yours` / `Change the harness, not your workflow`。可让 Pi 在运行时**原地修改自身**，`/reload` 后继续；扩展、技能、提示模板、主题可打包成 Pi packages，通过 npm 或 git 分发（`pi install npm:@foo/pi-tools`、`pi install git:github.com/badlogic/pi-doom`）。
- **F-P2｜官方明确「不做」清单（What we didn't build）**：无 sub-agents（建议 tmux 派生 Pi 实例或写扩展）、无 permission popups（建议跑在容器里或自建确认流程）、无 plan mode、无内置 to-dos（用 `TODO.md`）、无 background bash（用 tmux，官方理由 `Full observability, direct interaction`）。页面首段另写 `Pi ships with powerful defaults but skips features like sub-agents and plan mode.`
- **F-P3｜MCP 立场已改变（重要）**：小标题原文是 `No MCP Now with MCP+Codemode`，正文 `MCP is built in, and Codemode lets agents compose tool calls in a JavaScript sandbox. MCP extensions are still supported too.`，并链接 `Why we changed our minds`。**「Pi 拒绝 MCP」是过时结论，不得写进课程。**
- **F-P4｜四种运行模式（Pi 的，不是 DSH 的）**：`Interactive`（完整 TUI）、`Print/JSON`（`pi -p "query"`，`--mode json` 事件流）、`RPC`（stdin/stdout JSON 协议，供非 Node 集成）、`SDK`（嵌入应用，官方以 OpenClaw 为实例）。
- **F-P5｜模型与供应商**：15+ providers、数百模型：Anthropic / OpenAI / Google / Azure / Bedrock / Mistral / Groq / Cerebras / xAI / Hugging Face / Kimi For Coding / MiniMax / NVIDIA / OpenRouter / Ollama 等；API key 或 OAuth；`/model` 或 `Ctrl+L` 会话中换模型、`Ctrl+P` 轮换收藏；自定义 provider 走 `models.json` 或 extensions。
- **F-P6｜会话树**：sessions 存成 tree，`/tree` 回到任意历史点继续，所有分支在单一文件；可按消息类型过滤、加书签；`/export` 导出 HTML，`/share` 上传 gist 得到可渲染链接（官方给了示例 session）。
- **F-P7｜上下文工程**：`minimal system prompt`（源码 `packages/coding-agent/src/core/system-prompt.ts`）；`AGENTS.md` 启动时从 `~/.pi/agent/`、父目录、当前目录加载；`SYSTEM.md` 可按项目替换或追加默认系统提示；`Compaction` 接近上下文上限时自动摘要旧消息，**可由扩展完全替换**（主题式压缩、代码感知摘要、换摘要模型）；`Skills` 是指令+工具的能力包，按需加载、渐进披露且不破坏 prompt cache；`Prompt templates` 是 Markdown 文件，`/name` 展开；`Dynamic context` 允许扩展在每轮前注入消息、过滤历史、做 RAG 或长期记忆。
- **F-P8｜人工介入**：运行中提交消息，`Enter` 发 **steering message**（当前工具执行后送达，并中断排队中的剩余工具）；`Alt+Enter` 发 **follow-up**（等 agent 完成）。
- **F-P9｜扩展原语**：`Primitives, not features` —— 扩展是可访问 tools / commands / keyboard shortcuts / events / full TUI 的 TypeScript 模块，官方提供 **50+ examples**，示例覆盖 sub-agents、plan mode、permission gates、path protection、SSH execution、sandboxing、MCP integrations、custom editors、status bars、overlays。文档 `https://docs.pi.dev/latest`，源码 `https://github.com/earendil-works/pi`。

## Claude Code 权限（https://code.claude.com/docs/en/permissions，官方文档）

> 该页返回 53.8 KB，被工具折叠成 `<persisted-output>`；完整原文已从持久化文件恢复并按章节切成 3 片（`../raw/02-02-claude-code-permissions-p1..p3.md`）。

- **F-C1｜六种 permission modes**：`default`（每个工具首次使用提示；CLI/VS Code/JetBrains/desktop 标为 Manual，接受别名 `manual`）、`acceptEdits`（自动接受文件编辑与 working directory / additionalDirectories 内的常见文件命令 `mkdir` / `touch` / `mv` / `cp`）、`plan`（只读探索，不编辑源文件）、`auto`（不做例行提示，由后台 classifier 在 shell / network 动作前审核）、`dontAsk`（自动拒绝本会提示的调用，但已安装 mod 仍可批准部分；`AskUserQuestion`、需用户交互的 MCP、network paths、组织设为 ask 的 connector 仍被拒）、`bypassPermissions`（跳过提示，包括对 `.git` / `.claude` 等 protected paths 的写入；官方强调只应在容器或 VM 等隔离环境使用）。新会话默认模式由 `defaultMode` 设置。
- **F-C2｜allow / ask / deny 优先级（官方原文）**：`Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the outcome, and rule specificity doesn't change the order.` 宽泛 deny 如 `Bash(aws *)` 会压过更窄的 allow；`Permission rules are enforced by Claude Code, not by the model.`（prompt / `CLAUDE.md` 只影响模型尝试做什么，不能改变允许什么）。bare 工具名 deny 会把工具从 Claude 的 context 里移除；scoped deny 只拦截匹配调用。
- **F-C3｜配置形状**：`settings.json` 顶层 `permissions.allow` / `permissions.deny` 字符串数组（该页**未给出 `permissions.ask` 的 JSON 示例**）。相关键：`defaultMode`、`additionalDirectories`、`disableBypassPermissionsMode` / `disableAutoMode`（设为 `"disable"`）、`denyInsteadOfPrompting`、`blockReadsOutsideWorkingDirectories`、`blockWritesOutsideWorkingDirectories`（需 v2.1.314+）、`sandbox.autoAllowBashIfSandboxed`、`allowManagedPermissionRulesOnly`。永久「Yes, and don't ask again」规则写入 git 仓库根 `.claude/settings.local.json`；文件修改批准只持续到 session end。
- **F-C4｜settings precedence**：`Permission rules follow the same settings precedence as all other Claude Code settings, with managed settings highest: no other level, including command line arguments, can override a managed permission rule.` 任意层级 deny 都不能被其他层级 allow；managed deny 不能被 `--allowedTools` 覆盖，`--disallowedTools` 只能追加限制。项目的 `permissions.allow` / `additionalDirectories` 需先通过 workspace trust dialog 才生效；`deny` / `ask` 不受 trust 影响。
- **F-C5｜工具白名单语法**：`Tool` 或 `Tool(specifier)`；`Bash(*)` 等价于 `Bash`；`Bash(npm run *)` 按第一个 `*` 之前的文本匹配，尾部 `*` 前有空格时还能匹配 bare command；支持 `Agent(model:opus)` / `Agent(isolation:worktree)` / `Bash(run_in_background:true)` 这类按顶层 input 参数匹配（不覆盖 `command` / `file_path` / `url` 等主内容字段）；deny/ask 支持工具名 glob（`"*"`、`"mcp__*"`），allow 只接受 `mcp__<server>__*` 这类锚定形式。复合命令（`&&` / `||` / `;` / `|` / `&` / 换行）中每个子命令都必须被 allow；固定 wrappers（`timeout` / `time` / `nice` / `nohup` / `stdbuf` / `command` / `builtin` / `noglob` / bare `xargs`）会被剥离；`npx`、`docker exec`、`mise exec` 等 **不在**剥离列表。Read/Edit 路径规则用 gitignore 语法（`//` 文件系统根、`~/` home、`/` settings source 相对、`./` cwd 相对）；`Write(path)` / `Glob(path)` / `Grep(path)` 不会按路径规则匹配，须改用 `Edit(...)` / `Read(...)`。
- **F-C6｜沙箱与权限互补（官方原文）**：`Permissions and sandboxing are complementary security layers` —— permissions 控制可用工具与可访问文件/域名，sandboxing 提供 **OS-level** 的 filesystem / network 限制（覆盖 Bash、PowerShell、Monitor 及其子进程）；两者应同时启用做 defense-in-depth，即使 prompt injection 绕过模型决策，sandbox 限制仍生效。`sandbox.autoAllowBashIfSandboxed=true` 时沙箱内 Bash 免提示（plan mode 例外）；`WebFetch(domain:*)` 会改变沙箱可达 host，bare `WebFetch` 不会；单靠 WebFetch 规则不阻止 `curl` / `wget`。
- **F-C7｜hooks 在权限链中的位置**：`When Claude Code makes a tool call, PreToolUse hooks run before the permission prompt, for every tool except EndConversation.`；hook 输出可 deny、force a prompt 或 skip the prompt；但 `PreToolUse hook decisions don't bypass permission rules.` —— deny/ask 规则仍评估，managed deny 优先；blocking hook（退出码 2）在权限规则评估前停止调用，因而优先于 allow rules。plan mode 下除 `ExitPlanMode` 外，hook 的 `"allow"` 不能放行 file edit。**该页没有出现 `PermissionRequest` hook 事件的定义**（只提到 `--permission-prompt-tool`、Agent SDK `canUseTool` callback、mod 的 `tool.check`），而 `hooks-guide` 页面列出了 `PermissionRequest` —— 两页不冲突，但引用触发时机时应以 hooks-guide 为准并注明来源页。
- **F-C8｜官方 JSON 示例（逐字）**：`{"permissions":{"allow":["Bash(npm run *)","Bash(git commit *)"],"deny":["Bash(git push *)"]}}`；`{"permissions":{"deny":["mcp__*"]}}`；PowerShell 版 `Get-ChildItem *` / `Remove-Item *`；`{"permissions":{"allow":["WebFetch"]}}`（保持 sandbox allowlist 不变）；`{"permissions":{"deny":["Agent(Explore)"]}}`。

## DeepSeek Harness 架构（https://deepseekharness.online/en/guide/architecture，官方 Handbook Chapter 16）

- **F-D1｜产品即插件树**：`At startup it hangs plugins onto a tree one by one, and the product is what that tree looks like when it runs.` 模型、工具、会话、沙箱、存储、界面都是树上的节点；modding 不是打补丁而是「挂一个插件」，`Mount it and it takes effect; take it off and things go back`。换模型/沙箱/整套界面不需要动其余部分。
- **F-D2｜启动四层配置（优先级由低到高）**：`bundles in the profile` → `the profile's own patch` → `the home-level patch` → `temporary overrides from the command line --patch`。术语：profile = 命名组合（如 `web` / `headless`），列出用哪些 bundle 并存自己的改动；bundle = 可分发的配置+挂载代码；patch = 只写「要改哪一项」而非整份配置。自省命令 `dsh --profile web --dump-config`，打印出的每一项都能被自己的 patch 覆盖。
- **F-D3｜四种运行模式（官方表）**：`Standard`（全套工具，日常默认）、`PTC`（Programmatic tool calling，模型写一段代码把多轮调用组合起来，适合「多工具调用且步骤固定」的批量任务；官方说觉得「步骤太多太慢」时再试）、`Minimal`（只留 1 个 shell + 1 个文件编辑工具，比较模型能力 / 最小环境测试）、`Creative`（在内存里试插件并组合新模式，开发插件与实验）。
- **F-D4｜append-only 会话日志**：写入模型看到的全部内容 —— system prompt、thinking process、tool calls and their results、sub-agent dispatch、every context injection；`write forward only, never rewrite history`，可完整重放。界面 trajectory view 按来源浏览；**resume / fork / retrieval / replay 共用同一事件流**，不是四套数据。
- **F-D5｜seam（可替换能力）**：三角色 `Definition`（接口）/ `Provider`（实现，如本地文件系统或远程沙箱）/ `Consumer`（使用方，如 shell 与文件编辑）。把 execution world 的 provider 从本地换成远程沙箱，shell、terminal、language service 一起迁移，无需为每件工具单独写远程版本。
- **F-D6｜核心包职责**：`core/session`（append-only 日志与存储）、`core/system-prompt`（prompt 分段与工具描述组装）、`core/tools`（工具注册表 + **gated execution pipeline**）、`core/agent` / `core/agent-loop`（Agent 接口与默认循环驱动）、`llm/llm`（消息与流式输出、模型适配器所在处）。
- **F-D7｜三个常见误解（官方辟谣）**：插件树 ≠ 微服务（单进程内通过 services/events 协作，不走网络）；一切皆插件 ≠ 什么都要自己装（发行版自带完整 assemblies，开箱即用）；modding ≠ 改源码（挂插件 + 写 patch，源码一行不改）。延伸阅读：`docs/architecture.md`、`docs/capability-seams.md`、`docs/cordis-primer.md`（均在 `github.com/deepseek-ai/deepseek-harness/blob/master/docs/`）。
