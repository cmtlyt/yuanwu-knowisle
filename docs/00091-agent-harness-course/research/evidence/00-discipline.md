## 0. 可信级别与引用纪律

| 级别 | 含义 | 在正文中的写法 |
|---|---|---|
| **A** | 官方仓库 / 官方文档 / 官方产品页 / 基准发布者的一手数据 | 直接陈述，附官方链接 |
| **B** | 可复核的第三方分析：公开原始记录、公开 `runs.csv`、作者复算、带统计检验的实测 | 陈述时注明「第三方实测 / 作者复算」并附链接 |
| **C** | 二手转述、社区文章、媒体报道、搜索引擎摘要 | 只作背景或定性描述，必须写「据…报道 / 转述」，不单独承担关键结论 |

**硬性纪律（写进课程方法论章）**：

1. 不把 **p = 0.14** 的差距写成「A 比 B 强」；原文口径是 *a consistent lean, not a proven gap*。
2. 不混用两套基准的分数与成本：Bug Hunt Bench 是「105 个预置 bug 中修好几个」，Harness Leaderboard 是「两基准任务解决率均值」；`cost per run` 与 `cost per solved task` 也不同。
3. 「每解出一题成本」存在**两种聚合口径**（见 F-B4），两者数值不同但都可复核；正文必须写明用了哪一种。
4. 官方自称的产品能力（star 数、平台数、工具数）与第三方实测表现分开写；star 数等易变指标必须带快照日期与来源。
5. 所有关键结论在正文里夹带可点击原文链接（用户明确要求）。
