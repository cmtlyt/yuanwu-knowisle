## 判定规则（唯一标准：这节课的交付物是「理解」还是「物」）

| 课型 | 判定条件 | 模板（00052 §2） |
|---|---|---|
| `theory` | 本节课交付**理解**：机制、为什么、辨析、选型。`goals` 用「理解 / 掌握 / 认识 / 区分 / 了解」，不要求产出可运行物 | 动机 → 机制 → 对比表 → 不适用面 → 经验 |
| `practice` | 交付**可运行物**：`goals` 至少含一个实现类动词（实现 / 写出 / 写一个 / 搭 / 搭建 / 构建 / 跑通 / 调通 / 部署 / 编码 / 改造 / 接入 / 从零） | 需求与不变量 → 接口 → 逐步实现 → 可跑验证 → 经验 |
| `framework` | 交付**对照结论**：手写版 vs 框架版双实现 + 差异度量 | 手写回顾 → 框架等价代码 → 差异对照 → 何时选/退 |
| `scenario` | 交付**某个真实场景的端到端系统**（编码 / 数据 / 研究 / GUI / 语音 / 生产运维） | 场景 → 模块边界 → 关键实现 → 端到端 → 评测/安全切面 |
| `capstone` | 交付**完整项目**（含验收断言） | 场景 → 需求分层 → 契约骨架 → 状态机 → 验收断言 → 交付物 |
| `overview` | 整节职责是**地图 / 全景 / 收束**，不产实现 | 知识地图 / 选型全景（四道护栏见 00052 §2.1） |

**两条硬判据（进闸门）**：

- **H1**：标题含「实战」→ 课型只能是 `practice` / `framework` / `scenario` / `capstone`，
  **禁止 `theory` / `overview`**（标题自己说了要动手，不能标成纯知识课）。
- **H2**：课型为 `practice` → `goals` 必须至少含一个实现类动词，否则是「知识课冒充实战课」。

H1 抓「标题说实战、标注说理论」，H2 抓「标注说实战、目标只有理解」。两条都不看当前正文字数
——**体量是待办，课型是身份**；用体量反推课型会让「还没重写」被误判成「标错了」。

## 附带发现：24 节课的代码块整体渲染错位（已修）

审计时顺手端到端抽查，`L46` 页面正文里出现了 `:::deep`、`:::` 原文——不是容器语法写错，
而是**代码块根本没被识别**，后面的正文全被吞进 `<pre>` 里。

### 根因

CommonMark 规定：反引号围栏的 **info-string 里不能再出现反引号**。历史数据里有 24 节写成
` ``` title="…" note="关键：\`server.tool\` 一句就完成…" `——`note` 里的行内反引号让整行**不再被
识别为围栏**。连锁反应：

1. 围栏开头失效 → 代码被当普通段落渲染（页面上能看到 `import { … }` 变成正文）；
2. 代码块末尾的 ``` 反而被当成「新的围栏开头」→ 把后续 Markdown（含 `:::deep` 容器、标题、
   列表）全部当作代码内容输出；
3. 阅读体验上表现为「一整节后续内容被塞进一个代码框里，里面还混着 md 语法」。

### 影响面

`grep` 全量扫描：**24 节**命中（L03 / L05 / L06 / L08 / L11 / L30 / L35 / L36 / L37 / L39 / L46 /
L47 / L56 / L57 / L60 / L65 / L75 / L95 / L100 / L106 / L108 / L109 / L110 / L111）。这些课的
代码块从 00053 迁移起就是错的，但此前只抽查了少数几节（都恰好没有反引号），一直没暴露。

### 修复（三层）

1. **数据**：把 info-string 内的行内反引号批量改为中文引号「」——`note` / `title` 只输出成纯文本
   （`code-title` / `code-note`），换引号视觉等价、不损失信息。24 行全部改完，全仓再扫为 0。
2. **渲染兜底**：`app/lib/markdown.ts` 新增 `normalizeFenceInfo()`，在 `renderMarkdown` 前把
   info 段的反引号换成「」。数据侧已修，这层是防回归——将来重写课时再写回反引号，页面也不会崩。
3. **校验**：`content-gate.mjs` 新增硬校验「围栏 info 不得含反引号」，命中即失败并点名课号 + 行号。

### 验证

- 全仓扫描：`info` 含反引号 **0 处**；渲染后行首 ``` 泄漏 **0 节**。
- 端到端（重建 + wrangler 3199）：L46 / L56 / L03 由「1 个代码块 + 正文混 md」恢复为
  「2 个代码块 + 3 个 callout」，`:::` 残留归零。
- 反向确认：把 L46 的 note 临时改回反引号 → 闸门点名 `L46 第 23 行`。

### 顺带修掉的一个自伤写法

`L13` 的 `parseArgs` 示例原本用「正则去掉三个反引号围栏」来容错，导致示例代码自身含 ``` 序列，
既容易被工具误判、也不便阅读。改为「先直接 `JSON.parse`，失败则取第一段 `{…}` 再试」——
容错效果更好，也不再需要显式写围栏字符。
