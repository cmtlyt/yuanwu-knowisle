### 2. 五课重写内容

统一的写作顺序（`00052 §1` 三元标准 + 课型模板）：

- **theory（L12 / L14 / L16）**：动机 → 机制 → 变体 / 同类对比表 → 不适用面 → 反直觉点 → 经验
- **practice（L13 / L15）**：需求与不变量 → 接口与环境探测 → 逐步实现（代码 ↔ 解释交替）→
  可跑验证 → 边界与失败 → 经验 → 改错题

各课补的具体缺口（不是加通用论述）：

| 课 | 要补的实质内容 |
|---|---|
| L12 | 为什么「步骤未知且依赖观测」必须交替；Thought 参与决策的机制与消融证据；ReAct / CoT / P&E / ReWOO 四者对照表；四类不该用的场合；工具描述写法对召回率的影响 |
| L13 | 把三段代码补成可跑闭环：`parseReAct` 的容错分支（多行 Thought、参数 JSON 退化、finish 的两种写法）、观测的注入形式（tool 角色 vs 文本拼接）、`maxSteps` 之外的超时与重复调用检测、假 client 的确定性测试 |
| L14 | 计划粒度（步骤数 vs 原子性）的取舍；计划失败的两类原因（拆错 / 世界变了）；重规划的触发条件；plan 与 execute 的上下文隔离（为什么要重写 system） |
| L15 | 与 L13 跑同一任务做对照：同一 fake client 下两套循环的调用次数、上下文长度、失败模式；把「谁更省」变成可测数字而不是感觉 |
| L16 | ReWOO 的 Planner / Worker / Solver 三段与变量引用（`#E1`）；为什么它能省往返但怕「变量依赖错」；与 P&E 的边界；失败恢复要靠重规划而非重试 |

### 各课补的实质内容

- **L12（ReAct）**：把「为什么必须交替」讲到「步骤依赖观测」这一根因上，补 Thought 参与决策的
  机制与消融证据（简单任务几乎不掉、多步任务掉得最狠）、CoT / ReAct / P&E / ReWOO / Reflexion
  五者定位表、四类不适用场合、工具描述对召回率的影响，以及三条典型失败（观测注入、编造
  Observation、重复调用）的现象 / 根因 / 检测 / 修复。
- **L13（ReAct 实现）**：从「三段代码」扩成完整闭环——四个不变量、容错解析器（多行 Thought /
  围栏包裹参数 / 两种终止写法）、失败回填为可纠正事件、重复调用折叠、\`tool.run\` 单独超时、
  两种观测注入形式对照（原生 tool 角色 / 文本标记 / 塞进 user 三种的坑）、脚本化 client 的
  两个断言用例、上下文线性增长与三种压缩策略的接口预留。
- **L14（P&E）**：补计划的数据结构要求（可遍历 / 可断言 / 可局部替换）、粒度三分表（太粗 / 合适 /
  太细）、四类优势场合（含「计划即审批接口」与并发起点）、三类不适用、以及「别把完整计划交给
  执行器」这条反直觉约束（跳步现象及其根因）。
- **L15（P&E 实现）**：不做「再写一遍 P&E」，而是做**同任务对照实验**——四个指标（llmCalls /
  inputChars / reasonChars / contextPeak）的采集方式、仪表装饰器、结构性断言，以及一张推翻直觉
  的结果表（3 步任务里 P&E 全指标更贵，只赢 contextPeak）；补 \`expect\` 由谁判定（确定性断言 /
  工具校验 / LLM 评判）与「判不出失败就谈不上重试哪一步」。
- **L16（ReWOO）**：补 Planner / Worker / Solver 三角色、蓝图 JSON 形状、拓扑分层与值级变量替换
  的实现（含缺失槽显式标记）、三范式调用次数与上下文增长对照表、四类依赖故障（引用错槽 / 环 /
  参数污染 / 顺序假设）与「三类静态可查」的结论、以及把 ReWOO 当「更快 P&E」和用它处理长文档
  两种误用。

### 写作时踩到的两个坑

1. **\`fmt:check\` 会卡长行**：md 模板串里的长段落（含中文）不影响，但 goals / quiz 里的长字符串会
   被 oxfmt 要求折行，先写后 \`oxfmt\` 一次比手写折行可靠。
2. **理论课必须显式写 \`:::warn\`**：L14 首版只写了「### 三个坑」的普通小节，渲染抽查才发现没有
   callout——三元标准里的「经验」要求它是独立提示框，普通小节不算。抽查脚本按 \`class="callout"\`
   判定，这条正好被它拦下。
