# 00094 · pitfall-resolver skill 精简

## 目标

用户反馈 pitfall-resolver 占用上下文过多。实测：`SKILL.md` 17,353 字节，其中 `description` 单行 4,537 字节（2,599 字符）、正文 12,765 字节、症状速查表 30 行累计约 5 KB；references 合计约 99 KB。**每次加载 skill 都要吃进 SKILL.md 全文**，而 description 在技能发现阶段进入上下文，两者是主要成本中心。目标：保留「强制闭环 + 症状路由」能力，把 SKILL.md 与 description 压到原来的 1/4 左右；references 保留原明细，改为按需检索。

## 变更计划

1. **description**：从逐条枚举错误码/工具名的 2,599 字符，压缩为一句触发规则 + 少量高信号关键词（约 400 字符）；具体报错原文交给正文速查表与 references，不在发现阶段加载。
2. **正文**：
   - 「触发范围」8 条合并为 1 段；
   - 「使用方式」5 步压缩为 5 行（强制语义不变：先加载 → 按症状只读命中文件 → 一次修复并回归 → 最终答复前强制回写 → 同步口径）；
   - 「症状速查」由 30 行关键词堆叠改为**按参考文件分组的 10 行主题路由**，每行保留该文件的高信号关键词，并明确「只读取命中的文件、不要全量展开 references」；
   - 「回写规则」表格 + 6 条细则压缩为 3 条要点（症状/根因/实测处理三要素、查库未命中也要回写、命令可复制且一次性内容不入库）；
   - 「与 course-builder 的关系」压为 1 行。
3. **references 全部保留原明细**（它们是按需读取的知识本体，不在加载时进入上下文）；在正文强调按关键词定位章节即可。
4. 按 §1 强制闭环回写：在 `references/toolchain.md` 新增简短条目「skill description / 速查表过大 → 主题级路由 + 按需读」，并在速查表登记关键词。
5. 顺带修正 AGENTS.md §8 的失真数字「6 个主题参考文件」→「9 个主题参考文件，按症状按需读取」（活文档直接校正）。

## 验证方案

- 字节数对比：SKILL.md 总大小、description 行、正文分别记录前后数值，目标 SKILL.md ≤5 KB、description ≤600 字节。
- frontmatter 三字段（name / description / agent_created）完整且 YAML 合法；skill 工具仍能加载。
- 门禁：`pnpm fmt:check` / `pnpm lint` / `pnpm typecheck`（md 不进 oxfmt，确认无误伤）。
- 闭环核对：四条强制语义（先加载 / 强制回写 / 回归顺序 / 未命中也回写）在压缩后全保留。
