## 这一批补的是什么

四节共用一套搜索术语（节点 / 扩展 / 评估 / 回溯 / 剪枝 / 预算），每节解决一个上一节留下的缺口：

- **L19**：立骨架。补 ToT 的成本公式（b×w×d 的具体调用量）、三种搜索形态（BFS / DFS / beam）的
  内存差异、评估器三种来源的可靠性梯度（同状态三次打分是否一致），以及「24 点 4%→74% 为什么搬不动」
  的前提分析。原文只说了「四步」，没说四步要花多少钱。
- **L20**：补结构缺口。原文只讲「图比树灵活」，没说清「树的分支永不汇合」这个具体形状（多源调研 /
  多文件审查 / 三分支评估），也没给聚合的四种语义（并集 / 投票 / 加权 / 消解矛盾）。新增「GoT 其实是
  map-reduce」的成本解释与「聚合输出≈输入总长就是没聚合」的判定法。
- **L21**：补决策依据。原文把 MCTS 四步列了一遍就结束。新增 UCB 的具体算例（A 0.8/40 次 vs B 0.5/2 次，
  B 反而优先）、「剪枝不可逆 vs 只降权」这个 ToT/LATS 的本质差异、把成本换算成钱的判据（¥4.5/题 vs
  返工 ¥50）、以及 Agent 上比围棋难的三条结构性原因。
- **L22**：补三个组件为什么必须同时在（自动课程管「做什么」、技能库管「以前怎么做」、迭代提示管
  「这次为什么失败」）、「跑通 ≠ 达成目标」的验证纪律、技能库三种腐化形态的治法治，以及「存代码」
  为什么既强又脆（可执行 → 也是不可信输入边界）。
