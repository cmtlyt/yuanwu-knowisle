# Wave 1 第二十二批：Stage 24 生态两课（L121–L122）

## 目标

重写模块八的生态速览两课。风险是写成「供应商名单 + MCP 市场目录」——这类内容两周就过期，且读者看完仍不会做决定。

统一定位：**生态是「会变的依赖」，不是「固定的能力清单」**。两课各自给一条判断框架：

| 课 | 判断框架 | 结论形态 |
|---|---|---|
| L121 | 每接一个第三方 MCP Server，等于把一段你没有代码审查权的可执行逻辑放进信任边界 | 准入登记表 + 漂移检测 |
| L122 | 模型是带版本、带行为契约的依赖，不是一串可以随手换的模型名 | 能力契约 + 行为指纹自检 |

按 00055 下限：theory = 正文 **1200 字** / 代码 **400 字符**；余量 >50；每课 ≥1 表格、≥2 独立 `:::deep` / `:::warn` callout、≥1 可运行代码块。

## 课型复核（本批重点）

两课标题都带「速览」，直觉上像 `overview`。**但不改课型，维持 `theory`**，理由三条：

1. **交付物是判断框架，不是地图**。overview 的定位（00055）是「地图与路径，400 字足够铺开要点与依赖关系」；这两课要交付的是「准入评估怎么做、能力契约怎么维护、漂移怎么发现」，属于可操作的方法论，400 字会逼成空话。
2. **overview 有硬约束**：总量不超过总课时 8%、每模块最多 1 节、必须写 `kindReason`、免实现代码免测验。模块八已有 L93 之外的收束课，把两节都改成 overview 会挤占额度且丢掉测验。
3. **两课都有可运行物**（登记表校验器、能力契约自检），但它是**用来支撑判断的示意代码**，不是本课交付的产品。按 00058 的判定口径看「交付物是理解还是可运行物」→ 理解为主，`theory` 成立。保持 goals 用「理解 / 掌握 / 认识」，不写实现类动词。

沿用作者原标注，本批不改动 kind。

| L122 | 供应商与模型变了以后，系统凭什么还能按原契约工作 | 路由算法（L88/L89）、对照实验（L94） |

## 术语统一

- **信任边界外移**：接入第三方 server 后，执行逻辑的归属从本团队代码变成外部代码。
- **能力漂移**：同一工具在不同版本下参数、返回结构或权限范围变了，而调用方无感。
- **能力契约（ModelProfile）**：把模型 id、版本、能力项、行为指纹、兜底策略固化成可校验的依赖声明。
- **行为指纹**：固定探针集上的输出特征，用来发现「名字没变但行为变了」。

## 变更计划

1. L121：以「某 server 悄悄改了返回范围，把不该读的目录读进上下文」开场；给三类风险表 + 准入登记表与漂移检测代码；讲「工具市场不是 npm 包市场」；给自建 vs 现成的取舍判据。
2. L122：以「供应商下线模型，四个 Agent 凌晨 404；同名模型行为差 9 点」开场；给四类生态风险表 + `ModelProfile` 与启动自检代码；讲「换模型名就行」为什么错；给「清单会过期，判据不会」的维护方式。
3. 每课末尾单列「与相邻课的分工」；不新增 concepts id（两课 id 均已注册）。
4. 双扫描、渲染抽查、`--update-baseline`、三门禁。

### 实际写出的内容

两课都刻意**不列会过期的名单**，只给可复核的判据：

- **L121**：三类风险表（能力漂移 / 权限过宽 / 供应链）、\`ServerManifest\` 准入登记表 + \`assertAdmissible()\`（精确 ref、负责人、schema 指纹、目录白名单、90 天复评）、\`detectDrift()\` 三档处置（结构变化告警 / 新增写能力阻断 / 越界路径阻断）、自建 vs 现成四维取舍表。主结论：**工具市场不是包市场——工具是运行时由模型自主选择，人不在回路上**，因此需要持续漂移检测而非一次性准入。
- **L122**：四类生态风险表（下线改名 / 行为漂移 / 定价配额 / 数据驻留）、\`ModelProfile\` 能力契约 + \`assertProfile()\`（版本锁定 / 兜底能力对齐 / 兜底不能同供应商 / 复评期）、\`fingerprint()\` 固定探针集 + \`assertBehavior()\`、能力/成本/延迟/合规四维选型表。主结论：**兼容接口只保证请求能收发，不保证行为一致**；「换个模型名就行」会把静默退化藏进 100% 可用率里。

### 课型复核结论

维持 \`theory\`，未改 \`overview\`。两课的正文虽含可运行代码，但代码是支撑判断的示意（登记表校验器、契约自检），交付物是「凭什么信任 / 凭什么切换」的方法论；goals 保持「理解 / 掌握 / 认识」，未写实现类动词。这符合 00058「看交付物是理解还是可运行物」的判定口径。
