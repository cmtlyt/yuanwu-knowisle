## 目标

重写模块七第三个框架专论（3 课）。Mastra 的定位与前两个框架不同：它不是「编排范式」，而是
**一套 TS 原生的成套件**（agent + workflow + memory + rag + observability + MCP + server）。

这带来一个特定的写作风险：容易写成「包清单」。所以本批三课的统一定位是——**成套的代价是
抽象层数，收益是拼装成本**，每课都要回答「这一层的抽象值不值」。

## 术语统一（Stage 19 共用）

- **成套件（suite）**：把 agent / workflow / memory / rag / 观测 / 服务打包在一起的框架形态。
  与前两个框架（范式型、SDK 型）相对。
- **抽象层数**：从你的业务代码到模型调用之间隔了几层。层数本身不是好坏，**绕行成本**才是。
- **成套的隐形成本**：每多接一个包，就多一份版本约束、多一个泄露面、多一处「它在背后做了什么」。
- **workflow ≠ P&E**：workflow 是「步骤与数据流」，P&E 是「计划由模型生成并可重规划」。
- **零埋点**：框架自动采集追踪，不需要写 span 代码。代价是粒度与字段由框架决定（L99 同款问题）。

   「谁功能全」）。

   重规划能力、可观测）。
3. L105：讲 MCP server 的声明式注册（对比 L45 手写协议）、内置追踪的零埋点与三项验证（L99 的

4. 每节 ≥1 表格、≥2 独立 callout、≥1 可运行代码块；渲染抽查；`--update-baseline`；全门禁。
