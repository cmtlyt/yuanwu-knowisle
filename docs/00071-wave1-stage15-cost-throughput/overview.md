## 术语统一（Stage 15 共用）

- **单位成本**：一次成功任务的平均花费（不是单次调用花费）。它是所有优化的统一标尺。
- **误路由（mis-route）**：把难任务交给了弱模型（或反之）。前者伤质量，后者伤成本。
- **级联（cascade）**：先小模型试、不达标再升大模型。与「路由」的区别是级联允许重试升级。
- **语义缓存**：按向量相似度命中的缓存；与「精确缓存」（key 完全相等）相对。
- **前缀复用（prefix caching）**：同一段前缀在不同请求间复用已计算的 KV，省的是计算与延迟。
- **有界并发**：限制同时进行中的请求数，避免把上游打到限流。

### 与原变更计划的偏差

1. **L90 增加语义缓存的业务闸**：原计划只写「阈值 + 失效」，实测发现调阈值永远救不了
   「同类但不同实体」的误命中（A 产品 vs B 产品的保修期），因此补了 `NEVER_CACHE` 清单与
   `admissible()` 业务闸——**不可缓存清单比调阈值有效**，这是原计划漏掉的一层。
2. **L91 把「动态裁剪」的风险写成系统性偏差**：原计划只说「按相关性丢历史」，实测发现
   否定型约束（「不要打电话」）在向量空间里天然排在 top-K 之外，因此补了正则 pin / 打标 /
   结构化 constraints 三种堵法，并说明第三种最贵最稳（每轮多约 200 token）。
3. **L92 把「重试放大」提为独立小节**：原计划归在「并发一致性」里，实测认为它更该单独讲——
   并发下每请求各自重试会把瞬时流量放大到 N 倍，这是那次 55 分钟事故的直接机制。
4. **L92 的代码量偏大（7 块）**：因为公式（利特尔法则、凑批等待）用缩进代码块呈现，
   计入 codeBlocks 但不计入 codeChars；正文 2366 字仍有 1166 字余量，不擦线。
