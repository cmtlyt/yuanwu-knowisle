# Wave 1 第二十五批：Stage 1 概念四课（L06–L09）

## 目标

重写课程概念阶段四课（全部 `theory`）。这四课最容易写成同义反复：L06 说「Agent 是能自主决策的系统」，L07 说「Agent 由模型和工具组成」，L08 又说「模型决定下一步」，L09 再重复一遍「不是所有任务都适合」。读者看完四节只记住一句正确的废话。

统一定位：**四课是同一个问题的四个递进追问，各占一层，不许越界**。

| 课 | 唯一要回答的问题 | 明确不讲 |
|---|---|---|
| L06 | 什么**不是** Agent（用三个反例划出边界） | 组件清单、内部实现 |
| L07 | 一个 Agent 由哪几个组件构成、接口在哪 | 决策权归属（L08）、选型（L09） |
| L08 | 把下一步的决定权交给模型，架构会**因此**改变什么 | 组件定义、什么时候用 |
| L09 | 什么任务**不该**用 Agent，判据是什么 | 架构细节、框架选型 |

按 00055 下限：theory = 正文 **1200 字** / 代码 **400 字符**；余量 >50；每课 ≥1 表格、≥2 独立 `:::deep` / `:::warn` callout、≥1 可运行代码块。

## 课型复核

四课交付物是**理解与判据**（边界、组件图、架构后果、选型清单），不是可运行产品 → `theory` ✓，沿用原标注。代码示例是判据的示意，不作为交付物；goals 保持理解类动词，不写实现类动词（00058 H2 只约束 practice）。

概念 id 已从 `git show HEAD` 对照原骨架确认并沿用：`agent-boundary` / `agent-components` / `model-decides` / `agent-selection`，均在 `concepts.ts` 注册，本批不新增概念。

## 术语统一

- **控制权归属**：下一步做什么由谁决定——人写的规则，还是模型基于观察的判断。
- **动作空间**：当前这轮里模型可选择的工具/动作集合（L85 会收口成最小权限）。
- **观察回流**：动作结果重新进入下一轮决策，形成闭环。
- **不可判定性**：同一输入可能走不同路径、产出不同结果，因而无法用固定调用序列做断言。

## 变更计划

1. L06：三个反例（定时脚本 / 单次摘要 / 规则路由）+ 一个正例，提炼「模型决策 + 动作空间 + 观察回流」三条必要条件；给可运行对照代码。
2. L07：六个组件的职责与接口表 + 组件装配代码；讲「接口比组件本身重要」，并和 L04 的四段骨架逐项对应。
3. L08：五个架构维度（控制流 / 失败模式 / 测试 / 容量 / 安全）的传统 vs Agent 对照；给确定性管线与模型决策循环的代码对照；讲「不确定性从数据进入控制流」。
4. L09：四类任务的选型表 + 评分函数 + 反例回归断言；讲「能写成断言的逻辑不要交给模型」。
5. 每课末尾单列「与相邻课的分工」；双扫描、渲染抽查、`--update-baseline`、三门禁。

### 四课防重复的实际效果

四课是同一个问题的四层递进，每课只在自己的层里回答：

- **L06**：三个反例（定时脚本 / 单次摘要 / 规则路由）+ 一个正例，提炼三条必要条件——模型决策下一步、动作空间、观察回流；并给 RAG 问答、带工具单次调用两类灰度情形的判据（决策是否基于上一步结果）。核心句：**下一步由谁决定**。
- **L07**：六组件表（主链四组件 + 观测旁路 + 两道护栏）+ 组件接口与装配代码；核心句：**接口比组件本身重要**，自检是「换实现要改几个文件」。
- **L08**：五维对照（控制流 / 失败模式 / 测试 / 容量 / 安全）+ 确定性管线与决策循环的代码对照；核心句：**不确定性从数据进入控制流**，由此推导出预算、轨迹、幂等、分布级断言、p95 容量五条后果。
- **L09**：四类任务选型表 + 五个否决项 + \`shouldUseAgent()\` 评分函数 + 运费纯函数精确断言；核心句：**能写成精确断言的逻辑不要交给模型**。

四句分别落在「识别 / 结构 / 后果 / 决策」四层，没有互相复述。每课末尾的「与相邻课的分工」逐条写明引用了哪些课、明确不讲什么。
