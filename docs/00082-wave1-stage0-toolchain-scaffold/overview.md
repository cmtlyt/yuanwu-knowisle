# Wave 1 第二十四批：Stage 0 工程准备四课（L02–L05）

## 目标

重写课程最前面的工程准备阶段（4 课，全部 `practice`）。这一批的特殊性：它是全课**唯一在讲「动手之前」**的阶段，后面 130 多课的可运行代码都默认读者已经有了一个可复现的环境。写得含糊，后面所有「照着跑一遍」的承诺都会失效。

风险是写成「安装教程」——列几条命令就完事，或者反过来把四课都写成同一件事（装环境）。统一定位：**四课按「装什么 → 锁什么 → 跑什么 → 埋什么」串成一条链，共同交付一个可复现的最小工程**，且每课都留下一条可执行的验收断言。

| 课 | 链上位置 | 唯一要回答的问题 | 明确不讲 |
|---|---|---|---|
| L02 | 装什么 | 运行环境怎么固定，才不会「我这能跑你那不能」 | 语言语法、框架选型 |
| L03 | 锁什么 | 依赖与版本怎么锁，才不会上游悄悄改行为 | 包管理器原理 |
| L04 | 跑什么 | 最小 Agent 工程长什么样，哪几行才是 Agent 逻辑 | 框架用法（模块七才讲） |
| L05 | 埋什么 | 观测与评测字段为什么必须在第一版就预埋 | 仪表盘 UI（L72）、harness 实现（L81） |

按 00055 下限：practice = 正文 **1800 字** / 代码 **1500 字符**；余量 >50；每课 ≥1 表格、≥2 独立 `:::deep` / `:::warn` callout、≥1 可运行代码块。00058 H2 要求 practice 的 goals 必须含实现类动词，四课逐条核过。

## 课型复核

四课交付物都是可运行物（环境契约校验脚本、锁定表校验、最小 loop 工程、预埋的 EventLog 与冒烟测试）→ `practice` ✓，沿用原标注。goals 含「搭好 / 写出 / 跑通 / 接入」等实现动词，通过 00058 H2。

## 术语统一

- **环境契约**：把 Node / TS / 包管理器 / tsconfig 的固定取值写成可被 CI 读取的声明。
- **版本锁定表**：课程用到的关键依赖及其精确版本，独立于 lockfile 便于人工复核。
- **最小 Agent 工程**：只有「模型调用 → 工具分发 → 循环 → 退出」四段，不含框架、不含数据库。
- **预埋**：在第一版代码里就记录后续观测与评测需要的字段，不等功能写完再补。

## 变更计划

1. L02：以「同一份代码两台机器跑出不同结果」开场；给环境契约（\`engines\` / \`.nvmrc\` / \`tsconfig\` 固定 target 与 lib）+ CI 校验脚本；讲「固定环境是复现的前提，不是洁癖」。
2. L03：以「上游小版本改了工具调用返回格式」开场；给版本锁定表 + 安装前校验（禁 floating specifier / lockfile 完整性 / peer 一致）+ 升级流程；讲「锁定的是行为，不只是数字」。
3. L04：以「脚手架一上来带框架，读者分不清哪行是 Agent 逻辑」开场；给目录骨架、手写 \`runLoop()\`、工具分发、冒烟测试；讲「最小工程的价值在可指认」。
4. L05：以「功能写完再接 trace，关键字段没记、无法回填」开场；给 \`EventLog\` 字段表、span 埋点、golden case 采样钩子；讲「预埋的成本几乎为零，补埋要重跑所有历史」。
5. 每课末尾单列「与相邻课的分工」；不新增 concepts id。
6. 双扫描、渲染抽查、`--update-baseline`、三门禁。

### 实际写出的可运行物

- **L02**：\`package.json\` / \`tsconfig.json\` / \`.nvmrc\` 三份固定取值、 \`check-env.mjs\`（Node 主版本、编译目标四项、包管理器、CI 时区）、\`smoke.mjs\`（五项运行时能力）、环境升级五步流程。补写了「容器与契约的关系」——教学上要显式摊开差异，生产上才用容器 + 契约双保险。
- **L03**：\`deps.lock.json\` 人工可读锁定表（含 \`usedBy\` / \`owner\` / 复评期）、\`check-deps.mjs\`（浮动版本、锁定表比对、lockfile 完整性、复评期）、\`upgrade-one.mjs\` 五步升级顺序、\`pnpm.overrides\` 与锁文件 diff 评审。主结论：**锁的是一组已验证过的行为，不只是数字**。
- **L04**：六文件目录骨架、\`loadConfig()\`、\`HttpLlmClient\` / \`ToolRegistry\` / \`runLoop\` / \`main\` 四段分离、\`FakeLlm\` 三条冒烟断言、三个可替换接口与「什么时候可以引入框架」判据。主结论：**可指认比能跑重要**，这个骨架是 L94/L97 的 baseline。
- **L05**：\`RunContext\` 四版本号、六类 \`AgentEvent\` 联合类型、\`digest()\` 脱敏、\`runLoop\` 插桩（失败路径也补 \`loop.end\`）、\`goldenFrom()\` 评测采样、\`BufferedSink\`（采样分层 + emit 失败不冒泡）。主结论：**日志是当时唯一的记录，字段必须预埋**。

### 过程中修正的两处

1. **L03 概念 id 自造**：初稿写成 \`dependency-lock\`，而 \`concepts.ts\` 注册的是 \`version-lock\`。用 \`git show HEAD:<file>\` 对照原骨架 + 查 \`concepts.ts\` 后把 concepts 数组与三道测验的 \`concept\` 一并改回，verify 概念引用校验通过。**这是 00075 那类失败的前置拦截**：重写课程时不要凭标题自造概念 id。
2. **L02 Node 版本与概念名不一致**：\`concepts.ts\` 中 \`toolchain\` 名为「TS 7 + Node 24 工具链」，初稿示例写 Node 22。已把 \`engines\` / \`.nvmrc\` / README 示例 / 测验题干统一为 Node 24，并把正文里「旧 LTS vs 新 LTS」的对照改成不带具体版本的表述。课程示例工程与本仓库运行环境是两回事，但**课程内部不能自相矛盾**。

另三课初稿均未过线（L03 1652 / L04 1500 / L05 1628），补的是传递依赖与供应链、骨架演进边界与接口替换点、事件体积与 sink 替换路径三处真实缺口。
