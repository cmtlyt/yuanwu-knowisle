## 目标

把 00051 落地的 142 节 Agent 课，从「单一概念介绍骨架」重构为「**理论 + 代码 + 经验**」三元精品课：

- 每课同时具备：理论（机制 / 为什么 / 边界）+ 代码（可跑 / 可验证、递进多片段）+ 经验（真实踩坑：失败现象 → 检测 → 修复 → 反例）。
- 按 6 种课型（theory 理论 / practice 实战 / framework 框架对照 / scenario 专项 Agent 场景 / capstone 综合交付 / overview 导览收束）分化模板，打破 142 课同构。
- 测验从「纯回忆」升级为「回忆 + 应用 + 改错 + 设计」混合（全部以单选形式承载，见决策 1）。

## 与 00053 的关系（前置使能项，已完成）

`00053` 已将全部 194 课的正文从 `blocks: LessonBlock[]` 改为 `md: string`（Markdown 模板串），并建成渲染层（`app/lib/markdown.ts` + `markdown-md.ts` + `markdown-article.vue`）。关键变化：

1. **书写单位变了**：第 8 位 `md` 模板串（删 `minutes` 后前移一位）；代码用 ```` ```ts title="…" note="…" ```` 围栏、提示用 `:::warn / :::deep / :::tip` 容器。三元结构与课型分化直接在 `md` 内表达。
2. **首次可量化**：`contentStats(md)` 算出 `proseChars` / `codeChars` / `headings` / `callouts` / `codeBlocks`，体量目标与时长推导都以它为准。

`quiz / terms / pitfalls / widget` 仍为结构化字段，未受 00053 影响。

## 诊断证据（为什么需要重构）

对 `app/data/agent-course/lessons/` 的评估（2026-11-15，00053 迁移前测量；迁移为无损转写，内容体量不变）：

| 维度 | 现状 | 结论 |
|---|---|---|
| 单课行数 | 142 课 **100% < 100 行**（min 70 / max 95 / 中位 76） | 容不下三层内容 |
| 内容结构 | 每课恰好 **1 段 prose + 1 代码 + 2 提示 + 1 列表** | 与课型无关，范式课 ≈ Capstone 课 |
| 代码块 | 99% 仅 1 个；其中 **53% 以示意注释起头** | 多为示意片段，少递进、无可跑 |
| 测验 | 100% 是「3 选 1 单选」，正确项 = 正文原话改写 | 零应用层，记忆回溯 |
| 专项 / Capstone（L116–L142） | 多为 ASCII 架构图 + 清单，无真实实现 | 「实战」承诺落空 |

`contentStats` 实测（重构前）：正文中位约 250 字符、代码中位约 420 字符；按体量推导的应然时长仅 9–10 分钟，而课时声明 15–22 分钟。**「看起来 20 分钟的课，实际内容只支撑 10 分钟」**——这是「太简单」的量化证据。

**根因**：用同一套「概念介绍骨架」复制 142 次，结构不随主题深浅变化。

**保留项（不重做）**：概念 DAG / `prereqs` / `Lxx` 互引；`pitfalls` 思路（升级为 `:::warn` 经验块）；模块 / 阶段 / 子阶段；complex 渲染层。重构保持课时 `id` 与概念 `id` 不变，图谱不受影响。

## 变更计划

### 1. 精品课三元标准（每课必备，落在 `md` 正文）

- **理论**：md 段落（机制 + 为什么 + 何时用 / 何时不用）+ `:::deep` 辨析 + **md 对比表**。
- **代码**：md 围栏块，可跑 / 可验证，不止一个、递进（直觉 → 严谨 → 边界）；实战课给完整函数 + 「跑法」注释。
- **经验**：独立 `:::warn` 块 = 失败场景 + 现象 + 根因 + 检测 + 修复 + 反例。

### 2. 课型模板与体量阈值

课型是**课时自己的课程元数据**：每节课在自己的 `lNN.ts` 里用 `withKind(L(...), 'theory')` 标注，阈值表在 `scripts/content-gate.mjs`。下表「当前课数」是 `agent` 课的实际标注结果，不是脚本里另存的映射表，也不从阶段继承。

| 课型 | `agent` 课当前课数 | 正文量下限（`contentStats`） | 结构要点 |
|---|---|---|---|
| **`theory` 理论 / 范式** | 27 课 | prose ≥800 · code ≥400 | 动机 → 机制 → 变体对比表 → 不适用面 → 经验 → 应用题 |
| **`practice` 实战 / 实现** | 62 课 | prose ≥1200 · code ≥1500 | 需求与不变量 → 接口 → 逐步实现（代码 ↔ 解释交替）→ 可跑验证 → 边界 → 经验 → 改错题 |
| **`framework` 框架对照** | 22 课 | prose ≥1000 · code ≥1000 | 手写回顾 → 框架等价代码 → 差异对照表 → 何时选 / 何时退 → 经验 |
| **`scenario` 专项 Agent 场景** | 12 课 | prose ≥1200 · code ≥1500 | 场景 → 模块边界 → 关键模块真实实现 → 端到端 → 评测 / 安全切面 → 生产事故 |
| **`capstone` 综合交付** | 15 课 | prose ≥2000 · code ≥2500 | 场景 → 需求分层 → 契约与骨架 → 状态机 / 编排 → 可执行验收断言 → 交付物与风险登记 |
| **`overview` 导览 / 收束** | 4 节（见 §2.1） | prose ≥400 · code ≥0 | 知识地图 / 选型全景 / 收束回顾，本就不该有实现代码 |

> **只设下限，不设上限。** 阈值是「这节课够不够厚」的护栏，不是「不许写更多」的配额：内容写得多、代码给得全是好事，卡 max 只会逼人为了「不超」而砍掉有价值的实现细节与真实踩坑。同一课型的深浅差异本就可达数倍，上限也判不准。因此 `content-gate.mjs` 只比对 `proseMin` / `codeMin`，不统计也不告警任何 max。

### 2.1 「有些课就是简单介绍」怎么处理

课多必然出现「看起来很简单」的课时。先分清它到底是哪一种，**处理顺序不可颠倒**：

| 情形 | 判定 | 处理 |
|---|---|---|
| **① 主题本来就重，只是写薄了** | 绝大多数（实测 136/142 课 prose <800，最薄的「人在回路」「多租户记忆隔离」「终止与回归」都是能写整章的重话题） | **写厚**，不许降级 |
| **② 内容量确实只有一两段，独立成课是硬拆** | 大纲切分粒度问题 | **合并**进相邻课，或降级为某节课的 `:::tip` 前置阅读；课时数允许减少，不留空壳 |
| **③ 整节课职责就是导览 / 收束** | 全班 4 节：L01 课程地图、L11 范式总览、L79 基准导览、L93 框架全景 | 走 **`overview` 导览课型** |

**`overview` 课型两项都放宽**：`prose ≥400 · code ≥0`。理由——导览课的交付物是「地图与路径」而不是实现：400 字足够铺开要讲哪几件事、彼此什么关系、怎么选；低于 400 说明连要点都没列全，仍是残桩。放宽阈值不靠自我声明兜底——想占这个口子仍要过 overview 四道护栏（理由必填、每模块 ≤1 节、总量 ≤8%、Capstone 禁用），所以「不知道怎么把课写厚」不能伪装成「这节是导览」。

**题目也一并免除**：导览课不设随堂测验（`quiz: []`）。它只负责指路，不承担考核职责；在这类课上凑 3 道回忆题只会制造无效刷题。配套三处改动：

- **渲染**：`lessons/[id].vue` 给「关键术语 / 常见误区 / 随堂测验」三个分区加 `v-if` 空态守卫，否则 0 项会留下空标题。
- **概念覆盖**：`overview` 课承载的概念视为「导览概念」（4 个：`ts-first` / `paradigm-taxonomy` / `benchmarks` / `framework-dimensions`），不进「概念需被题目覆盖」的告警——它们只要「知道有这么回事」，不需要掌握度考核。学情侧本来就按 `stat.total > 0` 过滤，0 题概念不会污染薄弱点与复习队列（已核实 `diagnose` / `reviewQueue`）。
- **闸门**：`content-gate.mjs` 增加反向规则「**非导览课必须 ≥1 题**」，防止有人用「不给题」蒙混过闸门；`overview` 课则允许 0 题。

白名单不存在独立文件里——`overview` 课型直接标在那节课自己的文件上（`app/data/agent-course/lessons/l01.ts` 里 `withKind(L(...), 'overview', '理由')`，落到 `Lesson.kind` + `Lesson.kindReason`），由 `content-gate.mjs` 读取并校验四道护栏：

1. `kindReason` 必填（不给理由不算导航课）；
2. **每模块最多 1 节**；
3. 总量 ≤ 总课时 8%；
4. **Capstone 阶段（26、27）禁止使用**——复盘课也要有真实实现与验收断言。

> 课型标在数据上，天然消灭了旧版「名单里的 id 已不存在」这一类腐化（课时改名时标注跟着走）。

> 首版我自己列了 6 节，护栏当场否掉 2 节，说明它有效：**L142**（课程总览）挂 Capstone B 阶段，按第 4 条须写厚——它是全课终点（知识地图 + 能力自评 + 进阶路线），本就值得展开；**L95** 与 L93 同属模块 7，按第 2 条只能留一节，且 L95 带 422 字符的 `package.json`/`tsconfig` 模板代码，本质是模板课而非导览，归 B 类写厚。

### 3. 课时用时推导口径（`minutes` 不进数据）

`Lesson` **没有 `minutes` 字段**，构造器 `L()` 也没有这个形参。用时是正文体量的函数，由 `lessonMinutes(lesson)` 在**渲染时现算**（`app/lib/lesson-time.ts`）：单课约 0.02 ms，Agent 课全量 142 节约 4 ms，且只在该课真正被显示时才发生。

**为什么不做成「生成课程时算好存进数据」**：

- 存下来就有两份真相（数字 vs 正文）。正文一改写，数字不跟着变，就出现「写着 20 分钟、实际只够读 8 分钟」——00052 之前 142 节课全是这种状态：声明均值 15.4 min，按体量只有 9.8 min，**132 节偏差超 30%**；
- 存下来就得在**所有课时创建时**付计算成本（模块加载期跑 142 次正则），而这些课时大部分在本次访问里不会被打开；
- 删掉字段后，「声明值 vs 推导值」的容差校验也一并删除——它存在的唯一理由就是盯住这个本不该存在的手填值。留着一个「随时可能说谎、靠另一段代码去核查」的字段，比没有这个字段更糟。

每类指标有独立单位用时，总时长 = 各项之和，同时输出占比：

| 指标 | 单位用时 | 依据 |
|---|---|---|
| `proseChars` | 1/320 分钟/字（≈320 字/分钟） | 中文技术叙述，需停下理解 |
| `codeChars` | 1/200 分钟/字符（≈5 行/分钟） | 读代码逐行对照语义 |
| `callouts` | 0.6 分钟/个 | 提示框需停下消化 |
| `quiz` | 1.2 分钟/题 | 读题 + 思考 + 看解析 |
| `terms` | 0.25 分钟/条 | 术语速览 |
| `pitfalls` | 0.5 分钟/条 | 对照自查 |
| `widget` | 5 分钟/个 | 交互演练：读参数 → 操作 → 对照结果。**方差最大**（有人 1 分钟、有人 10 分钟），取代表值；不设该项会让「正文短、主要靠演练」的 effect / rxjs 被算成 7 分钟 |

`shares` 输出形如 `正文 21% · 代码 47% · 提示 4% · 测验 18% · 术语 5% · 误区 6%`（带演练的课多一项 `演练 xx%`），用于解释「这节课为什么是这个时长」。闸门用**同一个入口函数** `lessonTime(lesson)` 打印推导值，与页面显示严格一致，不再比对任何声明值。

**切换后的实测影响**（口径变化的真实成本，不是 bug）：

| 课程 | 课数 | 原手填均值 | 现推导均值 | 说明 |
|---|---|---|---|---|
| agent | 142 | 15.4 min | 9.8 min | 正文均值仅 ~800 字，手填值一直在替内容圆谎 |
| effect | 26 | 32.3 min | 12.0 min | 正文均值 205 字，主体是 widget 交互（25/26 带演练） |
| rxjs | 26 | 27.4 min | 12.3 min | 正文均值 152 字，26/26 带演练 |

Agent 课的数字会在 Wave 1–3 重写后自然涨回（试点 L128 就从手填 20 变成 33）；effect / rxjs 若认为偏低，调 `TIME_RATES.perWidget` 一行即可，不该回头给课时加回 `minutes`。

### 4. 体量闸门落地（`scripts/content-gate.mjs`）

- 挂在 `pnpm verify` 第三段（`verify-course` → `verify-tutor` → `content-gate`）。
- **课型来源：课程数据，脚本零配置**。取值就是 `Lesson.kind`，一个课时一个值，没有继承、没有优先级：
  - 标注位置：该课自己的 `app/data/agent-course/lessons/lNN.ts`，形如 `export const L26 = withKind(L(...), 'theory')`；
  - `withKind()` 是 `course-builders.ts` 里的纯包装，只补 `kind`（`overview` 时另补 `kindReason`）；
  - 一节课都没标 `kind` 的课程（effect / rxjs 等 simple 课）→ 打印一行「未标注课型，跳过体量闸门」，视为不纳入。
- **取值用语义名，不用 A/B/C/D 代号**：`theory` / `practice` / `framework` / `scenario` / `capstone` / `overview`。读 `withKind(L(...), 'practice')` 就知道这节是实战课，读闸门报错 `L21=X` 也能对着取值表一眼定位，不需要回头查「B 是什么」。代号最初只是为了省字符，代价却是每读一处都得对一次映射表——体量闸门本来就是给人看的护栏，可读性优先。
- **为什么标在数据上而不是脚本里**：课型描述的是「这节课是什么」，属于课程元数据；旧版 `COURSE_CONFIG` 把它拆到脚本，导致同一事实有两处真相（写课时、改脚本），且新增课程必须回来改脚本才被纳入。现在写课时顺手标注，闸门自动接管。
- **为什么是课时级而不是阶段级**：课型回答的是「这一节该多厚」，判定单位本来就是课。早先版本用 `Stage.kind` 阶段默认 + 课时继承，代价是三条：① 看一节 `lNN.ts` 看不出课型，得跳回 `stages.ts` 并记得「继承 + 仅 overview 可覆盖」的规则；② 显式多出「阶段漏标」「越权覆盖非 overview」两类校验，而这些校验本身就是在修补继承带来的歧义；③ 假设「阶段内 5 节课同课型」，但实际数据已经反证——4 节 overview 课全是阶段内的异类，阶段 1「认知基础」（L06–L10）标 practice 实战、实质更接近 theory 理论。课时级标注多写 114 行，换来一个字段一个来源、打开文件即见课型。
- **数据完整性硬校验**（两类都直接失败）：
  - 课时漏标 `kind` → 报「以下课时未标注 kind」并失败（负向测试：拿掉 L20 的 `withKind` 后闸门非零退出并点名 L20）；旧版按阶段覆盖时，负向测试删掉阶段 27 会让闸门从 142 课静默降为 134 课却仍打印「通过」；
  - `kind` 取值非法（不在 `theory/practice/framework/scenario/capstone/overview` 内）→ 失败（负向测试：L21 改成 `'X'` 后报 `L21=X`）；
  - `overview` 课缺 `kindReason`、挂在 Capstone 阶段、每模块 >1 节、总量 >8% → 分别失败（负向测试：L129 改标 overview 后报「Capstone 阶段的课不允许标 overview」）。「阶段是否属于 Capstone 区」按阶段名 / `en` 匹配，不再依赖阶段课型。
- 当前标注结果（`--verbose` 会打印同样一行「课型分布」）：theory 27 · practice 62 · framework 22 · scenario 12 · capstone 15 · overview 4，合计 142。
- **棘轮机制**：`scripts/content-gate-baseline.json` 保存「尚未重构因此豁免」的课时 id。重合时把该课交付即可达标；已达标却仍在名单里会提示删除，防名单腐化。
- 用法：
  - `node --experimental-strip-types scripts/content-gate.mjs`（CI / verify）
  - `--verbose` 打印课型分布 + 每课明细 + overview 课理由；`--only=L26,L42` 只看指定课；`--update-baseline` 回写豁免名单。
- 当前状态：**7/142 达标，135 课豁免**（Wave 1–3 逐步收缩），其中 3 节为 overview 导览课。
- **题数事实校正**：全课实为 **438 题**（136 课 ×3 + 6 节试点课 ×5），`00051` 记录的「426 题」是 142×3 的估算值。按旧目录不改写约定，仅在本文记录正确口径。

### 5. 测验策略（决策 1 落地）

仍用 `QuizQuestion` 单选模型，但题干承载不同认知层级：

- **1 回忆题**：概念定义 / 机制归属。
- **2 应用题**：给场景选方案、给条件选变体。
- **1 改错题**：把有 bug 的片段写进题干（`text` 内用 `\n\n` 分行），选项给「缺陷在哪」。
- **1 设计题**：给约束选最合理的架构取舍。

判断可用 2 选项单选表达。多选 / 代码补全 / 自由改错**不做**——它们需要「判定对错」的机制（AST 比对、测试执行、人工评分），属于独立任务。

### 6. 实施节奏
