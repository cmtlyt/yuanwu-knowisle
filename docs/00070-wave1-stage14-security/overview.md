## 术语统一（Stage 14 共用）

- **直接注入（direct injection）**：攻击写在用户输入里。
- **间接注入（indirect injection）**：攻击藏在 Agent 读取的外部内容里（网页、文档、工具返回、
  代码注释）。这是 Agent 特有的威胁面——普通 LLM 应用没有它。
- **护栏（guardrail）**：对输入或输出做的检查，可以是规则、模型或程序校验。
- **最小权限（least privilege）**：工具只授予完成任务所需的最小能力，且能按会话收窄。
- **沙箱（sandbox）**：把危险执行放进受限环境（无网络、只读挂载、资源上限）。
- **租户（tenant）**：数据隔离的边界单位；跨租户泄漏是最高危的一类 bug。

## 变更计划

1. L83：讲清「指令与数据的边界在 Agent 里消失了」这一根因，给直接 / 间接注入的三种载体
   （工具返回、检索文档、代码注释），说明「加一句『忽略恶意指令』」为什么无效，
   并给出「信任级」模型（数据按来源分级、不同级不同处置）。
2. L84：构造五种真实注入（越权工具调用、数据外带、角色劫持、指令覆盖、隐形指令），
   实现三层防御（内容隔离与标注、工具白名单与参数约束、输出校验与出站过滤），并给出可跑的
   攻防测试。
3. L85：讲权限拆细（能力 → 资源 → 动作三级）、按会话授权的实现、四种沙箱形态（进程 / 容器 /
   受限解释器 / 远端执行）与各自逃逸面，以及「读与写分开授权」。
4. L86：讲输出护栏拦什么（越权动作、敏感信息、不合规表述）、三种形态（规则 / 模型 / 程序校验）、
   拦截后的三种降级（拒答 / 改写 / 转人工）与误拦率的度量。
5. L87：讲三层隔离（存储分区、检索过滤、上下文隔离）与「过滤放在哪一层」的决定性差别，
   给出越权访问的测试方法（跨租户探测）与被漏掉的常见路径（缓存、向量索引、日志）。
6. 每节 ≥1 表格、≥2 独立 callout、≥1 可运行代码块；渲染抽查；`--update-baseline`；全门禁。
