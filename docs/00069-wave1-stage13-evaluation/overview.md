## 术语统一（Stage 13 共用）

- **维度（dimension）**：评测的一个可量化方面（正确性 / 效率 / 成本 / 可靠性 / 安全）。
- **指标（metric）**：某维度上的具体可计算量（准确率、平均步数、每任务 token、失败率）。
- **基线（baseline）**：一组固定样本 + 固定指标 + 一个已知版本的分数，用于判断「改动是否退化」。
- **轨迹评测（trajectory eval）**：对过程打分（步数、工具成功率、冗余动作），与只看最终答案的
  结果评测相对。
- **harness**：把「样本集 + 执行器 + 指标 + 报告」固定下来的可重复运行装置。
- **judge**：用模型做评分器；它与「验证器（verifier）」的区别是后者可执行、judge 是概率性的。

## 变更计划

1. L77：给五维定义与每维的判据，讲「感觉变好」的三种典型误判（挑样本、看单指标、忽略分布），
   并给出维度之间的权衡关系（正确性 ↑ 常伴随成本 ↑）。
2. L78：给出从 span 树计算步骤数、工具成功率、冗余动作率的实现，讲「结果对但过程烂」的三种形态
   （绕路、重复、危险接近），以及冗余动作率的分母该怎么取。
3. L79：横向对照三个基准测什么、样本规模、判定方式、可被刷分的点、以及「分数不能证明什么」；
   给「按需选基准」的决策表。
4. L80：讲基线三要素（固定样本、固定指标、版本快照）、样本集怎么建（从真实轨迹里分层抽）、
   基线的维护（何时该更新、更新会掩盖什么）。
5. L81：实现一个可运行的 harness（用例定义、执行、指标计算、与基线对比、退化告警），
   含并行、超时、重试与结果落盘；对照 LangSmith Evals / Ragas。
6. L82：实现最小 judge（评分维度、rubric、多次采样取多数），讲位置偏差、自我偏好、长度偏差与
   三种缓解（交换顺序、盲评、校准集），以及「judge 何时不该用」。
7. 每节 ≥1 表格、≥2 独立 callout（L79 同样要求）、可运行代码块（L79 可豁免）；渲染抽查；
   `--update-baseline`；全门禁。
