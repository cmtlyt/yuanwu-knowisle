## 术语统一（Stage 17 共用）

- **假迁移**：代码搬到了图上，但控制流仍藏在节点内部的 for/while 里。表现为 LOC 下降、
  断点能力为零。
- **节点粒度**：节点边界 = 你想断点 / 观测 / 重试的边界，不是「一个函数一个节点」。
- **subgraph 边界**：应以「状态契约」为界。两个角色需要频繁读对方内部状态时，不该拆。
- **checkpoint_ns**：子图的命名空间。在 subgraph 内 interrupt 后恢复必须带它，否则恢复到别的会话。
- **双层记录**：托管追踪存摘要（可检索、可看拓扑），自有日志存全文（出问题时能捞原文）。

### 与原变更计划的偏差

1. **L97 增加了「节点粒度」的独立 deep 段**：原计划只写「用条件边表达循环」。实测发现真正难的是
   「一个节点该多大」，因此补了三个判断问题（要不要只重跑这一步 / 要不要独立 span / 能不能挂起），
   并给出经验值「5–15 个节点最好维护」。
2. **L97 把「节点内允许 Promise.all、不允许长循环」写成一条判据**：原计划没提这个区分。实测认为
   它是理解 super-step 边界最锋利的一个例子，且能解释「为什么扇出并发是合法的」。
3. **L98 补了「中心式回边」的结构选择**：原计划只讲 subgraph。实测发现「角色之间直接连边」
   与「都回 supervisor」是可观测性与调度成本的核心权衡，属于 L69 控制权位置的图版本，因此补上。
4. **L98 补了「别给子图单独挂 MemorySaver」**：这是与前文 reducer/checkpoint 主题的交叉坑，
   会导致两套快照（两个真相）。原计划未列。
5. **L99 的落点从「了解」改为「验证 + 迁移清单」**：原计划是介绍 LangSmith 与 Platform。实测认为
   「接入」这个动作太便宜、不足以支撑一课，因此把重心移到三项验证、双层记录与锁定点清单，
   并给出可接进 CI 的 `assertNotTruncated` 冒烟断言。
6. **一次自伤（已修）**：L99 首次 Write 误写成 `import { L, withKind } from '../../builders.ts'`
   （正确为 `../../course-builders.ts`），把骨架覆盖成单行 → `git checkout --` 恢复后重写。
   与 00071 的 L90 同类错误，已第二次发生，记入 memory。
